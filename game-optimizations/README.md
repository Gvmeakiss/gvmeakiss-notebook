## 通用优化清单（跨游戏）

下面这些与具体游戏无关，先做完再谈游戏内设置。**每条都标注了它解决什么问题、以及怎么验证。**

### 1. 电源方案：确认不是「节能/平衡」

| 项 | 做法 | 为什么 |
|---|---|---|
| 电源方案 | 切到**高性能**（Windows 11 默认把它藏起来了，需要先创建） | 平衡方案会做核心停泊与频率下探，密集帧时容易出帧时间尖刺 |
| 最小处理器状态 | **保持系统原有的值**，不要一律拉满 | 拉满会让待机功耗与温度上升；只有当"开游戏前几秒明显卡"时才考虑提高 |
| 系统散热方式 | 主动（优先风扇，而不是先降频） | 迷你主机/笔记本尤其明显 |

> **判据**：`powercfg /getactivescheme` 看当前方案；`powercfg /query <方案> SUB_PROCESSOR` 看最小/最大状态。
> **别只看"改了"，要回读十六进制值。**

### 2. 关闭游戏的可执行文件的「全屏优化」

| 项 | 做法 |
|---|---|
| 兼容性标记 | `HKCU\Software\Microsoft\Windows NT\CurrentVersion\AppCompatFlags\Layers` 下新增 `<exe 全路径>` = `~ DISABLEDXMAXIMIZEDWINDOWEDMODE` |

这会让游戏走**独占全屏**，绕过 DWM 合成，降低输入延迟、减少掉帧。

> ⚠ **写这个键只能用 `New-ItemProperty` 单值写入。**
> 用 `New-Item -Force` 会**清空同级所有已有值**（其他游戏的兼容性标记会一起没）。
> 改完回读一次，并对比条目数是否只 +1。

### 3. 关掉后台录制

| 项 | 检查位置 | 期望 |
|---|---|---|
| GameDVR 策略 | `HKLM\SOFTWARE\Policies\Microsoft\Windows\GameDVR` → `AllowGameDVR` | `0` |
| GameDVR 用户级 | `HKCU\System\GameConfigStore` → `GameDVR_Enabled` | `0` |
| 游戏模式 | `HKCU\Software\Microsoft\GameBar` → `AllowAutoGameMode` | `1`（**要开**） |

### 4. 杀软排除游戏目录

实时扫描会在**加载资源、换图、首次编译着色器**时抢磁盘与 CPU，表现为"进图卡一下"。

> 这一步**没有通用脚本接口**（各家杀软配置格式不同），只能手动在客户端里把
> Steam 库目录与具体游戏目录加入信任区。

### 5. 帧率上限：不要无脑"不限帧"

对**核显/中低端卡**，不限帧会让 GPU 长期 100% 占用，温度上升后反而降频，
同时帧时间分布更差。**设一个略高于刷新率的上限更稳**（例如 60 Hz 屏设 90–120）。

对高端卡 + 高刷屏，才考虑不限帧或 `fps_max 0`。

### 6. 先算天花板：瓶颈在哪一层

优化之前先回答三个问题，否则容易在错的层上使劲：

1. **显示器刷新率上限是多少？** 超过它的帧数没有画面收益
2. **GPU 是独显还是核显？核显的话内存是不是双通道/多通道？** 单通道核显性能可能腰斩
3. **游戏跑在什么分辨率？** 4K 下的核显基本不可用，必须降到 1080p 或开 FSR

## 新增一款游戏的流程

按这个顺序，避免"改了但没验证"：

```
1. 体检      → scripts/check-<game>-readiness.ps1   （只读，先出结论）
2. 量化基线  → 进游戏记 3 个数据：平均帧、1% low、GPU/CPU 占用
3. 系统层    → 电源方案 / 独占全屏 / 后台录制 / 杀软排除
4. 游戏内    → 按"最贵到最便宜"的顺序降画质，每改一档测一次
5. 复测      → 与第 2 步同场景同比，只保留有提升的项
6. 写回文档  → 记录：本机硬件、瓶颈判定、最终设置、预期帧数、回滚方式
```

**新增目录时只需要：**

```
<game-slug>/
├── README.md          # 硬件评估 · 系统优化 · 游戏内设置 · 排错 · 回滚
└── scripts/
    ├── check-<game>-readiness.ps1      # 只读体检
    └── apply-<game>-optimizations.ps1  # 可回退的应用脚本（支持 -WhatIf / -Revert）
```

并回到本文件把游戏加进 [收录的游戏](#收录的游戏) 表。

### 脚本约定（与本仓库其他项目一致）

- **纯 ASCII**：Windows PowerShell 5.1 按 ANSI 解码无 BOM 文件，含中文会解析失败
  （表现为"脚本启动即退出、退出码 0x1"）。需要中文时用 `\uXXXX` 转义。
- **支持 `-WhatIf`**：预览必须能走完全程并列出"将会做什么"，判据看**实际状态**而不是输出文字。
- **支持 `-Revert`**：每个改动都要能单独回退，并回读确认回退成功。
- **幂等**：重复运行不产生副作用。

## 观测指标：怎么算"优化有效"

不要只凭手感。至少记这三个：

| 指标 | 怎么取 | 说明 |
|---|---|---|
| **平均帧** | 游戏内 `net_graph` / `cl_showfps` / 外部叠加层 | 单看这个最容易被误导 |
| **1% low**（最低 1% 帧） | 同上，或 CapFrameX 等工具 | **卡顿感主要由它决定**，提升它比提升平均帧更有意义 |
| **GPU/CPU 占用与温度** | 任务管理器 / HWiNFO | 判断瓶颈：GPU 满 = 画质吃紧；CPU 单核满 = 逻辑/物理瓶颈 |

改动前后**同一场景、同一时长**对比，才有可比性。

## 纪律

1. **先量后调** —— 没有基线数据的"优化"无法判断是变好还是变坏
2. **可回退** —— 改任何系统项前先导出/记录原值，并给出回退命令
3. **不关闭系统服务** —— 按需启动的服务禁用后省不到性能，却可能搞坏输入法/音频/网络
4. **不动驱动** —— 驱动"更新"带来新问题的概率并不低；没有实测症状就不动
