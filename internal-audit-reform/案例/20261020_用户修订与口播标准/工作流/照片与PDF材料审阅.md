# 照片与 PDF 材料审阅工作流

适用于拍照的 PPT、截图、扫描件和 PDF，用于后续写稿、问答、H5、PPT 与海报制作。执行原则：**首次按版本完整审阅，形成可检索的材料包；后续先读文本，遇到具体疑点才回查对应图像。**

本工作流记录材料读取和核对方法，不改变业务要求，也不要求每次重新制作展示文件。

## 1. 读取顺序

| 情况 | 默认操作 | 回看图片的条件 |
| --- | --- | --- |
| 新材料，没有有效材料包 | 清点全部文件和页序；提取文字；逐页核对内容与结构，建立材料包 | 初次审阅按批覆盖全部页面，密集区域另作局部核对 |
| 已有材料包，来源版本未变 | 读取 INDEX，检索并读取相关页 MD；涉及设计再读 VISUAL_SPEC | 对应页存在未解决疑点，或本次问题依赖尚未记录的视觉细节 |
| 只修改一句文案或一个栏目 | 读取相关页 MD 和用户修订记录，修改交付物 | 文本记录不完整、关系有歧义或用户指出理解错误 |
| 用户提供新版 | 比对来源指纹和页序；失效对应缓存，核对变更页及受影响关系 | 无法确认哪些页面未变时，重新审阅相应版本 |
| 检查最终显示 | 查看本次生成的交付物渲染 | 此操作是成品验收，不应因此再次全量打开来源图 |

不得把“新一轮对话”“忘记标题”“文件移动过”作为重复打开整套图片的理由。先检索材料包；文件只移动且指纹一致时，更新路径即可。

## 2. 材料包

每份有效材料独立存放，默认位于本地项目的 `资料索引/<材料ID>/`。原始文件保留原位置，引用相对路径，不复制进最终交付目录。

```text
资料索引/<材料ID>/
├── INDEX.md              # 默认入口：版本、总页数、逐页标题、关键词、核对状态
├── manifest.json         # 来源指纹、页序映射、解析方式与核对状态
├── pages/p001.md ...     # 逐页原文、结构关系、摘要及疑点
├── VISUAL_SPEC.md        # 版式、字体层级、配色角色、来源与不确定项
├── ISSUES.md             # 尚未解决的具体页/区域与问题
└── USER_OVERRIDES.md     # 用户后来确认的文案/展示调整，独立于原文
```

使用 [索引模板](./templates/INDEX.template.md)、[逐页模板](./templates/PAGE.template.md)、[视觉记录模板](./templates/VISUAL_SPEC.template.md)、[未决事项模板](./templates/ISSUES.template.md)、[用户确认模板](./templates/USER_OVERRIDES.template.md)和[来源清单示例](./templates/manifest.example.json)。只需按实际材料填写，不要求制造空白表格或冗余文件。

原图、OCR 文本和包含业务信息的材料包默认本地保存。公开 Git 只同步工作流、空模板和已授权的脱敏内容；方法研究不意味着自动向第三方解析服务上传材料。

## 3. 首次完整审阅

### A. 清点和锁定版本

1. 记录用户指定的有效材料、旧版用途、来源文件 SHA-256、总页数/图片数、文件名与逻辑页序。
2. 按文件中的数字自然排序，避免把第 10 页排在第 2 页前。印刷页码与文件页序分别记录，不能默认为一致。
3. 清点缺页、重页、旋转、模糊、反光和裁切。重复文件指纹相同时复用已有记录；相似图片不能只凭外观判定内容相同。
4. 用户指定“新版”“经理修改版”的效力高于文件名和修改时间；未指定时保留版本差异，不能用历史记忆替代版本确认。

### B. 批量提取，逐页核对一次

- 有可用文字层的 PDF：先批量提取文本及块位置；可取得原生字体、字号和颜色属性时一并保存。提取顺序不等于阅读顺序。
- 纯扫描 PDF、照片和截图：在本地已有工具可用时批量 OCR，并保存页/区域定位；结合当前会话视觉审阅。缺少 OCR 工具时可以直接逐页视觉转录，不必为了工具额外安装整套服务。
- 混合 PDF：按页判断，不能因封面有文字层就将后续扫描页判为可直接提取。
- 分批审阅全部页面，每页确认标题、正文、图表和脚注；缩略总览用于盘点及比较版式，不能替代密集小字的可读尺度核对。
- 同一页首次读取时同时记录内容、结构和视觉信息，避免为标题、表格和配色分别重复打开整页。需要放大的区域在这一轮一并核对。
- OCR 保留为未审原始提取结果，不能直接当正式原文；水印、界面按钮、乱码等在整理正文时排除，并记录处理规则。

### C. 原文、结构、摘要分别保存

逐页 MD 至少包含以下信息：

1. **原文**：页面标题、分组标题、正文、数字、限定词和脚注。不能以口播稿或历史总结冒充页面原文。
2. **结构**：标题层级、区域位置、阅读顺序、表格行列对应、流程箭头及分支关系。
3. **摘要与可用事实**：方便检索的概括，保留主体、动作、条件、范围、时点、交付物及状态，能追溯到原文区域。
4. **视觉记录与疑点**：本页与整体视觉规范的关系、例外、无法辨认的字及需要回查的区域。

原文和摘要不能相互覆盖。用户后来要求缩短标题、隐藏范围或去除句号时，记录在 USER_OVERRIDES，修改展示稿；原文层仍保留来源实际写法。

## 4. 如何确认理解了图片结构

记录“左栏是什么、右栏是什么、各行分别对应什么”，再记录结论；不能只留一段顺口的概述。

| 元素 | 必须记录和核对 | 常见错误 |
| --- | --- | --- |
| 多栏、卡片、目录 | 区域 ID、所属标题、区域阅读顺序 | 横跨两栏读成一句话，或把装饰性文字当正文 |
| 表格 | 表头、行列名、单元格对应、合并关系、单位和表下注释 | OCR 文本都对，但数字归错列、脚注丢失 |
| 流程 | 节点、箭头方向、条件、分支、回溯边、虚实线含义 | 按视觉位置强行串行，或把周期动作误写成逐单前置步骤 |
| 图表 | 图例、轴、单位、标签与数据系列对应 | 把颜色图例和数据对应错，或从低清图估读精确数值 |
| 强调/底色 | 颜色对应的分组或状态，文字与背景的角色 | 因颜色相近就推断两个概念属于同一主体 |

简单表格用 Markdown；合并单元格使用 HTML `rowspan/colspan`，或展开成带完整行列标签的记录。复杂流程可附节点/边表或 Mermaid。必要时添加 `layout.json`，用区域 ID 和 0—1000 的归一化坐标定位；无需为每个字符制造坐标记录。

**结构复核问题**：是否漏组？每条说明属于哪个标题？数字对应哪行哪列？箭头的起点和终点是什么？正文、脚注、注释是否混入同一层？不能从原图明确判断的关系标为待核实，不靠常识补齐。

## 5. 如何记录配色和版式

Markdown 的标题和表格可以表达语义结构；精确版式和颜色需另记，不能用“已转 MD”证明“已准确理解视觉规范”。相关依据见[知识与方法来源](./知识与方法来源.md)。

- **原生属性**：从可编辑 PPT、原生 PDF 或用户提供的规范读取的字体、字号、颜色、对象尺寸，标记来源及页/区域。PDF 字体名可能为子集名，不能据此保证另一软件已有相同字体。
- **照片观察**：记录“白底、深灰正文、橙色主强调、浅橙辅助底”等角色和区域。照片的色温、白平衡与显示/拍摄条件会影响颜色，取样 HEX 只标为估测，不能称为正式 VI 色值。
- **确认的执行值**：用户提供或确认的色板另列为最终执行值；没有确值时用已确认的视觉方向做有标识的近似选择，不虚构精确提取。
- **版式规则**：记录画布比例、边距和对齐、标题与正文的相对尺度、行距、圆角、线条、装饰占比。照片里的尺寸和字体只作估计，不能直接当原稿精确字号。
- **视觉例外**：允许页间差异，但要说明适用页/元素。一次显著色块不能直接概括为全稿规范。
- **可读性**：新交付物按实际邮件/屏幕显示比例检查。可参考 WCAG 的普通文字 4.5:1、大字 3:1 对比度要求；大字参考至少 18pt 或加粗 14pt。PNG 的导出倍数不代表实际显示字号，单项对比度检查也不等于完整无障碍合规。

内容、结构、配色角色分别记录“未核对/部分核对/已核对”，并记录具体证据；精确色值、字号和字体是否可确认另列。可以确认颜色用途，同时注明精确参数仍未知，不必反复打开照片试图确认其无法提供的原生属性。不能用一个“高置信度”代替三种核对。OCR 置信度只说明识别器的判断，不代表行列关系、业务语义或颜色一定正确。

## 6. 完成条件与增量更新

### 初次审阅完成条件

- 清单中的每页都有记录，内容和结构核对状态齐全；无法辨认的地方具体列入 ISSUES。
- 标题、主体、数字、比较符号、限定词、例外、表格和箭头已重点复核。
- VISUAL_SPEC 区分原生提取、照片估测、用户确认和未核对，没有把估测写成规范。
- INDEX 能按主题检索到相应页，manifest 能定位到来源文件和当前版本。
- 影响必需要求理解的疑点尚未解决时，该部分保持待核实，不能写进正式结果或声称全部核对通过。

### 后续每轮执行

1. 先读 INDEX，核验本次指定来源与版本；必要时用文件指纹检测变化。
2. 用标题/关键词检索目标页，只读相关 MD；设计任务再读 VISUAL_SPEC 和用户最新确认。
3. 文本已能解答时直接工作；需要回查时记录原因、页/区域和具体问题，优先看该区域，并保留足够上下文。
4. 回查后立刻把确认结果写回逐页 MD、ISSUES 和核对状态。不要将解决结果只留在聊天里。
5. 新版只重做变更页及受影响关系。PDF 整文件变化后，须通过逐页渲染或对象/内容与样式比较确认哪些页未变；仅文本相同不足以证明布局和配色未变。不能确认时重新核对相关页。
6. 修改完成后验收新成品；业务材料包与交付文案继续分开，避免下次把删减后的海报当作原始制度材料。

下列情形可以回看来源图：密集表格/多级审批链、低清数字或符号、箭头歧义、文本与版面冲突、来源更新、用户质疑识别准确性、任务需要此前未记录的视觉细节。每次说明具体目标，不反复全量载入同一版本。

## 7. 下次可直接执行的指令

> 收到照片或 PDF 后，先检查是否已有同版本资料索引。首次完整清点、审阅全部页面，整理逐页原文与摘要，并记录表格、阅读顺序、流程关系和配色版式。为文字、结构、配色分别记录核对状态，无法确认的内容保持待核实。建立 INDEX、逐页 MD、VISUAL_SPEC 和来源指纹；原文与用户后续展示调整分开保存。后续先查 INDEX 和相关页 MD，信息密集或有具体疑点时才回查对应图像/区域，确认后及时更新文本记录。新版本增量处理，不使用历史业务记忆覆盖本次材料，不把图片估测色值当作正式 VI 规范。
