# 个人条线业务稽核年度规划：编写方法与口径

> **这份文档是什么**：把一轮「个人条线（车险 + 个人非车险）年度稽核规划」的编写过程，沉淀为可复用的方法、口径与模板。适用于年度规划从零编写、已有规划审阅、以及把材料交给 AI 续写三种场景。
>
> **不是什么**：不是某家公司的制度原文，也不是一份已批准的年度计划。具体项目、排期、覆盖范围与检查重点，必须按新项目的有效材料（尤其计划清单）重新确认。
>
> **脱敏约定**：金额、件数、比例、机构名称与责任人不在公开版列示，统一写作 `【N】`、`区域 A/B/C`、`责任人代号`。监管文件的名称与条款保留原文表述，引用前核对官方发布文本。

---

## 0. 三条硬规则

写这类规划，事实一致性比文采重要。三条规则决定后面所有做法。

| 规则 | 含义 | 违反后的典型症状 |
| --- | --- | --- |
| **事实只有一个源** | 项目名称、实施季度、覆盖范围、检查重点，以**计划清单**为准 | 同一项目在两份材料里排期不同、名称不同 |
| **叙事不覆盖事实** | 汇报稿、H5、海报只解释背景与必要性，不能改期、改范围、改责任主体 | 汇报稿悄悄变成事实源，越改越对不上 |
| **外部资料只核验** | 监管文件只用于核验已有材料中**已表达**的监管背景 | 凭空多出检查事项、检查维度或管理要求 |

## 1. 基础知识：先分清业务线与监管框架

### 1.1 业务线边界

个人条线通常拆成两条业务线，稽核口径不同，不能混在一张表里算。

| 业务线 | 范围 | 典型产品 | 主要风险落点 |
| --- | --- | --- | --- |
| **车险** | 交强险 + 商业车险 | 车损、三者、车上人员等 | 费用真实性、费率执行、虚假承保与业绩调节 |
| **个人非车险（个非）** | 面向个人的非车险种 | 百万医疗、宠物险、意外/驾乘、门诊/药诊等 | 条款费率、产品组合、退保与亏损、互联网渠道 |

要点：

- 个非不是一个险种，而是一组差异很大的短险产品。做规划时先按「渠道 + 产品 + 经营结果」三轴归类，再谈项目，否则检查维度会互相打架。
- 车险与个非的项目**可以按同一套逻辑立项**，但风险信号、监管依据、数据口径不同，项目卡要分开写。
- 产品目录、渠道清单以本公司当期口径为准，本文不列具体产品名。

### 1.2 监管框架三条主线

三条主线决定了个人条线近两年的稽核重点。

| 主线 | 核心要求 | 对稽核规划的含义 |
| --- | --- | --- |
| **报行合一** | 报备费率与实际执行一致；费用真实性；客户信息真实 | 费用套取、报行不一、虚开发票、服务权益异常兑现是长期高发领域 |
| **非车险综合治理** | 条款费率使用、中介管理、经营管理费用、保费收入真实、批单退费规范 | 个非从「单一费率检查」转向「经营品质 + 综合治理」 |
| **金融产品网络营销** | 第三方平台合作管理、营销主体展示、销售环节边界、客户信息保护 | 互联网业务要同时看经营品质与营销合规，不能只看退保率 |

监管文件具有时效性。**新规发布日期、施行日期与条款号，必须在当次材料中重新核对**，不沿用旧稿引述。

### 1.3 稽核侧基础概念

排期和写法都建立在这几个概念上，先统一含义再动笔。

| 概念 | 在本规划中的含义 |
| --- | --- |
| **专项** | 围绕一个风险主题、有明确对象范围和时间窗的独立检查项目，是年度布局的基本单元 |
| **立项** | 从四类输入中筛出主题，并按优先级决定是否进入年度计划 |
| **监测指标** | 能持续跑数、可重复验证的量化口径；专项结束后要能沉淀成指标 |
| **稽核地图** | 按机构/业务标出红黄灯风险事项的地图，是筛选对象的主要工具之一 |
| **负面行为清单** | 明令禁止的行为清单；命中即触发检查，不参与排序权衡 |
| **整改** | 责任主体对已确认问题的处置，含制度、流程、系统三类动作 |
| **回头看** | 对往年问题整改效果的再验证，重点看是否复发 |
| **分级验收** | 按问题严重程度设定不同复核比例，避免平均用力 |
| **反哺** | 专项发现转化为监测指标、风险特征、制度流程或下一轮立项线索 |

### 1.4 风险四分法

把材料里的风险归成四类，项目自然成组，汇报时也容易讲清「为什么做」。

| 风险类型 | 判断问题 | 对应项目类型 | 主要输出 |
| --- | --- | --- | --- |
| **监管合规风险** | 业务执行是否与监管要求、报备规则一致 | 报行合一、综合治理专项 | 问题清单 + 整改要求 |
| **经营真实性风险** | 数据异常背后是正常波动还是虚假业务 | 虚假承保、业务品质专项 | 线索 + 定性结论 |
| **新业务未知风险** | 发展速度是否快于风险管理能力 | 新业务调研、总部专项 | 风险底数 + 监测建议 |
| **整改不实风险** | 问题是否真正消除、机制是否改变 | 回头看、整改验收 | 验收结论 + 复发判断 |

## 2. 逻辑口径：项目从哪来、怎么排序

### 2.1 四类输入

年度项目不是拍脑袋列出来的，也不是把两条业务线的项目简单相加。统一为四类输入：

| 输入 | 主要来源 | 要回答的问题 |
| --- | --- | --- |
| **① 监管要求识别** | 监管制度与新规、行业处罚、监管关注事项、负面行为清单、内部合规要求 | 哪些是必须守住的底线？ |
| **② 监测数据筛查** | 风险监测指标、经营品质指标、异常业务数据、投诉/退保/费用信号 | 风险集中在哪些机构、产品、场景？ |
| **③ 战略业务分析** | 新业务、新产品、新渠道、新合作模式、重点发展业务 | 哪些业务发展快但稽核覆盖不足？ |
| **④ 历史问题梳理** | 当年稽核发现、内外部检查发现、监管整改事项、重大整改台账 | 哪些问题还需要验证整改实效？ |

```text
监管要求识别 ─┐
监测数据筛查 ─┼─→ 风险判断与优先级排序 ─→ 年度专项项目
战略业务分析 ─┤
历史问题梳理 ─┘
```

> 两套常见标签对应同一逻辑：叙事版用「监管要求 / 监测数据 / 战略业务 / 历史问题」，汇报版用「监管关注与负面清单 / 风险地图与监测 / 新兴及重点业务 / 整改与闭环」。选一套用到底，不要混用。

### 2.2 立项四步法（车险材料多一步「计划落地」）

| 步骤 | 输入 | 动作 | 通过判据 |
| --- | --- | --- | --- |
| **1 风险定位** | 监管处罚、内部预警数据、监测指标 | 锁定重点风险领域 | 每个领域能说出监管依据或数据依据 |
| **2 对象定位** | 机构风险评价、监测排名 | 筛出高风险机构/产品名单 | 排序可复现，能说明取数口径 |
| **3 底线过滤** | 负面行为清单、稽核地图红黄灯 | 确定必做项，一票否决 | 命中清单的项目不参与优先级权衡 |
| **4 深度定级** | 量化指标、危害程度、紧急度 | 排出 P0/P1/P2 | 排序理由能落到「红线 + 数据量 + 危害」三项 |
| **5 计划落地**（车险口径） | 人力、排期、行事历 | 形成年度计划表 | 每个项目有主审、助审、季度和交付物 |

### 2.3 排序规则

优先级不是按项目重要性的主观感觉，按四条规则依次判断：

1. **红线一票否决**：命中负面行为清单（如虚构业务、财务数据造假）的，直接排前，不参与比较。
2. **紧急 + 战略优先**：集团/领导层关注、战略执行核心、处于高速扩张期的业务，前置安排。
3. **数据危害程度定序**：同一层级内，按命中数据量、涉及金额、对监管报送的影响排序。
4. **资源可行性兜底**：人力不足时，把排名靠后的机构交常规远程项目组跟进，不硬塞进专项。

| 优先级 | 典型特征 | 排期原则 |
| --- | --- | --- |
| **P0** | 战略业务、新业务、领导层关注、稽核覆盖空白 | 优先安排，且以「摸清底数」为目标而非「查处问题」 |
| **P1** | 命中红线、数据量最大、危害最直接 | 排在数据准备充分后 |
| **P2** | 监管高发但需前置整备（费率、费用数据） | 排在费用/数据整备完成之后 |

### 2.4 事实与解释分离（核心口径）

这是整套方法里最容易被忽略、也最容易出错的一条。

| 内容 | 由谁决定 | 具体包括 |
| --- | --- | --- |
| **事实** | 计划清单（表格类台账） | 项目名称、实施季度、覆盖范围、检查重点、责任人 |
| **解释** | 叙事材料（汇报稿、H5、PPT） | 风险背景、数据证据、项目目标、检查逻辑、必要性 |
| **佐证** | 外部监管资料 | 监管环境解释、项目必要性佐证；**不得据此新增检查事项** |

推论：

- 叙事材料与原计划表冲突时，**以计划清单为准**，并同步修正叙事材料。
- 外部研究只能支撑「为什么做」，不能支撑「查什么」。要新增检查维度，须项目负责人确认。
- 同一项目在两份材料中名称不一致时，以计划清单的名称为准，并在材料中注明曾用名。

### 2.5 项目卡五问

每个项目只用五个问题讲清楚，避免长篇描述。

| 问 | 写什么 | 常见错误 |
| --- | --- | --- |
| **WHY｜为什么做** | 风险信号 + 监管依据 + 不做会怎样 | 只写「领导要求」，没有风险依据 |
| **WHAT｜重点看什么** | 检查维度清单（可核对、可分工） | 维度写成口号，无法落到取数 |
| **WHERE｜重点查哪里** | 覆盖范围：总部/机构、机构代号、产品范围 | 范围写成「全国」，实际无法执行 |
| **HOW｜怎么检查** | 数据筛查 + 现场/非现场 + 抽样规则 | 只写「开展专项检查」，没有方法 |
| **RESULT｜希望形成什么** | 问题清单、整改要求、可沉淀的监测指标 | 只写「形成报告」，没有沉淀物 |

### 2.6 口径冲突的处理

材料越多，冲突越多。处理顺序固定为：**记录 → 提出 → 业务确认**，不擅自选一个方便的口径。

已知的冲突高发类型：

| 类型 | 表现 | 处理 |
| --- | --- | --- |
| 启动时间 vs 年度排期 | 页面模板里的「启动时间」被当成年度计划季度 | 两者分开记录，年度排期以计划清单为准 |
| 页序 vs 业务顺序 | 汇报页的先后被读成办理先后 | 页序只服务叙事，不改变业务顺序 |
| 外部研究 vs 检查事项 | 新规研究被写成新增检查维度 | 只作背景，新增须负责人确认 |
| 名称变体 | 同一项目在不同材料中名称不同 | 以计划清单名称为准，注明曾用名 |

> 差异**只记录、不修正**：在附录中列出冲突项，注明各自来源，交给业务确认。擅自「统一」会让下一位使用者失去溯源依据。

## 3. 规则内容：检查依据与验收标准

### 3.1 监管规则要点（可作检查依据）

以下条款来自本轮材料摘录，**引用前须核对官方原文**；条款号与施行日期以官方发布为准。

| 主题 | 规则要点 | 材料引述来源 |
| --- | --- | --- |
| **代收保费** | 代理机构代收保险费的，应开立独立代收保费账户结算 | 《保险代理人监管规定》第四十九条（材料摘录） |
| **禁止代缴/代领** | 销售人员不得接受委托代缴保费、代领退保金或保险金，不得经手非本人账户资金 | 《保险销售行为管理办法》第三十二条（材料摘录） |
| **见费出单** | 保险公司应在收取保费后签发保单并开具保费发票 | 非车险监管通知第七条（材料摘录） |
| **分期缴费下限** | 确有需要且经内部审核同意的非车险业务可分期；分期缴费最低限额不低于 20 万元 | 非车险监管工作指引第二条（材料摘录） |
| **批退费权限** | 批改业务审核权限原则上集中于总公司或省级分公司，并明确审核流程与标准 | 非车险监管通知第八条（材料摘录） |
| **报行合一** | 报备费率与实际执行一致，费用列支真实，客户信息完整 | 报行合一相关规定 |
| **网络营销** | 金融机构对合作平台负事前评估与持续管理责任；营销主体展示、销售环节边界有明确约束 | 《金融产品网络营销管理办法》 |

> 20 万元分期下限是监管指引中的**具体数值**，复用到新项目时须重新确认是否仍为现行标准。

### 3.2 检查维度清单（按项目类型）

维度清单是项目卡「WHAT」的素材库，按项目类型取用，不要跨类型拼凑。

| 项目类型 | 维度清单 |
| --- | --- |
| **报行合一 / 综合治理** | ① 特别约定不规范 ② 未执行报备费率 ③ 产品开发与设计不规范 ④ 费用管理不规范 ⑤ 新规执行情况检视 |
| **业务品质监测** | ① 产品组合异常 ② 承保亏损业务 ③ 机构间恶性竞争 ④ 转保风险 ⑤ 渠道成本 |
| **互联网经营品质** | ① 高退保率筛查（示例阈值：退保率 > 50%） ② 虚假业务识别（同 IP/设备集中投保、投保时间异常、客户信息完整性） ③ 流量业务甄别（渠道费用占比、获客成本、续保率） ④ 合规性审查（第三方协议、营销页面、跳转链路） |
| **虚假承保调节业绩** | ① 异常批退注销 ② 重复投保 ③ 异常调节保单起期 ④ 异地新车 |
| **新业务 / 战略业务** | ① 保费规模 ② 主体渗透率 ③ 机构覆盖率 ④ 业务规则与战略底数 |
| **新产品调研** | ① 业务模式与合作平台资质 ② 风险特征（欺诈、高退保、赔付异常） ③ 定价合理性 ④ 合作方资质与分成模式 |

> 具体阈值（如退保率门槛）、排名口径、取数范围属于案例口径，须按新项目材料重新确认后再写入正式稿。

### 3.3 整改验收规则

整改验收的重点不是「有没有交材料」，而是「问题有没有消失」。

| 问题等级 | 复核方式 | 示例复核比例 |
| --- | --- | --- |
| **重大问题** | 现场复核 | 100% |
| **重要问题** | 半现场 + 远程 | ≥ 70% |
| **一般问题** | 文档审核 | ≥ 30% |

验证三问（每个问题都要回答）：

1. 问题是否**消除**？
2. 制度、流程或系统是否**真正改变**？
3. 同类问题是否**仍可能复发**？

> 比例是示例口径。正式使用前按当期整改管理制度确认，不把示例比例直接写成通用规则。

### 3.4 证据与留痕

- 每个结论附**口径说明、源数据逻辑、运行记录**，使结论可复核。
- 监测指标要记录取数时间、口径版本与过滤条件，避免同名指标前后不可比。
- 引用监管条款时保留文件名称与条款位置；引用内部制度时保留版本号。

## 4. 年度布局模板

五个阶段、两条业务线，每个阶段一个主题。这张表是**结构模板**，项目名称与季度按新项目计划清单填写。

| 阶段 | 车险 | 个非 | 阶段重点 |
| --- | --- | --- | --- |
| **Q4（当年）** | 存量问题整改 / 业审联动 | 综合治理专项 | **打基础**：承接存量，启动监管重点 |
| **Q1** | 报行合一监测 | 业务品质监测 | **守底线**：费用合规 + 经营品质 |
| **Q2** | 虚假承保调节业绩 | 互联网经营品质 | **查异常**：真实性 + 互联网风险 |
| **Q3** | 新业务总部专项 | 新产品调研 | **控新险**：新业务 + 战略业务 |
| **Q4（次年）** | 回头看 | 整改验收 | **促闭环**：整改验证 + 长效机制 |

### 四条主线的功能

四主线是**功能分层**，不是项目分类：同一项目可以同时服务两条主线。

| 功能层 | 要解决的问题 | 对应动作 |
| --- | --- | --- |
| **守住底线** | 监管规则是否真正落实到业务执行 | 报行合一、综合治理专项 |
| **穿透异常** | 经营结果和业务数据是否真实 | 虚假承保、业务品质、互联网品质专项 |
| **前置新业务** | 发展是否快于风险管理能力 | 新业务总部专项、新产品调研 |
| **督促闭环** | 问题发现后是否真正解决 | 回头看、分级整改验收 |

> 两个常见命名变体，含义相同，按汇报场合选一个：
> 叙事版「守底线 · 查异常 · 控新险 · 促闭环」；汇报版「守底线 · 控风险 · 促合规 · 督闭环」。

### 年度节奏的写法

- Q4 承接存量问题，同时启动监管重点专项，避免跨年空窗。
- 上半年集中解决监管合规与经营真实性问题。
- 第三季度前置介入新业务，此时风险尚未充分暴露，调研价值最高。
- 第四季度集中验收，并把专项发现沉淀为指标与制度。

## 5. 项目卡模板

复制下面模板，每个项目填一张。

```markdown
### 项目名称
- **业务线**：车险 / 个非
- **季度**：按计划清单
- **优先级**：P0 / P1 / P2（理由：红线 / 战略 / 数据量）
- **覆盖范围**：总部 / 区域代号 / 产品范围
- **检查方式**：专项检查（数据筛查 + 非现场 + 现场）

**WHY｜为什么做**
（风险信号 + 监管依据 + 不做的后果）

**WHAT｜重点看什么**
（维度清单，逐条可核对）

**WHERE｜重点查哪里**
（机构代号、产品、业务场景；说明筛选口径）

**HOW｜怎么检查**
（数据筛查规则 → 抽样 → 现场/非现场 → 结论形成）

**RESULT｜希望形成什么**
（问题清单、整改要求、可沉淀的监测指标）

**来源**
（计划清单 / 稽核地图红黄灯 / 监测预警 / 负面清单 / 战略规划 / 整改台账）
```

填写示例（占位）：

```markdown
### 报行合一监测专项
- **业务线**：车险
- **季度**：Q1
- **优先级**：P1（红线 + 监管处罚高发）
- **覆盖范围**：区域 A/B/C
- **检查方式**：专项检查（监测数据筛查 + 现场核查）

**WHY｜为什么做**
客户服务异常兑现与销售费用监测已形成连续风险信号，且该领域历史上出现过停业级处罚。
**WHAT｜重点看什么**
客户服务异常兑现、报行合一客户信息、虚开发票。
**WHERE｜重点查哪里**
监测排名靠前的省级分公司（区域代号），以服务兑现与费用列支为主线。
**HOW｜怎么检查**
先跑监测口径锁定异常保单，再按机构抽样核对服务兑现凭证与费用列支。
**RESULT｜希望形成什么**
问题清单与整改要求；沉淀为可常态化的服务兑现与费用监测指标。

**来源**
计划清单；稽核地图红灯；负面行为清单命中项。
```

## 6. 共性风险与治理动作

十条左右的专项，背后其实是三个共性问题加一条治理要求。汇报时讲共性，比逐个念项目更有说服力。

| 主线 | 车险侧 | 个非侧 | 共同问题 |
| --- | --- | --- | --- |
| **守底线** | 费用真实性、报行合一、服务权益兑现 | 条款费率、特别约定、产品与费用、互联网营销 | 业务实际执行是否与监管要求、报备规则和公司制度一致？ |
| **查异常** | 虚假承保、业绩调节、批退注销、重复投保 | 产品组合异常、亏损、高退保、虚假/流量业务 | 异常数据背后是否存在流程缺陷、违规经营、虚假业务或损失风险？ |
| **控新险** | 新业务（战略重点） | 新产品、互联网渠道、第三方合作 | 新业务快速发展时，制度、系统、监测指标和管理机制是否覆盖关键风险？ |
| **促闭环** | 整改专项 + 回头看 | 高风险事项分级验收 | 问题发现后是否真正解决，同类风险是否复发？ |

> 促闭环不是第四类业务风险，而是贯穿前三条主线的**治理要求**。这一点决定了它应该是一条横向闭环带，而不是并列的第三个柱子。

## 7. 管理闭环与年度价值

### 闭环

```text
监管要求 ─────┐
经营数据 ─────┼──→ 风险识别 → 对象筛选/排序 → 专项立项
新业务变化 ───┤                                  ↓
历史问题 ─────┘                        数据筛查 + 现场/非现场核查
                                                  ↓
                                    问题确认 + 风险定性
                                                  ↓
                                          整改推动
                                                  ↓
                                    整改验收 / 回头看
                                                  ↓
                     制度 / 流程 / 监测指标 / 稽核地图优化
                                                  ↓
                                      下一年度风险识别 ↺
```

### 年度价值用三个结果表达

| 结果 | 判断标准 |
| --- | --- |
| **风险有没有看清** | 能否说清重点风险、重点机构和重点产品 |
| **问题有没有解决** | 是否推动责任落实并完成整改验证，而非停留在材料报送 |
| **机制有没有留下** | 是否转化为制度流程、监测指标或稽核地图，减少同类问题复发 |

汇报收尾不要写「完成 N 个项目」这类任务型结论，改为表达治理价值；也避免把「计划开展」写成「已实施」。

## 8. 交付前检查清单

| 序号 | 检查项 | 判据 |
| --- | --- | --- |
| 1 | 事实源唯一 | 项目名称、季度、覆盖范围全部来自计划清单，逐条可对应 |
| 2 | 名称一致 | 同一项目在正文、表格、附录中的名称完全相同；有曾用名的已注明 |
| 3 | 季度一致 | 计划表与叙事材料的季度无冲突；有冲突的已记录并标注待确认 |
| 4 | 外部资料用途 | 监管文件只出现在「背景/依据」，未新增检查事项或维度 |
| 5 | 项目卡完整 | 每个项目都有 WHY/WHAT/WHERE/HOW/RESULT 五问 |
| 6 | 范围可执行 | 「重点查哪里」能落到机构代号与产品范围，不是「全国」 |
| 7 | 输出有沉淀 | 每个项目至少沉淀一项监测指标或风险特征 |
| 8 | 分级验收 | 整改验收写明等级、复核方式与比例，比例来源已标注 |
| 9 | 状态用语 | 已实施 / 计划中 / 待确认 三类状态不混写 |
| 10 | 脱敏 | 真实公司名、人名、机构名、金额、件数 0 命中 |

## 附录 A｜来源与已知差异

### 材料角色

本轮材料由四类来源构成，角色不同，不能互相替代：

| 材料类型 | 在本规划中的作用 |
| --- | --- |
| **计划清单（表格台账）** | 项目名称、季度、覆盖范围、检查重点的唯一事实源 |
| **规划叙事材料（H5/汇报稿）** | 风险背景、数据证据、项目目标、检查逻辑 |
| **结构化整理（逐页梳理）** | 把图片/PDF 转成可检索文本，记录口径差异 |
| **监管材料摘录** | 条款级检查依据；只用于核验，不新增事项 |

### 已知差异（本轮实际遇到，仅记录不修正）

1. **车险专项季度互换**：规划叙事材料把「新业务专项」排在 Q1、「报行合一」排在 Q3；计划清单相反。按第 0 节规则，以计划清单为准，差异保留待业务确认。
2. **个非项目时间两套口径**：叙事材料标注的是「启动时间/页面标签」，计划清单标注的是「年度排期」，两者相差一个年度。使用时必须区分，不能混为同一含义。
3. **项目名称变体**：同一季度项目在叙事材料与计划清单中各有一个名称（如「同业专项」与「回头看」），本文统一按计划清单名称表述。

> 这三类差异是方法的一部分，不是错误。把它们写进附录，下一位使用者才知道该以哪份为准。

## 附录 B｜脱敏与复用边界

| 原值类型 | 公开版处理 |
| --- | --- |
| 公司名称、品牌名 | 泛化为「本公司」「某财产保险公司」 |
| 具体机构（分公司/中支） | 写作「区域 A/B/C」或「机构代号」 |
| 人名、主审/助审 | 省略，或写「责任人代号」 |
| 金额、件数、保单量 | 写作 `【N】`，不列绝对值与量级 |
| 比例、阈值 | 保留方法性阈值（如 >50%），标注「示例口径」 |
| 项目金额与业务规模 | 不列示 |
| 监管文件名称与条款 | 保留，标注「引用前核对官方原文」 |

**复用边界**：方法、口径、结构模板、检查维度清单、验收规则可以复用；具体部门、人员、职级、风险条件、金额、时限、比例、评分与实施安排属于案例，必须按新项目的有效材料重新确认。
