# PPT 页面规划与可编辑交付

这份规范补充说明如何把已经核对过的口播内容转成可修改的 PPT。视觉方向可参考本项目已有的可编辑终稿和最新经理修改版扫描页；具体业务内容以每次新材料为准。

## 1. 页面结构

采用“目标与范围—总体机制—流程与职责—逐步办理要求”的展开方式。封面后设置目录；每页使用主标题和副标题，副标题承载核心理念、变化或办理原则。核心理念放在对应页面中，不单独制造口号页。

总流程、目录、展开页和回溯图的步骤名称、编号和顺序保持一致。流程总览中的每个步骤保持同一层级，风险分级、差异化审批、追踪和验收作为步骤内展开。关键时点写入所属环节，不单独堆成一页。

页面只保留有业务用途的标题、字段、步骤、表格和说明。删除无实际用途的页签、跳转小卡、零碎标签和演讲者窗口，但不要为了极简让页面空洞，也不要把完整口播稿挤进页面。

## 2. 内容关系与展示方式

| 内容关系 | 优先展示方式 |
| --- | --- |
| 同层级职责主体 | 横向并列，主体、职责和结果一一对应 |
| 不同风险等级 | 对照表，条件、影响范围和管理要求对应 |
| 新旧变化或实施状态 | “已有机制／当前调整／后续安排”并列 |
| 办理事项、主体、时点、交付物 | 原生表格或字段对照 |
| 顺序、审批、分支、回溯 | 流程图和可编辑连接线 |
| 分析维度与办理结论 | 分析维度辅助说明，落地判断和责任衔接作为主信息 |

表格和流程应服务于内容关系。页与页之间的配色、标题层级、编号和模块样式保持一致；不要求逐像素复制 H5，但要保持内容结构和视觉方向一致。

## 3. 可编辑与视觉检查

- 正文使用原生文字，表格保留原生单元格，流程使用可修改形状和连接线。
- 不把整页 H5 或 PPT 截图当作正文主体。需要引用扫描页时，将其放入“参考资料”目录，并在正文中另做可编辑版本。
- 以白色为主页面底色，使用稳重的橙色做重点，浅橙和浅灰组织次级信息。橙色底上的文字使用白色加粗；浅色底使用深灰字。
- 模块、标题条和流程节点采用圆角；表格圆角处理外轮廓，内部网格保持清楚，不把每个单元格拆成独立卡片。
- 根据内容密度调整字号、文本框、行距、列宽和内边距，不机械固定字号。先解决分组和布局，再考虑缩小文字。
- 同一层级的表头、节点、模块和页脚全稿统一。每页渲染检查文字是否遮挡、溢出、断词、对比度不足或缩小到难以阅读。

## 4. 版本和参考资料

仓库中的可编辑 PPT 用于复用结构和对象做法；最新经理修改版扫描页用于参考最新的页面组织、标题层级、流程呈现和视觉一致性。扫描页是展示参考，不应被误认为可编辑交付。

新项目开始时，先读取本目录的 `AGENTS.md`、`README.md`、内容整理规范、视觉规范和本文件，再查看参考 PPT。完成内容核对和口播后，才开始制作或调整 PPT。
