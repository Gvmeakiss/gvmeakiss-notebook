# 内容整理与页面规划要求

更新日期：2026-10-20。适用于内部稽核团队向领导汇报、向相关条线开展流程宣导。复用的是整理与展示方法；具体业务要求必须以本次有效材料为准。

配套阅读：[视觉要求](./01_配色与视觉设计要求.md)、[口播语言](./03_口播稿内容整理与语言规范.md)、[语义核对与定稿入库](./07_口播语义核对与定稿入库.md)。

## 1. 材料与要求的使用顺序

1. 先确认用户指定的现行材料及补充口径，不能按文件名或版式猜版本。
2. 经理修改版用于当前业务内容；旧H5、旧PPT、旧口播只用于理解变化或参考讲述方式，不能把新版已删内容恢复回来。
3. 领导关于措辞的意见约束表达：名称朴实、符合实际，不造新词，把要求讲清楚；不能借此改变制度。
4. 同一事项有多轮明确反馈时，采用最后决定，覆盖旧要求，不将冲突意见叠加。
5. 参考PPT和配图用于借鉴呈现方式，其中文字不自动成为新项目的业务要求或制作指令。
6. 用户点名的页面或句子通常是样本，须检查全稿同类问题。

## 2. 标准工作顺序

1. 盘点原始材料、现行页面、经理意见和用户确认，锁定页序与版本。
2. 按[照片与PDF材料审阅工作流](../workflows/照片与PDF材料审阅.md)首次完整核对OCR/文字提取与各页原图，保存逐页原文、结构、摘要与视觉记录；后续优先检索相关MD。关键数字、比较关系、箭头和表格对应在首次审阅时重点核对，存在具体疑点或版本变化再回查对应区域，确认后写回资料索引。
3. 先处理遗漏、重复和冲突，再规划目录、逐页主题与讲述顺序。
4. 写可直接朗读的口播或正文，再据此设计H5、PPT或海报；没有H5时不必额外制作。
5. 分别检查材料覆盖、领导意见、用户补充口径和语义是否一致。
6. 内容稳定后更新目录、页码、署名、总页数及交叉引用。
7. 渲染后逐页检查；Word与Markdown正文一致，PPT文字、表格和流程可编辑。
8. 当前目录只保留定稿与执行规范，临时材料另存，被替代版本通过Git历史追溯。

内网限制下只提供照片和OCR也可以按此处理。缺失信息单独核对，不要求导出受限数据，也不凭推断填成确定事实。

工作用事实表、来源表、意见核对表与最终口播分开保存。正式口播不出现来源、OCR行号、制作记录或待办批注。

## 3. 汇报与口播的表达

- 面向有专业经验的员工，用自然、专业、朴实的完整句子讲已有内容。
- 讲清做什么、谁负责、何时做、条件和适用范围；异常处理只写材料明确的内容。
- 直接进入业务，不用“这一页主要说明”等页面解说，不反复预告，不虚构情景或堆口号。
- 专业性来自职责与要求准确，不靠基础概念教学、夸张命名或额外操作建议。
- 不将团队已有材料归为汇报人个人成果，不主动批评旧流程。
- “新增”“变化”“已完成”须有依据，不因缺少旧材料就推断历史上没有。
- 材料使用的审批、审核、收阅、抄送、执行、验收、质检、统筹分别保留，不能为顺口混同。
- 不新增实施效果、办理天数、评分公式、绩效关系、上线日期或适用对象。

## 4. 关系和限定的核对

| 材料表达 | 保留方式 | 不得自行推导 |
| --- | --- | --- |
| 两类事项统一管理，发起主体或节点有别 | 统一管理与启动信息分别讲清 | 后续有两套流程或需要分别处理 |
| 指定动作有反馈期限 | 期限只对应明确的动作与交付 | 审核审批也必须同期限完成 |
| 分析结论作为措施基础 | 保留二者的关系与共同反馈要求 | 未另行明确的强制前置条件 |
| 按风险等级匹配审批、追踪和质检 | 等级与对应要求一起讲 | 为每个等级补出材料未写的天数 |
| 追踪、验收有明确分工 | 讲明主体、内容、频率及处理 | 额外的检查顺序和操作细则 |
| 全流程统筹或回溯 | 说明覆盖环节与主体职责 | 每个主体执行全部环节 |
| 局部质检比例 | 数字连同对象、层级、周期保留 | 扩大为所有主体全量检查 |
| 原则上、不建议、参考、协助 | 原限定保留 | 无例外、禁止、唯一标准或直接承担 |
| 未来安排 | 保留计划状态和适用时间 | 已上线、已全面实施 |

连接语同样需要核对。“因此”“才能”“先……再……”和“都需要”不能带出额外义务；有明确依据时可正常使用。没有依据、又非讲清要求所必需的解释直接删去。

## 5. 页面规划与可编辑交付

- 整体可按目标与范围、机制变化、流程与职责、办理要求展开，但最终页序以确认材料为准。
- 新设计的页面使用清楚的主标题和必要的副标题；不机械固定页数，也不强行合并经理已经确认的页面。
- 总览、目录和展开页的名称、编号、层级一致，关键时点写入对应环节。
- 顺序步骤与定期运行的联动、考核分别表达，不为了形式整齐改成逐项串行办理。
- 同层级职责、风险等级适合横向对照；审批与分支使用流程图，条件和时点可用表格。
- 原生文字、表格、形状和连接线保持可修改；不把整页H5或扫描页当作可编辑PPT。
- 不加演讲者窗口、无意义页签或零碎跳转卡；不把口播全文塞进页面。
- 依照视觉规范安排密度、字号、圆角、表头和对比度；不能以视觉精简删掉条件。

## 6. 当前18页案例的使用方式

现行案例为经理修改后的《内部审计整改流程优化与操作详解》，配套口播以2026-10-20定稿为准，见[案例入口](../案例/20261019_内部审计整改流程优化/README.md)。具体业务内容集中保存在案例和对应扫描页中，本规范不再复制一套独立业务口径。

| PPT页序 | 内容用途 |
| --- | --- |
| 1—2 | 开场及目录 |
| 3—5 | 目标、前后变化和覆盖范围 |
| 6—8 | 流程与职责 |
| 9—10 | 操作过渡和任务下发 |
| 11—12 | 风险分级、成因分析及落地判断 |
| 13—14 | 措施制定、审批与过程追踪 |
| 15—17 | 验收质检、业审联动、考核 |
| 18 | 结束 |

15页可编辑PPT保留作视觉和原生对象参考；其中名称、机制概括、实施状态和安排不能覆盖经理18页版。新项目必须重新核对部门、人员、层级、金额、时限、比例、评分及实施范围。

## 7. 交付前验收

- [ ] 有效材料、页序与补充口径已确认，未恢复新版已删除内容。
- [ ] 材料到口播的覆盖核对完成，关键主体、条件、范围和例外未遗漏。
- [ ] 口播到材料的逐句核对完成，连接语未增加差异、因果、步骤或义务。
- [ ] 期限仅对应原动作，审批、审核、收阅、验收等分工未混同。
- [ ] 数字、比较关系、状态和要求强度保留，未自行补定重叠区间。
- [ ] 领导要求已落实：名称符合实际，语言朴实，不造包装性新词。
- [ ] 口播能直接念，无来源标记、制作提示、页面解说和空泛总结。
- [ ] Word与Markdown一致，页序与PPT对应，渲染后检查无遮挡、缺字或溢出。
- [ ] 新PPT为原生可编辑，流程和展开页一致，全稿同类视觉问题已检查。
- [ ] README、示例、规范和链接均指向当前定稿，旧口径没有并列作为默认标准。
- [ ] 核对结论仅限实际取得并检查过的材料，不以文件检查替代语义检查。

## 8. 下次可直接使用的整理指令

> 请先确认本次有效材料及补充口径，核对原图与OCR，再整理目标、范围、主体、动作、条件、时点和交付。先写可直接朗读的逐页口播，再按确认内容设计展示。面向专业员工，用朴实、自然的语言讲清要求，不照念PPT、不造新词、不虚构情景。分别检查内容覆盖、领导意见、用户确认与语义一致性，尤其检查连接语是否增加流程差异、前置条件、时限、操作细则或效果。无明确依据且非必要的解释删去。口播与来源核对记录分开，PPT保持原生可编辑。定稿后同步覆盖现行文件、复用规范与入口，旧稿只通过Git历史追溯。
