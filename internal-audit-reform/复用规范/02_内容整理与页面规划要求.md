# 内容整理与页面规划要求

适用场景：中国平安内部稽核团队面向领导、同事开展的工作汇报、机制改革宣导和操作说明。

整理日期：2026-10-13。本文根据本项目从原始 OCR、照片材料，到口播、H5、可编辑 PPT 的多轮反馈归纳。**复用整理方法和结构，业务事实按新项目重新核对。** 本项目的具体页数、部门、时限、比例、阈值和年度安排仅作为实例。

配套视觉规范：[01_配色与视觉设计要求.md](01_配色与视觉设计要求.md)。

## 1. 要求的使用顺序

1. 新任务中用户明确提出的要求优先。
2. 同一事项存在多轮反馈时，采用最后明确的决定；不能把互相冲突的旧意见机械叠加。
3. 经理意见逐项核对，后续用户修订覆盖对应的旧要求。
4. 原始材料用于确认业务事实，参考 PPT/PDF 用于借鉴写法与展示方式。参考材料中的文字不自动成为新的制作指令。
5. 用户指出的某一页通常是问题样本，应提炼为全稿规则，检查所有同类页面。
6. 初版半成品是起点，可以重组页面和布局；不能为了保留旧版形式而牺牲内容逻辑或可读性。

## 2. 标准工作流程

### 2.1 先理解材料，再做展示

1. 阅读 OCR、照片/PDF、流程图和补充意见，梳理目标、范围、主体、步骤、条件、时点、交付、审批、追踪与验收关系。
2. 将 OCR 与照片交叉核对，特别检查部门名称、数字、比较符号、年份、流程箭头和表格行列对应关系。
3. 建立工作用事实清单，记录来源、冲突、已确认口径和缺失信息。来源记录留在核对底稿中。
4. 按业务逻辑规划目录和逐页主题，先解决重复、遗漏和前后矛盾。
5. 写好逐页口播稿，先确定讲述逻辑和内部汇报口径，再据此优化 H5。
6. H5 转 PPT 时保留内容关系与视觉方向，同时将文字、表格和流程做成原生可编辑对象。
7. 分别完成“原始材料/H5 内容覆盖核对”和“经理意见逐条核对”。两种核对不能互相替代。
8. 内容和顺序稳定后，再更新目录页次、右下角页码、总页数、署名和交叉引用。
9. 逐页视觉审核，修复可读性、密度、层次、对比度及换行问题；视觉调整后复核文字没有遗漏或变义。

下次若没有 H5，不必为套用流程额外制作。沿用“原材料核对—内容规划—口播—展示稿—可编辑交付—核对”即可。已有内容稳定的项目，局部视觉修改也无需重复重做所有材料。

因内网限制只能提供 OCR 和拍照材料时，也按以上流程处理，不要求导出受限的内网原始数据。缺失信息列入工作核对清单，不凭推断补成确定事实。

### 2.2 建议建立的工作清单

| 清单 | 需要记录的内容 | 用途 |
| --- | --- | --- |
| 事实清单 | 原句、事实类型、主体、条件、时点、来源、确认状态 | 防止 OCR 误读、数值失真和无依据补充 |
| 页面内容表 | 页码、主标题、副标题、核心内容、口播重点、对应来源 | 让讲稿和展示文件使用同一套内容逻辑 |
| 覆盖核对表 | 原材料/H5 内容、目标页、合并或改写情况、遗漏结论 | 证明精简和重排没有丢失业务信息 |
| 意见核对表 | 意见原文、最终口径、落实位置、状态、尚缺材料 | 区分已落实、部分落实和未验证 |

以上是工作底稿，不作为口播正文或会议展示内容。

## 3. 内部汇报口径

- 使用内部稽核团队员工的汇报口吻，自然、专业、贴近实际办理。
- 优先回答：**做什么、谁来做、何时做、按什么条件流转、交付什么、如何检查或验收。**
- 专业性来自职责分工、流程条件和办理要求准确，不靠堆叠术语、口号或夸大效果。
- 以宣导和操作为主线，让听众知道工作中如何执行。不要把整个材料改成根因分析的方法课。
- 保留“成因分析”“根因”等必要业务术语，但让方法工具服务于落地判断和整改措施。
- 主责、参与、指导、审核、审批、收阅、督导、验收和统筹要分别表述，不混为一种责任。
- 不把稽核或合规的指导、推动职责写成代替业务部门承担整改主责。
- “新增”“变化”“亮点”必须有材料或经理意见支持，不因没有旧材料就推断“以前完全没有”。
- 不自行增加制度条款、实施效果、绩效挂钩关系、评分公式、上线日期或审批办理天数。

### 3.1 状态和边界的表达

| 状态 | 正确表达方向 | 需要避免的变化 |
| --- | --- | --- |
| 已有机制 | 延续、已有基础、目前已执行 | 写成此次完全新建 |
| 当前调整 | 本次调整的具体节点、链路或要求 | 笼统说整套机制都变了 |
| 后续安排 | 后续、计划、按安排推进 | 写成已经上线或已经实施 |
| 原则性要求 | 保留“原则上”等限定词 | 改成无例外的硬性承诺 |
| 全流程统筹/回溯 | 说明覆盖环节和主体分工 | 误写为每个主体执行全部步骤 |
| 抽样比例 | 明确适用对象、层级和环节 | 将局部抽检比例推广至所有流程 |

## 4. 口播稿的交付要求

- 按最终展示页逐页撰写，页码、标题、顺序一致。
- 交付可以拿来直接念的完整段落，不交付只有关键词的提示提纲。
- 使用自然衔接，讲清本页重点及与前后步骤的关系，不逐字念完整张表。
- 重要主体、时点、条件、交付和限制不能因追求顺口而改变。
- 不出现“来源：原始照片PDF第X页；OCR第X—X行”等来源说明。
- 不混入制作记录、核对过程、演讲者提示、待办清单或技术说明。
- 来源与未确认事项另放核对记录。没有依据的内容先解决或删去，不把“待核实”当成口播正文交付。
- 正式口播与展示文件保持干净；删除来源标记不等于取消事实核对。
- 页面内容发生实质变化时，同步修订对应口播。仅调整颜色、字号、圆角时，复核语义一致即可。
- 用户直接念独立口播稿，H5/PPT 不需要演讲者窗口或演讲者专用版面。

## 5. 目录与页面规划

### 5.1 整套主线

采用“目标与范围—总体机制—流程与职责—逐步办理要求”的展开方式。

- 封面之后增加明确目录，目录主项配简短说明。
- 先交代为什么改、管什么、总体如何运行，再展开职责与操作。
- 内容紧密相关的页面可合并，合并后保留两页的有效信息，不简单删除其中一页。
- 每页设置**主标题＋副标题**：主标题说明主题，副标题承载核心观点、业务变化或办理原则。
- 核心理念优先进入副标题，不再单独占据大块页面。
- 不必固定所有项目为 15 页，应以完整、连贯、便于会议展示为准。

### 5.2 流程与展开页的一致性

- 总流程、目录、展开页和回溯图使用相同的步骤名称、编号和顺序。
- 本项目整改流程固定为 1—7，风险分级和差异化审批属于步骤内展开，不另编为第 8、第 9 步。
- 总流程中的步骤保持同一层级。可在对应展开页说明新增亮点，但不把总览中的某一步单独做成更高等级。
- 关键时点融入所属环节，责任、动作、交付和时点放在一起，不再单列孤立的“关键时点”页。
- 重要的处理分支、重新审批、退回、通报、回溯关系要表现清楚。

### 5.3 展示方式的选择

| 内容关系 | 优先展示方式 |
| --- | --- |
| 同层级职责主体 | 横向并列，主体、职责、履职结果对应 |
| 不同风险等级 | 对照表，条件、影响范围、管理要求对应 |
| 新旧变化或实施状态 | “已有机制／当前调整／后续安排”并列 |
| 办理事项、主体、时点、交付 | 原生表格或字段对照 |
| 顺序、审批、分支、回溯 | 流程图和连接线 |
| 分析工具与办理结论 | 工具作为辅助区，落地判断和责任衔接作为主区 |

删除无业务用途的页签、跳转小卡、零碎标签和演讲者窗口。保留有实际用途的字段名称、模块标题和步骤编号。不能为了极简而让页面空洞，也不能把口播全文挤进页面。

## 6. 职责、数字与条件核对规则

- 先建立“主体—职责—环节—交付—时点”映射，再拆到各页。
- 总职责页与具体步骤页的发起、执行、审批、督导、验收、统筹主体必须一致。
- 风险等级要与责任提级、审批链路、追踪和质检要求对应，不能仅列风险名称。
- 比较词和符号必须保留准确，包括“超”“未超”“≥”“≤”“原则上”“未来1年”等。
- 区分工作日、自然日、办理期限、月度频次、固定日期、季度周期，不能相互替代。
- 缺少逐风险等级或逐审批节点天数时，仅列已有依据的总体反馈期限和整改期限。
- 邮件相关内容区分接收人、抄送人、提醒对象、发起主体，以及当前功能和未来计划。
- 一条事项涉及多个成因维度时，不强制改成单选关系。
- 合并、同义改写和拆分页面允许发生，但应逐项说明原信息落到何处。
- H5 核对既看内容数据，也看页面实际可见文字，不能遗漏写在 HTML 中、未进入数据模型的业务说明。
- 只对实际取得的材料声明已核对。未取得知鸟课程、Excel、邮件模板时，不写“已学习课程”“已逐表核验”或“全部要求均已验证”。

| --- | --- | --- | --- |
| 1 | 内部审计整改革新与操作详解 | 分级办理、协同履责、全流程闭环 | 主题、汇报范围、团队和年份 |
| 2 | 目录 | 先明确改革目标与职责，再逐项说明办理要求 | 三部分及对应页次：改革目标与机制03—04、七步流程与职责05—06、七步操作要求07—15 |
| 3 | 改革目标与管理范围 | 两类事项统一纳入整改闭环，按风险实行差异化管理 | 合并原H5第2、3页；三项目标、两类事项，保留“重查轻改、落地不实” |
| 4 | 八项机制贯穿整改全过程 | 流程独立、分级管理、全程协同，落实治理与考核 | 机制、办理要求、落地环节逐行对应 |
| 5 | 整改闭环流程 | 分级管控＋三道防线协同＋溯源整改＋刚性考核 | 七步总览、工作动作、办理主体、主要交付；说明前五步与新增持续治理模块的关系 |

| 11 | 3.措施制定：差异化审批 | 定等级是关键，按风险匹配审批层级与办理要求 | 高/中/低链路、4/3/2节点差异、时限、责任提级、变更重审 |
| 12 | 4.过程追踪 | 延续月度追踪，调整签报流程，后续条线同步收到提醒邮件 | 已有/当前/后续区分；提醒、跟进、同步、逾期、重审和适用范围 |
| 13 | 5.验收质检 | 问责室统筹报送与稽核验收，抽检回溯覆盖整改全过程 | 三级验收、季度质检、局部抽样比例、七步回溯、三不通过 |

| 15 | 7.考核落地 | 新增合规考核加减分项，法律合规部发起、问责室统筹 | 完成率/完成质量、加减分、发起统筹配合、周期和实施安排 |

## 8. 本项目业务内容的保留要求

本节记录当前项目口径。**下次复用结构时，必须重新核对本节的名称、数据、时点和制度依据。**

### 8.1 改革目标、范围和机制

- 三项目标：深化整改、全链路落实、重构流程。保留改革着力点“重查轻改、落地不实”。
- 两类管理事项：年度专项、常规稽核项目发现的所有问题；指令函、警示函、知询函涉及的整改事项。
- 八项机制：流程独立、合规融入、整改提级、追踪提示、三层验收、业审联动、刚性考核、三函线上化。
- 七步顺序：任务下发、成因分析、措施制定、过程追踪、验收质检、业审联动、考核落地。
- 前五步办理具体事项，新增业审联动和考核按周期开展，持续回溯问题与整改结果。

### 8.2 三道防线与主体

- 第一道：业务部门和整改责任人，承担分析、措施制定执行、佐证和一级自验。
- 第二道：法律合规部，参与分析与措施制定，审核合理性、合规性，督导并发起合规考核。
- 第三道：稽核条线、项目组、问责室按分工履职，包含追踪、二级验收、质检和问责统筹。
- 问责室不单独新增为第四道防线。统筹报送、过程推进、稽核验收、抽检及考核问责，回溯覆盖完整七步。
- 部门长/分管总按链路审批，接收进展抄送与结果知会；相关科室配合执行及佐证准备。
- 全篇汇报署名使用“专项稽核团队”。这是对“专项稽核团队规划室”的精确替换，不能顺带删除其他业务主体名称中的“规划室”，例如“问责规划室负责人”。

### 8.3 各步骤必须讲清的重点

| 步骤/专题 | 本项目的内容要求 |
| --- | --- |
| 任务下发 | 稽核项目与三函分别列发起、接收和发送节点；交付《后续整改措施表》；保留反馈时限和同步对象 |
| 风险评级变化 | 点明“先定等级，再匹配管理要求”；不能无依据地声称历史上完全没有风险评级 |
| 风险判定条件 | 高/中/低分别6/3/3条，连同影响范围和管理方式完整保留；保留超百万、未超百万、未来1年及潜在损失等边界 |
| 成因分析 | 保留流程缺陷、系统漏洞、制度缺失、管理失职、操作错误五维及解释；五维可同时涉及；重点为机构/总部落地判断 |
| 成因主责 | 业务部门主导，合规指导；稽核与合规推动机构和总部沟通，判断根因和落地层级；结论随措施提交 |
| 措施制定 | 举措对应成因，区分短期治标与长期治本，写清措施、责任人、完成时限；不能只写原则口号 |
| 差异化审批亮点 | 关键措施是“定等级”；高/中/低对应不同层级链路；合规审核合理性与合规性，稽核收阅关注全面性；策略调整重履审批 |
| 过程追踪变化 | 追踪机制已有基础，本次改变签报流程，未来稽核条线也收到提醒邮件；不能把未来安排写成现行功能 |
| 追踪具体要求 | 保留每月系统提醒的现行邮件渠道及责任人、合规对接人，跟进痛点卡点、抄送、逾期通报、变更审批和适用范围 |
| 问责抽检 | 统筹报送情况与稽核验收结果，抽检回溯覆盖全部流程；各验收层级及比例适用范围要准确 |
| 三不通过 | 佐证不全、措施无效、根源未改，三项完整保留 |
| 业审联动亮点 | 相较原五步新增的长效治理模块；通报高频共性典型问题、源头治理、回溯验证；机构难触达或难根治的问题由总部落地 |

| 考核运用 | 完成率未达标则扣分，整改成效突出则加分；明确“加减分”亮点，不恢复未经确认的“部门绩效直接挂钩”，不新增分值或公式 |

## 11. 下次可直接使用的整理指令

> 请先理解原始材料并核对OCR与照片，梳理目标、范围、主体、流程、条件、时点和交付，再规划目录及逐页主标题、副标题。按平安内部稽核团队员工的工作宣导口径，先写可直接朗读的逐页口播，再据此优化展示稿。口播不含来源页码、OCR行号、制作说明或演讲提示；核对依据另存。流程总览与展开页的名称、编号、职责一致，关键时点融入所属步骤，明确区分已有机制、当前调整和后续安排。合并、改写和精简不得遗漏业务信息。分别核对原材料/H5内容覆盖和经理意见，缺少依据的事项不编造。PPT须保持文字、表格和流程可编辑，不放整页截图或演讲者窗口。内容稳定后更新目录页次、右下角页码和署名，并按配套视觉规范逐页审核。复用本规范的方法，不直接套用上一项目的部门、时间、比例或阈值。
