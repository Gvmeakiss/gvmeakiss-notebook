# 口播稿内容整理与语言规范

这份规范用于把内部稽核汇报材料整理成可以直接朗读的逐页口播稿。它只沉淀整理方法和表达方式；具体部门、人员、数字、期限、比例、评分和实施安排都必须以新项目的有效材料重新确认。

## 一、先确定材料依据

1. 先锁定用户明确确认的现行 PPT、H5、扫描页或其他材料。不能只按文件名、修改时间或版式新旧判断版本。
2. 经理修改版、旧版 PPT、H5 和旧口播稿分别标明用途。旧版用于识别变化和理解背景，不把新版已经删除的表述补回来。
3. 用户本轮补充的口径用于解释对应内容；如果与旧稿冲突，以用户最新确认的口径为准，并在独立复核说明中留下记录。
4. OCR 适合检索，关键职责、数字、审批顺序、比较符号和限定词要回看原图。看不清、来源冲突或区间重叠时，不自行补定制度。
5. 领导对外部材料的语言意见约束表达方式，不等于可以改变业务规则。删掉夸张命名和新造词，同时保留必要的业务名称和办理要求。

## 二、按业务关系整理内容

先整理“讲什么”，再润色“怎么讲”，最后检查 Word 阅读和分页。每页只确定一个主要用途：交代目标、说明范围、解释分工、给出操作要求、说明变化或结束汇报。

逐页建立以下对应关系：

| 要核对的问题 | 说明 |
| --- | --- |
| 谁来做 | 发起、执行、参与、审核、审批、收阅、验收、质检、统筹分别记录 |
| 做什么 | 具体动作和交付物，不用“加强协同”等空泛词替代 |
| 何时做 | 发送节点、反馈期限、固定日期、月度或季度频次分别记录 |
| 按什么条件流转 | 风险等级、适用范围、前置条件、例外和限定词完整保留 |
| 如何检查 | 自验、复核、验收、质检、退回、通报和回溯分别说明 |
| 不满足怎么办 | 重新审批、补充整改、通报或其他处理要写清主体和触发条件 |

总览页说明整条关系，详解页说明实际操作。可以适度复述以帮助听众定位，但不要每页都预告“后面再展开”，也不能为了顺口删除条件、范围、例外或责任主体。

新旧差异采用“在原有基础上新增、细化或明确了什么”的表达，不主动批评旧流程，也不把团队已有工作写成汇报人个人成果。把先后步骤和持续运行机制分开讲，不为了整齐把所有工作包装成一个新方法名称。

## 三、直接可念的自然表达

- 正文直接进入业务内容，不用“这一页主要说明”“页面列出”“从图中可以看到”等页面解说开头。
- 目录页可以短句承接，例如“先说调整目标和涉及范围，再说明各方如何分工”，不机械报栏目标题。
- 用具体主语和动作代替概括口号：谁分析、谁审批、谁反馈、谁验收，要在句子里出现。
- 一句表达一个主要动作或关系。长条件拆成短句，但审批顺序、适用范围和条件关系不能被拆散或改义。
- 保持部门汇报的专业程度，不加口语填充词，不刻意讲故事，不虚构现场案例。
- 保留材料已有的专业名称，并解释它对应的工作；不创造“七步法”“五维工具”等包装性名称。
- 不邀功、不拔高。使用“本次调整”“在原有流程基础上”等客观说法，不写“我构建了”“我提炼了”。
- 不空泛收尾。说完本页需要交代的要求即可，不为了收尾补“推动高质量发展”等没有依据的效果判断。

规则强度必须原样保留。“原则上”“不建议”“参考”“协助”“至少”“不低于”等词不能在润色中删掉或改成绝对表述。发起、执行、审核、批准、收阅、追踪、验收、质检和统筹也不能为了句子短而混同。

## 四、数字和边界的核对

数字要和主体、周期、分母、范围一起核对。金额、风险等级、比例和评分档位不能脱离适用范围单独搬运。比较词和符号也要保留，包括“超”“未超”“不低于”“原则上”“未来一年”等。

同时检查期限起点、完成期限、无法完成时的处理，以及区间端点。遇到重叠区间，只有在用户确认后才能写成“达到……但未达到……”，不能凭感觉补充容差、四舍五入或其他规则。

具体项目中的姓名、职级、部门、金额、比例、评分档位和实施年份只属于该项目案例，不能写进通用规则，下一次必须重新核对。

## 五、交付和复核

口播稿只放可直接朗读的正文和用于定位的页标题，不放来源页码、OCR 行号、制作记录、审校提示、待办事项或演讲者窗口。来源、冲突、未确认事项和页面显示问题放到单独的交叉复核说明中。

完成后做三次核对：

1. 口播稿对现行 PPT：页码、标题、数字、主体、动作和条件一致。
2. 口播稿对领导意见：逐条确认删改、合并和新增内容的落实位置。
3. 口播稿对用户补充口径：特别检查边界、限定词、例外和要求强度。

最后只检查朗读体验：删除页面介绍、重复预告、空泛总结、过长句和生硬衔接。Word 与 Markdown 正文应保持一致，并检查最终分页和可读性。

## 六、可复制的任务提示

> 请以【本次确认的 PPT/H5/扫描材料路径】为现行依据，为【汇报对象及使用场景】撰写逐页口播稿。【旧版路径】仅用于识别变化，不沿用新版本已删除的内容。请先确认页数、顺序和材料版本，再逐页核对责任主体、办理动作、材料、时点、审批路径、条件、适用范围及异常处理。
>
> 稿件要能直接朗读，语言专业、朴实、自然。正文直接讲业务，不使用“这一页主要说明”“从图中可以看到”等页面介绍，不反复预告“后面再展开”，不制造新名词，不夸大调整效果，也不把团队已有成果归为汇报人个人成果。目录页只作简短承接。
>
> 保留原材料中的“原则上”“不建议”“参考”“协助”等限定，不改变职责分工和规则强度。数字必须连同对应主体、期限、范围和边界一起核对。看不清或存在冲突时单独提出，不自行补定制度；旧案例中的具体姓名、数字和部门安排不能直接迁入。
>
> 请交付内容一致的 Word 与 Markdown 口播稿，以及单独的交叉复核说明。口播正文不放来源、OCR 行号、审校提示或待确认事项。复核说明需对照现行 PPT、领导意见和用户补充口径逐项检查，记录新增、删除及调整内容，最后检查自然朗读效果和 Word 分页。
