# AI协作约定

接手本项目时，先阅读本目录的 `README.md` 和 `复用规范/00_项目导航与结果导向.md`，再按任务阅读相关规范。收到照片、截图或 PDF 时，先执行 [照片与PDF材料审阅工作流](./workflows/照片与PDF材料审阅.md)，优先检查已有资料索引及有效版本。

## 材料读取与复用

- 新材料首次完整审阅全部页面，形成 INDEX、逐页原文与摘要、结构关系、VISUAL_SPEC 和来源指纹；不要把一次 OCR 成功等同于内容、结构和配色均核对准确。
- 后续先检索 INDEX 和相关页 MD；设计任务再读视觉记录。只在具体疑点、信息密集区域、版本变化或尚未记录的视觉细节需要核验时回看对应图像，回查结果立即写回材料包。
- 标题和业务要求取自本次有效材料的已核对文本；不能用历史记忆、旧口播或删减后的海报替代原文。用户后续文案调整独立记录。
- 文字、结构、配色分别记录核对状态。拍照取色、字体和尺寸标为估测，不充当正式 VI 色值或原稿精确参数。
- 当前材料包默认本地保存。公开仓库收录工作流和空模板，不自动同步新材料的原图、OCR、逐页业务文本或缓存。

## 工作顺序

1. 按材料审阅工作流清点有效版本、复用已核对材料包，再按主体、职责、步骤、条件、时点、交付物和状态建立核对关系。
2. 先核对内容与经理意见，再设计页面；先写可直接朗读的逐页口播稿，再优化PPT。
3. 用户提供的新材料优先于本目录的示例交付。遇到冲突时保留差异并明确提出，不擅自选取方便的一种口径。
4. PPT文字、表格、流程和卡片应保持可编辑。不要把整页拍照或导出成一张背景图，不增加演讲者窗口。
5. 需要配图时从 `素材库/` 中选择少量合适素材；保持图片比例，避免压住标题、表格或正文。
6. 内容定稿后逐页核对PPT与口播。复用时按交付要求生成最终文件，过程稿与渲染图不要冒充交付成果。

## 内容与口播

- 口播采用稽核团队员工汇报口吻，直接、专业、贴近实际操作；描述做什么、谁负责、何时完成、按什么条件流转以及如何验收。
- 口播必须是能直接念的完整语句，不写来源页码、OCR行号、制作记录、演讲提示或待办事项。
- 已有机制、当前调整、后续安排须明确区分；后续计划不得改写为已上线或已实施。
- 区分业务整改主责、合规审核督导、稽核复核验收、问责统筹，不混淆审批、收阅、抄送和执行职责。
- 风险等级、金额阈值、比例、时限、年份、层级和发起主体均须以本次有效材料为准，不将示例中的数字或制度口径直接推广。
- 内容合并或精简时，保留条件、适用范围、例外、责任主体和时点。
- 对连接语也做事实核对。来源、发起人或发送节点不同，不代表后续办理流程不同；并列内容不能自行改成前置条件、办理顺序或因果关系。
- 反馈期限不能扩展为审核审批的完成期限；材料未明确的操作细节，不凭工作常识补写。
- 不只核对数字和名称，还要检查听众是否会从整句话理解出新增要求。无明确依据且非必要的解释直接删去。
- 面向有专业经验的员工，讲述应自然、朴实、清楚；不照念PPT，不虚构案例，不做低水平概念教学，也不用额外推论增加“口语感”。

## 视觉与交付

- 以白色为主，使用配套色板中的橙、浅橙和灰色；圆角表格与卡片应服务于分组和阅读，不因早期意见提过浅蓝就自行加回。
- 橙色底上的文字使用清晰的白色粗体；根据页面内容调整字号，不为满足固定字号而制造空白。
- 流程总览、展开页和目录的名称与编号保持一致。关键时点写在对应步骤中。
- 最终PPT与口播逐页对应。最终文件命名清楚，逐页检查文字是否被遮挡、溢出或缩小到难以阅读。
- 只在本次明确要求的文件和目录范围内整理成果；不把临时导出物、日志、缓存或无关个人文件混入交付包。

## 交付前校验（每条都要过）

| 项 | 判据 |
| --- | --- |
| PPT 可编辑 | 打开后每页文字都能选中修改，不是图片贴上去的 |
| 口播与页面一一对应 | 逐页口播稿的页序、标题、数字与 PPT 完全一致，无多页无少页 |
| 数字一致 | 正文、口播、配图里出现的同一数字必须相同 |
| 语义一致 | 连接语、因果、先后、范围和规则强度没有带出材料未明确的要求 |
| 业务条件已标注 | 时限、金额、部门等只适用于示例项目的条件，必须在页面上显式标注适用范围 |
| 配图可追溯 | 每张配图的来源与替换说明都记录在配图库索引里 |
| 脱敏 | 搜真实公司名 / 人名 / 单据号 / 内网标识，0 命中 |

## 红线

- **不把示例业务条件写成通用规则** —— 本套资料的业务口径只适用于对应示例项目
- **不提交**真实底稿、客户数据、内部规范原文、含真实业务数字的截图
- 交付物以"可复用"为准：方法、模板、配图规范入库；一次性素材不入库

## 口播与 PPT 复用入口

- 口播整理方法和自然句式见 `复用规范/03_口播稿内容整理与语言规范.md`、`复用规范/04_口播句式对照.md`。
- PPT 页面关系、可编辑对象和视觉检查见 `复用规范/05_PPT页面规划与可编辑交付.md`。
- `案例/20261019_内部审计整改流程优化/` 保存2026-10-20定稿的18页口播、最终核对结果和本轮对话确认事项；目录日期为项目归档起始日。`参考资料/最新经理修改版18页PPT扫描参考/` 是对应的经理修改版扫描参考。
- 当前目录只保留现行稿和可执行规范；被替代的稿件通过Git历史追溯，不作为并列默认版本。15页可编辑PPT仅用于视觉及原生对象参考，不能作为18页现行业务内容依据。
- 案例和扫描参考用于学习结构与表达，不得把其中的业务条件直接迁移到新项目。
