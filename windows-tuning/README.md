# Windows 调优：按配置顺序排列

这个目录不是文集，是**一条装配线**：从拿到一台机器，到它变成能干活、能打游戏、出问题能回滚的状态。

文件编号 = **实际配置顺序**，不是重要性排序。你可以在任意一步停下，但不要跳步 —— 跳步的典型后果是
"先改了一堆注册表，才发现这台机器没有管理员权限"。

## 五步各自解决什么

| 步骤 | 文件 | 回答的问题 | 读完你能做什么 |
|---|---|---|---|
| ① 判定起点 | [01-baseline.md](./01-baseline.md) | 这台机器现在是什么状态？有管理员吗？装了什么？什么版本？ | 判断哪些步骤可行、哪些必须跳过 |
| ② 决定改什么 | [02-decisions.md](./02-decisions.md) | 这么多"优化"到底哪些值得做？ | 拿到一张"做 / 不做"决定表，附机制与风险 |

## 与技能的关系

`skills/win-ai-gaming-setup` 是这条装配线的**可执行版本**：

| 本目录 | 技能里对应的东西 |
|---|---|
| 01 起点的环境事实 | `-Phase check` 的输出 |
| 02 决定表 | `tune` 阶段每条写入的 `Why`，以及**不写**什么 |
| 03 系统调优 | `-Phase tune`（写入）+ `verify-env.ps1` 的 `tweaks` 组（验收） |
| 04 开发环境与软件 | `-Phase dev` / `apps` / `link` |
| 05 游戏 | `05-games/cs2/scripts/` 的体检与应用脚本 |
| 验收与回滚 | `verify-env.ps1`（85 项）+ `tune-undo-<时间戳>.ps1` |

**一句话**：本目录写"应该是什么样、凭什么"；技能负责"把它变成那样，并证明变了"。

## 三条硬约定

1. **文档里的值与代码里的值必须一致** —— 改 `setup.ps1` 的写入就要同步 `verify-env.ps1` 的期望值，反之亦然；
   两者不一致时，以**代码**为准并立即修文档。
2. **只写结果，不写过程** —— 每个文件陈述"当前应是什么状态 + 怎么验证"，不叙述改动历史。
3. **每条结论都要有判据** —— 没有判据的"优化"不进这个目录。

## 维护

| 变化 | 改哪里 |
|---|---|
| 新增一条系统调优 | `03-system-tweaks.md` 加行 + `setup.ps1` 加写入 + `verify-env.ps1` 加检查 |
| 新增一个软件 | `apps.json` 加条目 + `04-dev-and-apps.md` 的清单表 |
| 新增一个游戏 | `05-games/<game>/` 按 [games 模板](./05-games/README.md) + 更新其索引 |
| 发现新的坑 | `reference/pitfalls.md` 加一行（症状 / 根因 / 判据 / 做法） |
