## 五、未采纳的改动及原因

1. **TCP 全端口代理（`1:65535`）**：实测该订阅节点只放行 443 等常用端口，`8443/2053/8080` 经节点连接全部超时，而直连反而可用。改成全端口会把本来能直连的高端口站点变成黑洞，已回退为常用端口列表。
2. **关闭 UDP 代理**：参考方案关闭是 fancyss 的限制；Passwall + Xray 的 UDP 转发正常，保留以支持游戏与语音。
3. **广告屏蔽**：Passwall 的 block 列表优先级高于直连列表，误伤微信等国内 App 的风险与参考仓库的告警一致，未启用；如需可先加小名单试用。
4. **开启 IPv6 代理 / 订阅周更**：订阅已开启“开机自动更新”，周更会引入节点变动风险；IPv6 代理需节点支持 IPv6 出口，未验证前不动。

已知边界（与参考方案一致）：路由器自身 IPv6 出站不经过代理；客户端自带 DoH/DoT 时可绕过 DNS 劫持。

## 九、升级到 iStoreOS 25.12.6（2026-11-18 11:30–11:44）

- 结论：24.10.8 是 24.10 分支最后一版；25.12.6（构建 2026110611）是当前最新正式版，x86_64 通用镜像可用
- 跨大版本：25.12 把包管理器从 opkg 换成 apk，官方不支持从 24.10 保留软件包升级，所有已装应用都要重装

实际执行流程：

1. 备份：`sysupgrade -b` 配置包、`/etc/passwall`（名单）、已装包列表、Passwall 25.12 的 apk、签名公钥，全部放到数据分区 `/mnt/sata1-4`
2. 恢复出厂：`firstboot -y` 后重启，清空 overlay 与软件包，回到默认 24.10.8
3. 刷 25.12.6：必须用 `x86_64_efi/` 目录的 `istoreos-25.12.6-2026110611-x86-64-squashfs-combined-efi.img.gz`（MD5 `24d3ba41…f0ca`）；BIOS 版 `x86_64/` 镜像会被 sysupgrade 以「Flashing a non EFI image to EFI system」拒绝
4. 重装 Passwall 26.11.11：25.12 用 apk；加入 openwrt-passwall-build 的 key 与 `packages-25.12/x86_64` 三个 feed，再 `apk add luci-app-passwall luci-i18n-passwall-zh-cn`
5. 手工恢复 Passwall 配置与名单：`-f` 配置恢复未生效，需 `tar xzf` 还原 `/etc/config/passwall` 与 `/etc/passwall/rules`，再装 `xray-core`（官方源 26.10.21-r1）

踩到的坑：

- `sysupgrade -n -f <config>` 并没有把 24.10 配置还原到 25.12，装完仍是默认配置，需手工恢复
- apk 大包（xray-core 等）经 CERNET 镜像偶发截断，改用 SUSTech 镜像手动下载 apk + `apk add --allow-untrusted` 解决
- 25.12 默认自带 Samba4、ttyd、unetd、wsdd2；Docker/dockerman、易有云完整版、vlmcsd、ddnsto、naiveproxy、haproxy 等用户自装包被清空
- 数据分区挂载点从 `/mnt/data` 变为 `/mnt/sata1-4`；Docker 数据仍在 `/mnt/sata1-4/docker`
- 25.12 默认仍对 WAN 放行易有云 8897 与 unetd UDP 51819，建议按需关闭

## 十二、磁盘分区调整：系统 2G → 16G（2026-11-18 12:10–12:17）

目标：用户基本不装软件，希望系统（overlay）空间大一些。

| 分区 | 调整前 | 调整后 |
| --- | --- | --- |
| sda3 /overlay | 2 GiB（1.9G，可用 1.5G） | **16 GiB（15.7G，可用 15.6G）** |
| sda4 /mnt/data | 53.5G | 38.6G（可用 36.2G） |

做法（全程在线，无需 U 盘/重启进救援系统）：

1. 先停 Docker/易有云等服务，把数据分区打包（`/tmp/sda4-backup.tgz`，171 MB，含 Docker 与配置），并复制一份到 Mac
2. 卸载 sda4（先停 dpanel 容器、kill 残留 shim，避免 target busy）
3. `parted /dev/sda rm 4` 删除数据分区，释放 sda3 后面的空间
4. 交互式 `parted resizepart 3`（`---pretend-input-tty` 回答 Yes + 新结束扇区）在线扩容已挂载的 sda3；内核立即识别到 16 GiB
5. `resize2fs /dev/sda3` 在线扩容 ext4：`/overlay` 变为 15.7G
6. 重建 sda4（42.4G）→ `mkfs.ext4` → 挂载 → 解包恢复数据
7. 给 `/mnt/data` 增加 fstab 挂载项（UUID `a9416951…`），Docker 数据目录继续用 `/mnt/data/docker`
8. 重启验证：分区 16G/38.6G 均保留，Docker 自启，dpanel 恢复为 `<网关 LAN 地址>:8807`

验证：重启后 `/overlay` 15.7G、`/mnt/data` 38.6G；dpanel Up（LAN 200）；Passwall 出口正常（Google 204、GitHub 200、百度 200）；旧的 `dpanel-old` 容器已删除。
