# iStoreOS 使用指南

配套 [README](./README.md)。基线：x86_64、EFI 启动、单盘 iStoreOS 24.10.8；目标 25.12.6。命令在路由器 SSH（`ssh root@<路由器地址>`）执行，执行前先读完整节。

> 跨大版本升级和改分区都会让设备短暂断网。请确保你能物理接触设备（显示器/键盘或 U 盘启动盘），再开始。

## 1. 先备份

升级前至少准备三份东西，放到**另一台电脑**，不要只留在路由器上：

```sh
# 1) 系统配置包（/etc/config 等）
sysupgrade -b /tmp/config-backup-$(date +%Y%m%d).tar.gz

# 2) Passwall 配置与名单（26.11 起用户名单在 /etc/passwall/rules）
tar czf /tmp/passwall-etc.tar.gz /etc/config/passwall /etc/passwall

# 3) 已装包清单，升级后对照重装
apk list --installed > /tmp/apk-installed.txt 2>/dev/null || opkg list-installed > /tmp/packages.txt
```

在电脑上取回：

```sh
scp root@<路由器地址>:/tmp/config-backup-*.tar.gz .
scp root@<路由器地址>:/tmp/passwall-etc.tar.gz .
```

记录当前：LAN IP、WAN 获取方式、主节点、DNS、端口策略。备份含凭据与订阅，**只放本地**。

## 2. 升级 24.10 → 25.12

### 2.1 确认 EFI 与镜像

```sh
ls -d /sys/firmware/efi && echo EFI
```

EFI 机器必须用 `x86_64_efi/` 目录的 `*-combined-efi.img.gz`；`x86_64/` 的 BIOS 镜像会被 sysupgrade 拒绝（“non EFI image”），不要用 `-F` 硬刷。

下载后先在电脑上核对官方 MD5（[固件站](https://fw.koolcenter.com/iStoreOS/x86_64_efi/)页面上有），再传到路由器：

```sh
gzip -t istoreos-25.12.6-*-efi.img.gz
md5sum istoreos-25.12.6-*-efi.img.gz      # 与官网一致
```

### 2.2 清空旧系统（保留配置备份）

25.12 换包管理器，旧 opkg 包不能带过去；官方要求先恢复出厂：

```sh
firstboot -y -r     # 清空 overlay 并重启；重启后是默认 24.10.8
```

重启后确认：LAN 能访问、`/etc/config` 是默认配置、备份文件还在数据分区（数据分区不会被清）。

### 2.3 刷入 25.12

```sh
sysupgrade -n /tmp/istoreos-25.12.6-*-efi.img.gz
```

`-n` 表示不保存当前配置。等 2–4 分钟，设备会以默认 25.12.6 启动，LAN 仍是 `192.168.100.1`。

> 实测 `sysupgrade -n -f <config.tar.gz>` 的配置恢复**没有生效**，不要依赖它；刷完手工恢复更可靠。

### 2.4 恢复配置

先恢复网络和 Passwall，再按需恢复其它应用配置：

```sh
cd /tmp
scp <电脑>:/path/config-backup.tar.gz .
tar xzf config-backup.tar.gz -C / etc/config/network etc/config/firewall etc/config/dhcp
tar xzf config-backup.tar.gz -C / etc/config/passwall
tar xzf passwall-etc.tar.gz -C /          # /etc/passwall/rules
uci commit
/etc/init.d/network reload
```

其余 `/etc/config/*`（Samba、Docker、DDNS 等）**按需**恢复：先装对应包，再恢复该文件，避免把未安装服务的配置一起带进来。

## 3. 重装 Passwall（25.12 / apk）

25.12 用 apk；Passwall 本体与依赖来自 openwrt-passwall-build 源。

```sh
# 签名公钥
wget -O /etc/apk/keys/openwrt-passwall-build.pem \
  https://master.dl.sourceforge.net/project/openwrt-passwall-build/apk.pub

# 25.12 的软件源（release/arch 按 /etc/openwrt_release 修改）
for feed in passwall_luci passwall_packages passwall2; do
  echo "https://master.dl.sourceforge.net/project/openwrt-passwall-build/releases/packages-25.12/x86_64/$feed/packages.adb" \
    >> /etc/apk/repositories.d/customfeeds.list
done

apk update
apk add luci-app-passwall luci-i18n-passwall-zh-cn xray-core
```

说明：

- `xray-core` 需要单独装；Passwall 包不会自动带节点内核。
- 大包经镜像偶发截断（`unexpected end of file`）时，换镜像手动下载 apk，再 `apk add --allow-untrusted /path/xray-core.apk`。
- 恢复 `/etc/passwall/rules` 后要清运行时缓存，否则继续用旧名单：

```sh
rm -rf /tmp/etc/passwall_tmp/user_rules
/etc/init.d/passwall restart
```

详细的分流参数与名单维护见 [`../passwall/使用指南.md`](../passwall/使用指南.md)。

## 4. 调整磁盘（可选）

本次把系统分区 2 GiB 扩到 16 GiB，数据分区从 53.5G 重建为 38.6G。**这是不可逆操作**，没有完整数据副本不要做。

### 4.1 先看清布局

```sh
parted /dev/sda print
df -h /overlay /mnt/data
```

示例（本次）：

| 分区 | 起始扇区 | 结束扇区 | 用途 |
| --- | --- | --- | --- |
| sda1 | 512 | 262655 | EFI /boot |
| sda2 | 262656 | 786943 | /rom（squashfs） |
| sda3 | 786944 | 4981247 | /overlay（ext4） |
| sda4 | 4982784 | 117231374 | /mnt/data（ext4） |

### 4.2 备份并停服务

把数据分区完整打包到另一台机器（演示值 899 MB → 171 MB）：

```sh
tar czf /tmp/sda4-backup.tgz --exclude='*.img.gz' -C /mnt/data .
scp /tmp/sda4-backup.tgz <电脑>:/path/
```

停掉占用数据分区的服务，再卸载：

```sh
/etc/init.d/dockerd stop
docker stop $(docker ps -q) 2>/dev/null
/etc/init.d/linkease stop
/etc/init.d/samba4 stop
umount /mnt/data          # 如 busy，先确认没有进程占用
```

### 4.3 改分区表

```sh
parted -s /dev/sda rm 4
printf 'Yes\n34341375s\n' | parted ---pretend-input-tty /dev/sda resizepart 3
parted -s /dev/sda mkpart primary ext4 34342912s 117231374s
```

- `34341375s` 是“从 sda3 起始扇区 786944 起、16 GiB”算出的结束扇区；换盘请自己算。
- 已挂载的分区必须用交互式 `parted` 并回答 `Yes`；`parted -s` 会以 “partition is being used” 失败。
- 新 sda4 起点按 1 MiB 对齐（2048 扇区），结束扇区沿用原值。

### 4.4 扩文件系统、重建数据区

```sh
resize2fs /dev/sda3          # 在线扩容，/overlay 立即变大
mkfs.ext4 -F -L data /dev/sda4
mkdir -p /mnt/data
mount /dev/sda4 /mnt/data
tar xzf /tmp/sda4-backup.tgz -C /mnt/data
```

### 4.5 持久化挂载

`/mnt` 是 tmpfs，**不要在里面放软链接**。用 fstab 挂载：

```sh
UUID=$(blkid -s UUID -o value /dev/sda4)
uci add fstab mount
uci set fstab.@mount[-1].uuid="$UUID"
uci set fstab.@mount[-1].target='/mnt/data'
uci set fstab.@mount[-1].enabled='1'
uci commit fstab
```

重启后确认 `/mnt/data` 自动挂载、容量正确。

## 5. 恢复 Docker 与 dpanel

```sh
apk add dockerd docker docker-compose luci-app-dockerman containerd runc
```

检查 `/etc/config/dockerd` 的 `data_root` 指向 `/mnt/data/docker`；启动后容器会按 `--restart always` 自动回来：

```sh
/etc/init.d/dockerd enable
/etc/init.d/dockerd start
sleep 6
docker ps -a
```

dpanel 只绑 LAN 的方式（重建容器）：

```sh
docker run -d --name dpanel --restart always --network bridge \
  -p 192.168.100.1:8807:8080 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -v /mnt/data/Configs/DPanel:/dpanel \
  -v /mnt:/mnt \
  --env-file /tmp/dpanel.env dpanel/dpanel:lite
```

`/tmp/dpanel.env` 从旧容器导出，避免把环境变量写进命令历史：

```sh
docker inspect dpanel --format '{{range .Config.Env}}{{println .}}{{end}}' > /tmp/dpanel.env
chmod 600 /tmp/dpanel.env
```

## 6. 安全收口

25.12 默认对 WAN 放行易有云 8897 和 unetd UDP 51819；不用就关：

```sh
uci delete firewall.linkease
uci commit firewall
/etc/init.d/firewall reload

/etc/init.d/unetd stop
/etc/init.d/unetd disable

nft list chain inet fw4 input_wan | grep -E '8897|51819|1688'   # 应无输出
```

易有云保留局域网使用时，8897 仍可被 LAN 访问；只是不再对 WAN 放行。

## 8. 常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| sysupgrade 报 “non EFI image” | 用了 `x86_64/` 的 BIOS 镜像 | 换 `x86_64_efi/`，不要 `-F` |
| 升级后配置全默认 | `-f` 配置恢复未生效 | 手工解包 `/etc/config` 与 `/etc/passwall` |
| apk 安装报 “unexpected end of file” | 镜像下载截断 | 换镜像手动下载 apk，`apk add --allow-untrusted` |
| Passwall 启动报 `run: not found` | 没装 xray-core | `apk add xray-core` |
| `/overlay` 没变大 | 只改了分区表，没 `resize2fs` | `resize2fs /dev/sda3` |
| 重启后 `/mnt/data` 为空 | 软链接建在 tmpfs，或没写 fstab | 用 UUID 写 fstab 挂载 |
| Docker 看不到旧容器 | 数据目录路径不对或挂载没生效 | 确认 `docker info` 的 Root Dir 与 `/mnt/data` 挂载 |
| umount 报 target busy | 容器/服务还占着数据分区 | 停 dockerd、kill shim、停易有云后再卸 |

## 9. 回滚

- **系统**：重新刷回 24.10 的 EFI 镜像，再恢复升级前的 `config-backup`；软件包要按 24.10 的 opkg 重新装。
- **Passwall**：apk 降级到上一个版本，或恢复 `passwall-etc.tar.gz`。
- **磁盘**：分区一旦重建无法原地回退；只能把数据备份恢复到新布局。执行前必须有完整副本。
- **容器**：保留旧容器配置（`/mnt/data/docker/containers`）与镜像层，重建失败时可以回滚到旧数据目录。
