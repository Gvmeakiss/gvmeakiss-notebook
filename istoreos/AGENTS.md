# AGENTS.md · istoreos

给 AI 的执行说明。给人看的说明在 [`README.md`](./README.md) 与 [`使用指南.md`](./使用指南.md)。

这个项目的风险是**不可逆**：刷机、改分区、重装包都会让设备暂时或永久不可用。改之前先读「红线」。

## 执行协议

| 步 | 动作 | 命令 | 通过判据 |
| --- | --- | --- | --- |
| 1 | 改前基线 | `node --test istoreos/tests/*.test.mjs` | 退出码 0 |
| 2 | 改文档 / 脚本 | 只动 `*.md`、`scripts/verify.sh` | 数字、链接、结论与实测一致 |
| 3 | 复跑测试 | 同上 | 全部用例通过 |
| 4 | 查空白 | `git diff --check` | 干净 |
| 5 | 脱敏扫描 | 搜订阅 / 节点 / UUID / 密码 / MAC | 0 命中 |
| 6 | 链接检查 | `pwsh -NoProfile -File scripts/check-links.ps1` | 锚点与相对链接都可解析 |

**硬规则**

1. **公开版只写方法与通用值** —— 订阅、节点入口、UUID、密码、MAC、路由器备份一律不进仓库；截图与命令输出先脱敏。
2. **破坏性步骤必须带前置条件** —— 刷机、删分区、格式化、重装包，每一步都要写清备份与物理访问要求，不能只给命令。
3. **数字必须来自实测** —— 版本号、分区容量、可用空间、服务版本都要与当次验收一致；推测值写成「待验证」。
4. **不把“一次成功”写成“通用最优”** —— 端口、DNS、镜像源都随线路与版本变化；给出适用条件。
5. **静态检查 ≠ 设备已加载** —— 写完文档要说明「已验证 / 未验证」的边界，不能把测试通过当成设备可用。
6. **脚本只读优先** —— `scripts/verify.sh` 只做检查，不写配置、不重启服务；需要改动的命令放在文档里让人确认后执行。

## 文件 → 用途

## 常见失败怎么定位

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 「version」红 | 文档里的版本/容量与实测不一致 | 先核对设备，再改文档或恢复数字 |
| 「secret scan」红 | 写了真实 UUID、节点域名、MAC | 换成占位符或 `blkid` 命令 |
| 「script」红 | verify.sh 被写成了会改系统的脚本 | 把修改动作移回文档，脚本只读 |
| 链接检查红 | 相对链接目标不存在或锚点不一致 | 先改路径/标题，再复跑 |
| 升级后配置丢失 | 依赖 `sysupgrade -f` 或没备份 `/etc/passwall` | 按使用指南手工恢复 |

## 红线

- **不提交**：订阅地址、节点入口与真实 IP、UUID / 密码 / 私钥、MAC、完整路由器备份、浏览器书签。
- **不省略备份与物理访问提示**：本目录的刷机和分区步骤都可能导致设备离线，文档必须写明。
- **不为通过测试改结论**：测试守的是已验证事实；事实变了先补实测，再改文档与测试。
