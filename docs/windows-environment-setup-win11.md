# Windows 11 系统优化审计 · 实测记录

一台 Windows 11 机器**被认为已经优化过**，逐项复核后拿到的事实，以及过程中我判错的地方。

这不是一份教程，而是一份**审计记录** —— 每个结论都来自在这台机器上真实跑出来的回读结果，判错的也一并留下。与 [`windows-environment-setup.md`](./windows-environment-setup.md) 的关系是**互补**：那篇讲一台 Win10 非管理员机怎么从零配起来，这篇讲一台 Win11 管理员机上"优化"到底做没做成、以及怎么判断做没做成。

- **环境**：Windows 11 Pro (build 26300) · **管理员账户** · PowerShell 7.6.7 · 单块 NVMe、无电池小型台式机
- **审计方式**：**全程只读**（`reg query` / `sc query` / `Get-CimInstance` 回读），改动前先导出了 12 个注册表键的 `.reg` 快照、全部计划任务状态与电源方案
- **参照判据**：[`skills/win-ai-gaming-setup/`](../skills/win-ai-gaming-setup/SKILL.md) 的 `tune` 阶段清单与 `verify-env.ps1` 的存活检查

## 1. 起点与终点

**起点**：这台机器在几天前被一轮"参考旧机配置做优化"的处理过。表面症状是开始菜单里一个图标报错，用户的原话是"整理审阅一下这台电脑还有那些地方可以优化"。

**终点**：`tune` 清单 **41 项全部 PASS**；但更重要的是**改动清单比预期短得多** —— 真正该改的是 2 项真实损害 + 18 项被累积更新删掉的调优值 + 4 个开发环境缺口，而**另有 3 项被我误判成故障、实际本来就是对的**（见 §2）。

| 类别 | 数量 | 处置 |
|---|---|---|
| 必须修（真实功能/安全损害） | 2 | MMCSS 未加载、自动更新被注册表策略关闭 |
| 该修（tune 存活检查失败） | 18 | 含 4 个**整键/整子树被删**，需重建而非改值 |
| 开发环境缺口 | 4 | `python3` 死存根、git 长路径、3 条死 PATH、无 scoop（不改） |
| 可回收空间 | 13.4 GB 表观 | 传递优化缓存，实际净增 5.1 GB（见 §3 第 7 条） |
| 被误关的系统任务 | 42 | 恢复 7 个非遥测的；3 个确认**本就不该手动开** |
| **被我误判成故障（实际正常）** | **3** | **见 §2 —— 这三条比上面任何一条都值得记** |

## 2. 最反直觉的发现

> **"优化"最大的风险不是漏改，而是把正常行为当成故障去修，并且修得有据可依、看起来完全合理。**

这台机器上前一轮优化留下的痕迹，和我自己在审计中犯的错，**是同一个毛病的两种表现**：**把"状态不等于我预期的值"直接等同于"坏了"。**

### 2.1 前一轮优化真的弄坏的东西（有据）

| 形态 | 实例 |
|---|---|
| **做了但没生效** | tune 写了 MMCSS 的四个 `Tasks\Games` 值，但 MMCSS 驱动根本没加载 —— 注册表写得漂漂亮亮，全是死值（§3 第 1 条） |
| **越界改了不该改的** | 用注册表策略**关闭 Windows 自动更新**（`NoAutoUpdate=1`），而技能自己明文写着"不动更新策略"（§3 第 2 条） |
| **改了但会伤到自己的判定** | 把 `BingSearchEnabled` 写进一个**内核级写保护的键**，于是"写入失败"和"写入成功"在汇总里长得一样（§4 第 3 条） |
| **留下非法残留** | 开始菜单里留了一个 `*.lnk.bak-<时间戳>` 备份文件，扩展名不是 `.lnk`，Windows 不认 ⇒ 显示成"未知文件"报错图标。**这就是本次的入口症状** |

### 2.2 我自己在审计中误判的三项（同样有据，且我一开始很自信）

| 我当时的判定 | 真相 | 我错在哪 |
|---|---|---|
| 15 个快捷方式"图标文件缺失" | `IconLocation` 是 `,0`（**空路径** + 索引 0），那是 Windows 表示"沿用目标程序自带图标"的**正常写法** | 我没处理"空路径"这种合法形态，读了 `split(',')[0]` 就直接 `Test-Path` |
| 2 个计划任务"被重启回滚成禁用" | `DiskDiagnosticResolver` / `OOBEFodSetup` 是**一次性任务，运行成功后自我禁用是设计**（本次开机都跑过，`LastTaskResult=0x0`） | 我用"必须 Ready"这种单一标准去判所有任务 |
| 电源方案"最小处理器状态 80%"是需要优化的项 | 那是**出厂/厂商有意设的地板**，目的是响应手感。我降到 10% 后用户反馈**"响应变肉了"**，回退 80% 才恢复 | 我只看"它比高性能方案还激进"，没问"这个代价用户在意吗" |

**教训一句话**：这三项的共同点不是技术难度，而是**我在报 FAIL 之前没有问一句"这个值有没有可能本来就是对的？"**。三条都写进了 `SKILL.md` 的陷阱速查。

## 3. 问题总表（按危害排序）

| # | 问题 | 危害 | 修法 |
|---|---|---|---|
| 1 | **MMCSS 驱动没加载，整套 MMCSS 调优是死值** | 游戏线程优先级、网络限流全部无效；而注册表**看起来完全正确** | 配置项全对就别折腾：**重启**。引导期驱动运行中途起不来是预期行为；`sc start` 返回 1341 **不代表配置错** |
| 2 | **Windows 自动更新被注册表策略关闭** | 不再自动收到安全更新，长期扩大攻击面 | 删掉 `...\Policies\Microsoft\Windows\WindowsUpdate\AU` 的两个值（连同空壳父键），回到系统默认 |
| 3 | **18 项调优值被累积更新删掉，含 2 处整键/整子树消失** | 优化"看起来做过"，实际已失效 | 值缺失必须重建（`AppCaptureEnabled` 整键、`Tasks\Games` 整棵子树），不是"改成别的值" |
| 4 | **开始菜单图标报错** | 用户可见的功能异常 | 移出 `*.lnk.bak-<时间戳>` —— 扩展名不是 `.lnk`，Windows 不认 |
| 5 | **`python3` 是 0 字节 Store 存根** | 任何 `python3 xxx` 的脚本返回 exit 9009 直接失败 | 在真 Python 目录建 `python3.exe` 副本（用户 PATH 中该目录排在 `WindowsApps` 之前，天然优先命中） |
| 6 | **开发环境 3 条死 PATH + git 长路径未开** | 深层仓库撞 MAX_PATH；个别工具找错位置 | 建目录而非删条目（`npm -g` / `go install` / `dotnet tool` 都需要它们）；`git config --global core.longpaths true` |
| 7 | **传递优化缓存占 13.4 GB** | 占盘 | 官方 `Delete-DeliveryOptimizationCache`；**注意表观 13.4 GB 与实测净增 5.1 GB 的差额**（同期更新下载回收了空间），报账要报实测值 |
| 8 | **42 个系统计划任务被禁用** | 磁盘故障预警、.NET 预编译、更新编排全哑 | 恢复 7 个非遥测的；**3 个 `UpdateOrchestrator` 任务被拒绝启用是设计**（任务 XML `Enabled=false`、文件 ACL 对 Administrators 只读），不要硬来 |

## 4. Windows 11 管理员机专属结论

与 [`windows-environment-setup.md`](./windows-environment-setup.md)（Win10 **非管理员**）逐条互证。**结论：拿到管理员权限并没有解锁"脚本化改默认程序"这类能力，真正的差别在别处。**

### 4.1 管理员权限**没有**改变的

| 项 | Win10 非管理员 | Win11 管理员（本次） |
|---|---|---|
| 脚本设置默认程序 | 不可行（`UserChoice` 有 Deny + Hash 保护） | **仍然不可行**。`UserChoice` 的防护与提权无关，脚本能做的依旧只是"让程序出现在候选里" |
| 系统文件完整性 | — | `sfc /verifyonly` 报**未发现完整性冲突**（说明前一轮优化没破坏系统文件） |
| 服务是否被乱禁 | — | 只有 10 个被禁用，**全是 Windows 自身合理默认**（`RemoteRegistry`/`AppVClient`/`shpamsvc`/`tzautoupdate` 等）；**没有任何输入法/相机/手柄相关服务被禁** —— 技能最担心的那类破坏没有发生 |

### 4.2 管理员权限**新暴露**出来的坑

| 坑 | 实测 |
|---|---|
| **ACL 正常但写入被内核层拒绝** | `HKCU\...\CurrentVersion\Search` 的 ACL 明确给当前用户 `FullControl`、`Owner` 也是该用户、进程已提权，但 `reg add` / `New-ItemProperty` / `reg import` **全部**返回拒绝访问。**不是 ACL 问题**（同批其它键全成功，也无第三方安全软件介入的证据）。别夺所有权，改走**官方策略路径**（`DisableSearchBoxSuggestions` + `ConnectedSearchUseWeb`/`AllowCortana`） |
| **`reg import` 是部分写入** | 文件里含一个写不进去的键 ⇒ **exit 1**、已写的保留、**后面尚未处理的节全部跳过**。归因会被带偏成"N 个互不相关的失败"，真凶是中间那一个锁。**不要把可写性未知的键放在批量导入中间** |
| **引导期内核驱动只能靠重启** | 配置全对 + `sc start` 返回 1341 ⇒ 重启后直接 RUNNING。同一次开机内反复 `sc start` 是无效功 |
| **一次性计划任务跑完自我禁用** | `Disabled` 不等于"被回滚"。判据是"本次已跑且 `LastTaskResult=0x0`" |
| **受 ACL 保护的系统任务** | `UpdateOrchestrator` 的三个任务：任务 XML `<Enabled>false</Enabled>` 是**出厂默认**，文件 ACL 对 `BUILTIN\Administrators` 只给 `ReadAndExecute`。**管理员也启用不了，且不该启用** |
| **第三方杀软接管后 Defender 让位是正常** | Defender 实时保护显示 `False`，同时存在第三方杀软且其内核过滤驱动在跑、`SecurityCenter2` 里注册为启用。**不要把"Defender 关着"当成被优化工具搞坏的证据** |

## 5. 已确认健康 · 不需要动

> 审计的价值有一半在于**确认哪些不用改**。下面每一条都实测过，结论是"别动"。

| 项 | 实测结论 |
|---|---|
| 系统文件 | `sfc /verifyonly` 未发现完整性冲突 |
| SSD / TRIM | `DisableDeleteNotify=0`（TRIM 正常）、磁盘 Healthy |
| 蓝屏 | `C:\Windows\Minidump` **为空** —— 无蓝屏转储 |
| 显卡稳定性 | `LiveKernelReports` **为空**、**无 4101/4102 事件** —— 无 TDR/显卡挂起史 |
| 设备故障码 | 所有非 OK 项都是 `CM_PROB_PHANTOM`（Code 45，历史记录里已拔插的设备）。**拔过的设备留记录是正常现象，不需要复位** |
| 第三方"优化软件" | 未发现（无各类"优化大师/加速器"常驻） |
| 启动项 | 很克制（同步客户端、浏览器自启、安全中心、杀软托盘 + 一个 NAS 连接脚本） |
| UAC / 服务 | UAC 未关；未发现被禁用的关键服务 |
| 索引 / 预读服务 | 均 Running / Automatic |
| 待装更新 | Windows 更新查询 = 0 个待装 |
| 休眠 / 页面文件 | 8.7 GB + 3.6 GB。**按技能纪律不动**（关休眠会连带关掉快速启动，反而开机变慢；实测本次启动 26.1 秒） |
| 开机唯一新错误 | `DCOM 10010` ×2 —— 良性噪音（Shell 体验组件抢跑），与本机改动无关 |

**递延项**：`tzautoupdate`（自动时区更新）处于禁用。固定时区不出差不影响，出差前开回。有电池的机器上"最小处理器状态"才有续航含义，本机无电池，所以该项**只影响手感**。

## 6. 可复现命令

### 6.1 只读审计（不改任何东西）

```powershell
# MMCSS：注册表值对 ≠ 生效，必须看驱动状态
sc.exe query MMCSS                       # 期望 STATE: 4 RUNNING
sc.exe qc    MMCSS                       # 期望 START_TYPE: 2 AUTO_START

# 调优值存活（含"被累积更新删掉"的判定：缺失即 FAIL）
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Multimedia\SystemProfile"
reg query "HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Multimedia\SystemProfile\Tasks\Games"
reg query "HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\GameDVR"

# 更新策略是否被策略接管（键不存在 = 系统默认，不要只看某个值）
reg query "HKLM\SOFTWARE\Policies\Microsoft\Windows\WindowsUpdate" /s

# 电源：当前方案的关键项（注意十六进制）
powercfg /query SCHEME_CURRENT 54533251-82be-4824-96c1-47b60b740d00 893dee8e-2bef-41e0-89c6-b55d0929964c
```

### 6.2 "写入失败"要先分辨原因

```powershell
# 受内核级保护的键：ACL 看着是全权，写入仍被拒。别夺所有权，改走策略键。
reg add "HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Search" /v BingSearchEnabled /t REG_DWORD /d 0 /f
#   -> ERROR: Access is denied.

# 官方策略路径（实测可写入，且优先级高于用户作用域）
reg add "HKCU\Software\Policies\Microsoft\Windows\Explorer" /v DisableSearchBoxSuggestions /t REG_DWORD /d 1 /f
reg add "HKLM\SOFTWARE\Policies\Microsoft\Windows\Windows Search" /v ConnectedSearchUseWeb /t REG_DWORD /d 0 /f
```

### 6.3 计划的复查（打完累积更新后）

累积更新对这类设置是**删除值**而不是改成别的值，所以"值存不存在"才是判据：

```powershell
pwsh -File skills/win-ai-gaming-setup/scripts/verify-env.ps1
```

本机已实测到 `SystemResponsiveness`、整棵 `Tasks` 子树、`AppCaptureEnabled` 整键**一起消失**，与 `SKILL.md` 里那条"累积更新会悄悄重置系统优化"完全吻合。**⚠ 先排除 `New-Item -Force`**（同一个键写多个值时它只会留下最后一个，症状一模一样，见 `SKILL.md` 受控实验）。

## 7. 审计口径与判定标准

> 这一节是本文最值得复用的部分。**同一个事实，判定标准写窄一点就会得出相反结论。**

| 检查对象 | ❌ 会误判的写法 | ✅ 正确判据 |
|---|---|---|
| 快捷方式图标 | `IconLocation` 为空 ⇒ 报"图标缺失" | 空路径 + 索引是**正常默认**（沿用目标图标）；只对**非空**路径做 `Test-Path` |
| 一次性计划任务 | 状态必须是 `Ready` | `Ready` **或**（本次已跑 且 `LastTaskResult=0x0`）—— 自我禁用是设计 |
| 注册表调优值 | 值 ≠ 期望值 才报 FAIL | **值缺失也必须报 FAIL**（累积更新是"删值"；只看等不等于期望值，会把"被删了"误读成"本来就没设置"） |
| 内核驱动类调优 | 注册表值正确 ⇒ 视为生效 | 必须叠加 `sc query` 看到 `RUNNING`；否则全部为**死值** |
| 策略键 | 父键不存在才算"没被接管" | 看**是否携带阻止值** —— 系统会重建**空壳父键**，空壳不产生任何策略效果 |
| 受 ACL 保护的系统任务 | 启用失败 ⇒ 报"权限故障" | 先查任务 XML 的 `<Enabled>` 与文件 ACL —— **出厂即禁用 + 管理员只读**是设计，不是故障 |
| 第三方杀软共存 | Defender 实时保护 `False` ⇒ 报"被搞坏" | 查 `SecurityCenter2` 注册状态与杀软内核驱动是否在跑 —— **让位是正常设计** |
| 偏离默认的系统设置 | 只要比默认激进就列成"待优化" | 先问**这个代价用户在意吗** —— 可能是厂商有意为之（实测"最小处理器状态 80%"降下来后手感变肉） |

三条元纪律：

1. **先证明"真的坏了"，再动手** —— 报 FAIL 之前问一句"这个值有没有可能本来就是对的？"
2. **写入返回成功不是证据，回读才是；回读正常也不是证据，得知道它是否真的生效** —— MMCSS 就是"值全对、驱动没跑"
3. **"查不到"不等于"不存在"** —— `reg query` 对不存在的键返回 **exit 1**（不是 0）；把 `exit=0` 读成"键存在"会让人去追一个不存在的"实时回写者"。**先确认查询手段本身有效**
