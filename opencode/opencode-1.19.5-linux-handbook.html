新建项目、加载 Skill、布置长任务没有直接对应的单一快捷键；展开下面三项看原生终端做法。

01 新建项目：用 shell 函数少敲几行

OpenCode 没有“新建项目”这个 TUI 命令。项目就是启动目录；先建目录，再在目录里启动。Git 建议一并初始化，/undo 和 diff 都依赖它。

shell
mkdir -p ~/code/new-app
cd ~/code/new-app
git init -q
opencode

如果经常新建项目，把下面函数加进 ~/.bashrc 或 ~/.zshrc，重开终端后执行 ocnew ~/code/new-app：

~/.bashrc 或 ~/.zshrc
# 用法: ocnew ~/code/new-app
ocnew() {
  mkdir -p "$1" && cd "$1" && git init -q && opencode
}

已有项目则直接 opencode ~/code/existing-project，不需要先进目录。

02 加载 Skill：/skills，默认无键位

1.19.5 默认没有给 Skill 选择器绑定快捷键；在输入框输入 /skills 回车，选择技能后会填入 /技能名，再回车执行。

技能文件放在项目的 .opencode/skills/<name>/SKILL.md，或全局 ~/.config/opencode/skills/<name>/SKILL.md。没有可用技能时，列表会是空的。

如果每天都用，可以在 ~/.config/opencode/tui.json 里加一个无冲突的自定义键位：

~/.config/opencode/tui.json
{
  "$schema": "https://opencode.ai/tui.json",
  "keybinds": {
    "prompt_skills": "<leader>k"
  }
}

重开 OpenCode 后，按 Ctrl+X → K 直接打开 Skill 选择器。这里的 <leader> 仍是默认的 Ctrl+X。

03 布置长任务：原生终端的三层做法

① 先在会话内拆解。按 Tab 切到 plan 代理，或在 prompt 里明确说：先拆任务、列 todo、按阶段修改并验证。长任务不要一次性让它改完。

长任务 prompt 模板
这是一个多阶段任务。先用 plan 拆解并建立 todo；
按阶段实现，每阶段结束运行测试并汇报；
不要一次性重写，不要跳过验证。

② 保持原生终端在线。任务期间别按 Ctrl+Z，也别让笔记本休眠。使用 systemd 的 Linux 可以在另一个终端临时阻止休眠：

另一个终端 · 任务结束后 Ctrl+C
systemd-inhibit --what=idle:sleep \
  --why="OpenCode long task" sleep infinity

如果你的系统不是 systemd，或公司策略不允许，改用电源设置保持唤醒即可。原生终端不需要 tmux；新开标签页就能并行。

③ 真要关终端：用非交互模式把任务和日志放到后台。先确保权限不会弹交互确认，否则任务会卡住；敏感仓库不要为了省事直接加 --auto。

headless · 可断终端
nohup opencode run "按 docs/plan.md 分阶段完成重构" \
  > ~/oc-task.log 2>&1 &
tail -f ~/oc-task.log

任务结束后回到对应项目目录，用 opencode -c 查看最近会话。

02

First Contact

一次完整回合，只要五步

把“上下文、目标、约束、验证”说清楚，比堆很多提示词更有用。下面是日常最顺的工作流。

  1. 01

    进入项目目录再启动

    cd ~/code/my-app 后运行 opencode。也可以在启动时直接指定目录：opencode ~/code/my-app。

  2. 02

    第一次进项目，先 /init

    它会引导生成或更新 AGENTS.md，把项目约定、常用命令和禁区写进去，之后每轮都更省心。不是必须，但很值。

  3. 03

    用 @ 给文件，再把目标说死

    输入 @ 模糊找文件，支持行号：@src/auth.ts#20-45。先只读分析，再让它动手，出错概率更低。

  4. 04

    看工具卡和权限，而不是盲等

    工具调用会显示在对话里。需要确认时选 once / always / reject；长任务可用 todowrite 看进度。

  5. 05

    不满意就撤销，再开新会话

    /undo 会移除上一条用户消息、后续回复和文件改动（需 Git）。想换话题用 /new，不要拿 /clear 当清屏。

两段式 prompt · 先只读，再动手

第 1 轮 · 只读分析
只读检查 @src/auth.ts#20-45 和它的调用方。
找出 token 过期后仍继续请求的路径。

先给结论和最小修改方案，不要改文件。
如果需要搜索，用 grep / read。
第 2 轮 · 修改并验证
按刚才的方案修改，只动 src/auth.ts。

改完用 bash 运行 pnpm test -- auth，
把失败测试和相关 diff 一起给我。

换行：Shift+Enter，在 SSH 或部分终端里更稳的是 Ctrl+J。

03

Projects & Sessions

换项目：先退出，再 cd

OpenCode 1.19.5 没有一按就换仓库的“项目切换器”。一个前台进程绑定一个启动目录；/new 只换会话，不换目录。

01 / PROJECT

项目 = 你启动它的目录

在哪个项目目录运行 opencode，就在哪个项目上下文里工作。Git 仓库边界通常决定项目身份；换仓库、换目录，就重新启动一次。

opencode ~/code/another-project
02 / SESSION

会话 = 项目里的一段对话

同一项目可以有很多会话，各自保留消息、待办和文件快照。/new 新建、/sessions 切换，都不会改变当前项目目录。

/new · /sessions · Ctrl+X → L
现在项目 A~/code/a
→
先退出/exit
→
换目录cd ~/code/b
→
再启动opencode

A · 标准换项目

最清晰、最不容易把两个仓库的上下文混在一起。

# 在 TUI 内
/exit

# 回到 shell
cd ~/code/project-b
opencode

B · 启动时直达

从任意 shell（或另一个终端）直接打开目标目录。

# 不进入当前目录，直接开
opencode ~/code/project-b

# 先确认路径
pwd

C · 多项目并行

原生终端新开标签页/窗口即可；一个项目一个前台 TUI，装了 tmux 再考虑 tmux。

# 标签页 A
cd ~/code/api
opencode

# 标签页 B
cd ~/code/web
opencode
只是想回到上次对话？ 在对应项目目录执行 opencode -c；指定会话用 opencode -s <id>；想保留原会话再分叉，用 opencode -c --fork。
×
这些动作不会切换项目。
  • 在 ! 里 cd：只影响那条 shell 命令，不会改 OpenCode 的会话目录。
  • Ctrl+Z 后 cd 再 fg：只是把同一个进程挂起再恢复，工作目录没变。
  • /clear：它是 /new 的别名，会新建会话，不是清屏，也不是换项目。
  • 直接关终端：可能中断正在生成的回答。要离开请用 /exit。
会话管理命令 · 在 shell 里
opencode session list -n 10      # 最近 10 个会话
opencode -s <session-id>        # 进入指定会话
opencode -c                    # 继续当前项目最近会话
opencode export <session-id>    # 导出为 JSON
04

Tool Calling

工具不是命令，是模型的手

OpenCode 没有让你手敲的 opencode bash ... 工具子命令。内置工具由模型根据你的自然语言自动选择；你能控制的是上下文、权限，以及是否要它明确用某个工具。

@

给上下文

引用文件或行范围。例：@src/api.ts#12-40。

/

跑工作流

内置或自定义斜杠命令。例：/sessions、/review。

!

直接跑 shell

在空输入行首按，命令在本会话目录执行，输出进上下文。

→

自然语言

描述目标，让模型调用 read / grep / edit / bash 等工具。

readFILE

读文件 / 目录

按行范围读取，支持图片与 PDF 附件。

“读一下 @src/auth.ts，只看前 80 行。”
globFIND

按路径找文件

用通配符列出文件，默认尊重 .gitignore。

“找出所有 *.test.ts，按修改时间排序。”
grepSEARCH

搜文件内容

底层用 ripgrep，支持正则和 include 过滤。

“搜哪里调用了 createSession，不要改代码。”
bashSHELL

执行 shell 命令

跑测试、Git、构建；受 permission.bash 控制。

“用 bash 跑 pnpm test，只汇总失败项。”
editPATCH

精确替换

按 oldString 匹配修改现有文件，是主要改码方式。

“把这个函数改成提前返回，不要动其他文件。”
writeCREATE

新建 / 覆盖

新建文件或覆盖已有内容；同样受 edit 权限控制。

“新建 scripts/check.sh，内容按下面这段写。”
todowritePLAN

维护任务清单

多步骤任务时显示 pending / in_progress / completed。

“这个任务步骤多，先列 todo 再逐项做。”
taskAGENT

派给子代理

把独立调查交给 explore / general 等子代理，拿回结论。

“用 task 让 explore 调查登录链路，只返回结论。”
webfetchURL

抓取指定网页

读取文档、issue、API 页面，返回文本或 Markdown。

“用 webfetch 读这个 URL，摘出配置示例。”
websearchWEB

联网搜索

需特定 provider 或开启 Exa / Parallel 环境变量。

“搜索这个报错的最新官方说明，并附来源。”
skillSKILL

加载技能

把对应的 SKILL.md 和附带资源带进当前任务。

“用 office 技能处理这个表格。”
questionASK

在执行中问你

需要取舍时弹出选项，避免模型自行猜。

“不确定数据库用哪个时，先问我再动。”
i
工具调用默认不一定“每次弹窗”。

OpenCode 的默认权限偏宽松：多数工具可直接运行；外部目录和重复三次的同一调用（doom_loop）默认询问，.env 文件默认禁止读取。想更保守就显式配置。

给工具加一道闸

把权限写进项目根目录的 opencode.json。规则按“最后匹配者生效”，所以把 * 放前面，例外放后面。

once · 只这次 always · 本会话内匹配规则 reject · 拒绝

改完用 opencode debug config 看最终合并结果。想临时放开可启动 --auto，但它只跳过“询问”，不会绕过明确的 deny。

建议：在不受信任的仓库里不要用 --auto；edit: ask 会很吵，但适合第一次合作的项目。

opencode.json · 保守起点
{
  "$schema": "https://opencode.ai/config.json",
  "permission": {
    "edit": "ask",
    "webfetch": "ask",
    "bash": {
      "*": "ask",
      "git status*": "allow",
      "git diff*": "allow",
      "npm test*": "allow",
      "rm -rf *": "deny"
    }
  }
}
READ ONLY

只读排查 @src/server.ts。 先用 grep 找到调用链，再 read 相关文件。 不要 edit / write，也不要运行会改文件的命令。

grepread
CHANGE & VERIFY

只改 src/auth.ts。 改完用 bash 跑 pnpm test -- auth。 把失败测试和相关 diff 一起给我。

editbash
DELEGATE

用 task 启动一个 explore 子代理， 调查 session 过期逻辑。 只返回结论和文件位置，不要改代码。

taskexplore

点名工具只是提高命中率。真正干活的仍是模型；它可能根据上下文换工具。要硬性限制，用权限或只读 agent。工具细节可在 Ctrl+P 里搜 “tool details” 切换显示。

A 加一个自己的工具（.opencode/tools）

文件名就是工具名。下面这个文件会生成 project-paths 工具；放好后重开 OpenCode，在 prompt 里点名即可。

.opencode/tools/project-paths.ts
import { tool } from "@opencode-ai/plugin"

export default tool({
  description: "报告当前会话的目录和 Git worktree 路径",
  args: {},
  async execute(_args, context) {
    return "directory=" + context.directory +
      "\nworktree=" + context.worktree
  },
})

然后说：“用 project-paths 工具看看当前路径。” 同一文件导出多个工具时，名字会变成 文件名_导出名。自定义工具若与内置工具重名，会覆盖内置工具，尽量用独特名字。

B 接入 MCP 的外部工具

先运行引导式添加，或在 opencode.json 写 mcp。配置后，MCP 工具会像内置工具一样进入模型上下文。

shell
opencode mcp add
opencode mcp list
opencode mcp auth <server-name>

添加后可在 TUI 里用 /mcps 开关服务器。然后在 prompt 里按名字调用：“用 mcp_everything 工具算一下 3+4。” MCP 会额外占上下文，别一次启用太多。

C 把重复 prompt 做成斜杠命令

自定义命令不是工具，它只是预置的 prompt 模板。放到 .opencode/commands/，文件名就是命令名。

.opencode/commands/review.md
---
description: 只读审查当前改动
agent: plan
---

阅读下面的 diff：
!`git diff`

只报告高风险问题和缺失的测试，
不要改文件。

然后在 TUI 输入 /review。模板里的 !`命令` 会先执行 shell 并把输出注入 prompt；$ARGUMENTS 可接收参数。

05

Linux Comfort

Linux 上少踩几个坑

下面按原生 Linux 终端来写，不依赖 tmux。终端层的快捷键和 OpenCode 是两套系统；先把剪贴板、流控和编辑器处理好。

CLIPBOARD

复制粘贴

OpenCode 复制文本会优先用 Wayland 的 wl-copy，或 X11 的 xclip / xsel；图片粘贴还需要 wl-paste 或 xclip。

# 检查已有工具
command -v wl-copy xclip xsel

# Debian/Ubuntu 示例
sudo apt install wl-clipboard
# 或 X11
sudo apt install xclip
  • 应用内粘贴：Ctrl+V
  • 终端自己的粘贴：Ctrl+Shift+V
  • 终端选区复制：Ctrl+Shift+C
SIGNALS

卡住与挂起

终端“没反应”不一定是 OpenCode 崩了。Ctrl+S 会暂停终端输出，Ctrl+Q 恢复。

Ctrl+S  # 误触后画面冻结
Ctrl+Q  # 解除流控，恢复刷新

Ctrl+Z  # 挂起 OpenCode
fg      # 回到 OpenCode

挂起不是退出，也不会改变工作目录；别用它来换项目。

EDITOR & NATIVE TABS

长 prompt 与长任务

设置 $EDITOR 后，/editor 和导出会用它打开。长任务不需要 tmux：原生终端保持窗口在线，或者新开标签页做别的事。

# ~/.bashrc 或 ~/.zshrc
export EDITOR=nvim

# 在当前项目启动
opencode

如果机器上已经装了 tmux，可选：离开用 Ctrl+B 然后 D，回来用 tmux attach -t work。没装就不用管。

新项目先跑 /init，把约定写进 AGENTS.md。
让模型改文件前，先保持 Git 工作区干净。
重要改动先看 diff，再用 /undo 兜底。
不在不受信任仓库使用 --auto。

Troubleshooting

症状对照表

先定位是“OpenCode 行为”“终端行为”还是“项目/权限配置”，通常比乱按快捷键更快。

症状最可能的原因处理
按 Ctrl+C 后整个 TUI 没了输入框为空，触发退出绑定用 opencode -c 恢复；按 01 节末尾的可选配置把 app_exit 改掉
想停生成，结果退出了把 Ctrl+C 当取消键生成中用 Esc，看到 again to interrupt 再按一次
终端像冻住，按键无反应误触 Ctrl+S 流控按 Ctrl+Q；若无效再检查 Ctrl+Z 与 fg
复制出来是空的Linux 缺少剪贴板后端装 wl-clipboard 或 xclip；先用终端 Ctrl+Shift+C
怎么 cd 都还在原项目在 ! 或挂起后 cd，进程 cwd 没变/exit → cd → opencode；启动前用 pwd 确认
模型明明该用工具却不动权限为 deny、工具未启用，或提示太模糊查 opencode debug config；/mcps；明确说“用 bash 跑…”；重开加载新工具
/undo 没反应项目不是 Git 仓库，或没有可回滚的改动先 git init / 在 Git 项目里用；确认改动已被快照
opencode -c 进错对话它取当前项目最近一次顶层会话opencode session list -n 10 后 -s <id>
升级后快捷键全变了1.x 与 2.x 是不同版本线opencode --version 确认；不要在不看迁移说明时 opencode upgrade --major
!
一个容易忽略的排查顺序

先看输入框是否为空，再看当前目录，最后看权限和模型。大多数“OpenCode 坏了”其实是这三件事之一。
