# Shadowrocket 通用分流配置

面向订阅制节点和手动选线的 Shadowrocket 配置，适用于 iPhone、iPad 和 Mac。

这份配置不保存节点、不绑定机场，也不替用户决定地区。订阅负责提供节点，Shadowrocket 负责测速和切换，本配置只处理分流、DNS、局域网兼容与失效兜底。订阅增删节点后无需修改配置。

## 适用场景

- 节点来自一个或多个订阅，名称和数量经常变化；
- 使用前会先测速，再根据用途手动选择节点；
- 经常在家庭宽带、蜂窝网络、酒店和机场 Wi-Fi 之间切换；
- 希望国内服务直连，境外服务使用当前节点；
- 需要兼顾流式对话、视频播放、局域网设备和公共网络认证；
- 不希望为了简单分流安装证书、开启 HTTPS 解密或维护脚本。

## 工作方式

配置只使用三种策略：

- `DIRECT`：国内服务、局域网、Apple、Microsoft 和 PayPal 等直连；
- `PROXY`：AI、流媒体、社交、游戏平台和境外服务使用首页当前选中的节点；
- `REJECT`：拦截广告规则命中的请求。

`PROXY` 不是固定服务器，也不是自动策略组。首页切换节点后，所有代理流量随之切换，因此订阅更新不会破坏配置。

## 核心设计

### 配置与节点分离

许多完整配置会内置地区组、节点正则和自动测速。节点命名一旦改变，策略组可能为空、误分组或选中并不适合目标服务的出口。

本项目保留手动选线：测速用于排除失效和高延迟节点，最终选择由使用场景决定。这样既能使用频繁变化的订阅，也能在需要时固定美国、新加坡或台湾等出口。

### 明确的规则优先级

Shadowrocket 按顺序命中规则。配置从具体规则逐步走向大类和本地兜底：

1. 局域网与 Apple 网段直连；
2. 广告拦截；
3. AI 服务；
4. 流媒体；
5. 社交与通讯；
6. 支付与购物；
7. 游戏平台；
8. 开发与云服务；
9. Apple 服务直连；
10. 国内应用直连，抖音先于 TikTok；
11. China 直连、Global 代理；
12. `GEOIP,CN,DIRECT` 与 `FINAL,PROXY` 本地兜底。

具体服务放在大类规则之前，可以减少域名重叠造成的误判。China 先于 Global，优先保证国内访问路径；未被远程规则覆盖的请求最终仍由 GEOIP 和 FINAL 接管。

### DNS 以可用性为先

- 腾讯和阿里 DoH 作为主要解析器；
- `223.5.5.5` 与 `119.29.29.29` 作为普通 DNS 补充；
- 主解析失败时允许回退系统 DNS，避免公共网络认证阶段完全失联；
- 只劫持应用常见的 Google DNS，不全量接管 `:53`，减少对局域网发现和酒店认证页的干扰；
- 直连域名解析失败时允许经代理重试；
- Apple 与 iCloud 直连域名使用所在地系统 DNS，获得更合适的 CDN 结果。

### IPv4、IPv6 与局域网兼容

配置启用 IPv6，但仍优先 IPv4。TUN 排除 RFC 1918 私网、链路本地、组播、IPv6 ULA 和 IPv6 链路本地网段，避免打印机、AirPlay、Bonjour、路由器管理页和认证门户被送入代理隧道。

### 代理连接稳定性

`block-quic = all-proxy` 只阻断代理流量的 QUIC / HTTP3，使相关请求回退到 TCP。对 UDP / 443 质量不稳定的订阅节点，这种取舍通常比追求 HTTP3 更稳，尤其适合需要持续传输的流式会话。

它不会修复节点出口被目标网站拒绝、节点丢包或服务端故障。延迟测试合格但仍频繁出现 HTTP 403 或重连时，应更换节点。

### 远程规则失效仍可使用

规则通过 jsDelivr 获取。即使远程规则暂时无法更新，配置末尾仍保留：

```ini
GEOIP,CN,DIRECT
FINAL,PROXY
```

国内 IP 继续直连，其余流量继续使用当前节点，不会因为规则源不可达而失去基本分流能力。

## 与常见配置的区别

| 维度 | 常见做法 | 本项目 | 实际影响 |
|---|---|---|---|
| 节点管理 | 配置内建立大量地区组和自动测速组 | 只使用当前 `PROXY` 节点 | 不依赖订阅命名，节点更新后无需改配置 |
| 选线方式 | 延迟最低即自动选中 | 测速后按用途手动选择 | 避免低延迟但出口地区、解锁能力或信誉不合适 |
| 规则格式 | 混用不同客户端格式 | 使用 Shadowrocket 原生规则 | 减少解析差异和后续兼容风险 |
| 远程依赖 | 依赖在线规则决定全部流量 | 在线规则加 GEOIP / FINAL 本地兜底 | CDN 或上游异常时仍能联网 |
| DNS 劫持 | 全量接管 53 端口 | 只劫持 Google DNS | 更适合酒店、机场和局域网设备 |
| IPv6 | 关闭，或只配置 IPv4 私网 | 启用但不优先，并排除 IPv6 本地网段 | 兼顾双栈节点与本地网络 |
| HTTPS 处理 | 使用重写、脚本或 MITM | 不安装证书，不启用 HTTPS 解密 | 配置简单，避免证书信任和应用兼容问题 |
| 长连接 | 保持应用默认 QUIC | 代理流量回退 TCP | 牺牲部分 HTTP3 性能换取兼容性 |
| 支付流量 | 随代理出口变化 | PayPal 直连 | 减少共享代理 IP 引发的账户验证 |

## 使用方法

1. 在 Shadowrocket 首页添加或更新节点订阅；
2. 进入「配置」，导入 [`shadowrocket-optimized.conf`](./shadowrocket-optimized.conf)；
3. 将其设为当前配置，断开后重新连接；
4. 回到首页测速并选择节点；
5. 保持「全局路由」为「配置」。

节点选择建议：

- Codex、ChatGPT、Gemini 等服务优先选择实际可用的美国节点；
- 视频和日常娱乐可选择延迟更低的新加坡或台湾节点；
- 延迟只反映连接速度，不代表出口地区、IP 信誉或目标服务可用性。

若某个 App 因广告规则无法正常工作，可先删除或停用 `Advertising.list` 对应规则，确认是否为误拦截。

## 主要参数

| 参数 | 当前值 | 用途 |
|---|---|---|
| `dns-server` | 腾讯 / 阿里 DoH + 国内普通 DNS | 防污染并保留解析兜底 |
| `fallback-dns-server` | `system` | 公共网络与异常环境恢复解析 |
| `hijack-dns` | Google DNS | 阻止常见硬编码 DNS 绕过 |
| `dns-direct-fallback-proxy` | `true` | 直连解析失败后经代理重试 |
| `block-quic` | `all-proxy` | 代理流量从 QUIC 回退 TCP |
| `ipv6` / `prefer-ipv6` | `true` / `false` | 支持双栈但优先 IPv4 |
| `private-ip-answer` | `true` | 保留局域网和认证门户私网应答 |
| `udp-policy-not-supported-behaviour` | `REJECT` | 节点不支持 UDP 时拒绝旁路直连 |

## 已知取舍

- 本配置依赖手动选线，不提供自动故障切换；
- 系统 DNS 兜底优先保证可用性，不属于严格的零泄漏方案；
- 禁用代理 QUIC 会失去部分 HTTP3 的速度和弱网恢复优势；
- 广告规则可能误伤少数 App，需要按实际情况停用；
- `tun-excluded-routes` 包含 `100.64.0.0/10`。若使用 Tailscale，应删除该网段，避免与 Tailscale 地址冲突。
