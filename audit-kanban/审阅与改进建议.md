# 稽核工作看板审阅与改进建议

审阅日期：2026-09-07。对象：当前源码及演示数据。以不懂计算机技术的填报同事、汇总人和经理为使用对象。

建议继续保留纯前端、双击运行、Excel 文件流转的架构。下一轮优先解决填报出错、误操作和汇总效率，再补充经理周会视图。本轮为审阅，未修改应用功能。

## 已复现的问题

### P1：Excel 百分比可能被错误解释

- 位置：`excel.js` 的 `read()`，数值字段转换分支。
- 现象：普通数值 60 正确导入为 60%；Excel 原生百分比单元格 60%（底层数值 0.6，格式 0%）被拒绝；100%（底层数值 1，格式 0%）被接受为 1%。测试使用未完成记录，排除完成标记的 100% 强制展示。
- 原因：导入仅使用原始数值，没有结合单元格百分比格式判断。现有说明要求填 60，但不能充分防止同事按习惯填写百分比。
- 建议：支持普通数值 60、文本 60%、Excel 原生百分比单元格三种明确输入；仅在确认单元格采用百分比格式时乘以 100，不能把所有 0–1 数字都当作百分比。对不能转换成整数进度的输入继续逐行报错。
- 验收：普通数值 1 必须仍为 1%；原生 1% 为 1%、60% 为 60%、100% 为 100%；0% 正确；101% 拒绝；有错误整批不提交。

### P1：误关编辑窗口会丢失草稿

- 位置：`app.js` 的统一关闭事件、`openEditor()`；`index.html` 编辑对话框。
- 复现：新增工作，输入名称，按 Esc，重新新增，名称为空。没有未保存提示或草稿恢复。
- 建议：检测是否有实际修改，对 Esc、关闭、取消使用一致的处理；有修改时提供“继续填写／放弃修改”。可增加一份独立草稿，不能把未完成草稿混入正式台账。
- 验收：无修改直接退出；已修改不静默丢失；保存成功后清理草稿；恢复草稿仍需正式校验和保存。

## 使用流程改进

| 优先级 | 当前情况 | 建议改进 | 价值与边界 |
| --- | --- | --- | --- |
| P1 | Excel 模板放在“汇总同事进展”弹窗里，而“我的工作”会隐藏该入口 | 在“我的工作”提供“下载空白填写表”和“下载我的工作表”；保留同一编号更新提示 | 同事不用进入汇总流程寻找表格；空白表用于新工作，已有工作从个人表继续填 |
| P1 | 合并预览展开所有记录，变化项展开全部字段；合并完成只显示通用提示 | 分成“待选择变化／新增／相同跳过”，默认集中显示变化字段，完整内容可展开；展示最终新增、更新、保留、跳过数量 | 减少逐屏查找，保留逐条选版和未选默认保留规则 |
| P1 | 表格错误只在网页中显示行号和原因 | 提供可复制错误清单，后续增加错误清单下载；显示文件名、工作表、行、字段、原值及原因 | 同事能回到原 Excel 修正；继续整批校验通过后才能提交 |

| P2 | 删除确认后没有直接恢复入口 | 增加最近一次删除撤销，后续视需要增加回收站 | 周快照维持独立；撤销须经过正常存储写入及冲突检查 |
| P2 | 文件夹中同时有源码、脚本、JSON、说明和 Excel，普通使用者难以判断入口 | 分发包突出“打开看板”、中文快速说明、Excel 示例；维护资料单独归类 | 最近的格式疑问说明交付结构也需要简化 |

## 经理查看结构

建议沿用橙白主色和红绿蓝状态，调整信息优先级：

1. 首屏概览：五模块数量及状态分布、当前筛选范围、查看基准日。避免筛选后其他模块计数为 0 被误读成整个部门没有工作；保持“统计随筛选更新”，增加明确范围提示和一键重置即可。
2. 重点跟进：已逾期、今天到期、未来 7 天到期。后两项作为日期提醒，不改变现有三种业务状态。默认优先看未完成工作；完成项可折叠。
3. 本周变化：与上一周选定快照比较，列新增、转为完成、进度变化、交付日期调整。多版本快照明确选定基准，第一次没有基准则显示“暂无可比较周报”。记录缺席称为“当前台账未见”，不直接推断取消或完成。
4. 详细台账：保留列表／卡片和完整详情；增加“按逾期优先／交付日期／最近更新”排序入口、字号选择和会议打印样式。

不建议把各项主观百分比直接平均后命名为“部门完成率”。不同工作体量和填报口径不同；若需要统计完成率，应明确为当前范围“已完成事项数 ÷ 事项总数”，空范围不计算。

界面模式可以提供“个人填报／部门汇总／会议查看”，只是简化按钮，不表示拥有登录权限或真正的访问控制。保持目前无登录的使用约定。

## 维护与验收补强

- 当前 `config.js / core.js / excel.js / app.js` 的职责拆分足够清晰，继续使用，不必为界面优化引入 npm 构建或后端。
- 增加 Excel/WPS 实际编辑保存再导入验证，重点覆盖百分比格式、日期、下拉值和隐藏编号。
- 现有全量渲染和同步 Excel 解析在配置上限下可能卡顿；尚未做规模实测。先用接近日常数据规模测量，再决定分批渲染、搜索防抖和预览分页。
- 100 份全量快照和 5000 条记录只是配置上限，不代表浏览器配额保证。补充规模测试、快照容量提示及备份后清理引导；不要自动删除历史。
- Windows、Edge 和单位实际浏览器策略仍需要实机验收。不能将本机 Chrome 通过当作全部平台通过。
- 小修：`app.js` 有“周周报”重复字；历史周报未选中时应区分“请选择已有周报”与“还没有历史周报”。

## 本轮证据与实施顺序

本轮重新执行 19 组业务／Excel 自动测试，全部通过；另外用真实 XLSX 编码和应用自身导入函数复现百分比问题。使用隔离的离线 Chrome、file:// 页面复现 Esc 草稿丢失，未接触用户浏览器台账。两项新问题说明现有通过的测试未覆盖所有日常操作。
