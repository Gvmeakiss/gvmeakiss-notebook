# AGENTS.md · audit-kanban

给 AI 的执行说明。给人看的说明在 [`README.md`](./README.md)、[`使用说明.md`](./使用说明.md) 与 [`构建说明.md`](./构建说明.md)。

这是一个**纯前端离线演示应用**：没有构建步骤、没有服务端、数据只在当前浏览器的 localStorage。

## 执行协议

| 步 | 动作 | 命令 | 通过判据 |
| --- | --- | --- | --- |
| 1 | 改前跑基线 | `node --test tests/core.test.cjs` | 退出码 0 |
| 2 | 改代码 | 见「改哪里」 | 只动对应层，不跨层搬逻辑 |
| 3 | 复跑测试 | `node --test tests/core.test.cjs` | 全部通过 |
| 4 | 浏览器实测 | Chrome/Edge 打开 `index.html` | 见「手工验收清单」 |
| 5 | 查空白 | `git diff --check` | 干净 |
| 6 | 脱敏 | 搜真实公司名 / 人名 / 单据号 | 0 命中（演示数据必须是虚构的） |

**硬规则**

1. **运行不需要 Node** —— 双击 `index.html` 即可。Node 只用于跑测试。
2. **所有写入必须经过 `commit`** —— `app.js` 里的写入路径统一，绕过它会造成快照与陈旧页面保护失效。
3. **`storageKey` 不能随意改** —— 改 `config.js` 的 `storageKey` 等于切到另一份空台账，**不迁移旧数据**。
4. **字段 `key` 是数据身份** —— 已有数据后不要改名或删除；新增用唯一英文 key，避开 `__proto__` 这类保留名。
5. **改状态口径要四处同步** —— `core` 的 `status`、快照校验、测试、使用说明；已保存快照应尊重旧口径，必要时升级数据格式。
6. **`vendor/` 是第三方库** —— 只有 `xlsx.full.min.js` 与许可文件，改它就等于改上游，不要动。
7. **不要把演示版说成协作系统** —— localStorage 不是多人数据库，没有服务端锁；文案里不得出现"实时协作"。

## 改哪里

| 文件 | 放什么 | 改动注意 |
| --- | --- | --- |
| `config.js` | 模块、字段、状态、`storageKey` | 内网优先改这里；字段口径改动最安全 |
| `core.js` | 业务计算、状态判定、快照校验 | 改动必须同步测试 |
| `app.js` | UI、事件、localStorage、下载与恢复 | 所有持久化经 `commit` |
| `excel.js` | Excel 导入导出 | 与模板列顺序对齐 |
| `index.html` / `styles.css` | 结构与样式 | 不改判定逻辑 |
| `演示数据/` | 虚构演示数据与生成脚本 | 只放虚构内容 |

## 手工验收清单（浏览器内，每次改完必过）

1. 首次打开为空台账，不报错（看 Console）
2. 「我的工作」填一条 → 下载提交文件 → 汇总人能导入并看到差异
3. 「本周留档」生成快照 → 快照校验无异常
4. 导出 JSON 备份 → 清空 → 从备份完整恢复
5. 列表／卡片切换、详情、筛选都正常
6. 刷新页面后数据仍在（同一浏览器、同一路径）
