# 构建说明：稽核工作进度看板

本项目为纯静态离线应用。无构建步骤，应用运行不需要 Node、Python、npm 或网络。此文档同时面向使用者和负责局部修改的内网 AI。

## 1. 打开与使用

1. 将整个应用文件夹复制到本机固定位置，保留 `vendor` 目录和全部相对路径。
2. 使用 Chrome 或 Edge 打开 `index.html`。第一次使用是空台账。
3. 点击“我的工作”填写姓名，新增或更新工作，再点击“下载我的提交文件”。原编号由应用保留。Excel 模板放在“汇总同事进展”窗口。
4. 将提交文件交给汇总人。汇总人点击“汇总同事进展”，校验和预览后逐条选择要采用的内容。
5. 每周由汇总人点击“本周留档”（内部仍称快照）。定期在“备份与恢复”中下载全部工作备份（JSON）。

每个浏览器、用户配置和文件位置可能拥有不同的 localStorage。移动文件夹、换浏览器、清理缓存或迁移电脑前先导出 JSON。内网静态 HTTP 服务也可托管同一套文件，但**不会因此成为多人共享台账**；每人的浏览器存储仍然独立。

建议只开一个编辑页面。已实现陈旧页面写入保护，但 localStorage 不是多人数据库，不提供服务端锁或同时写入事务。不得把本方案宣传为实时协作系统。

### 当前界面组织

- 部门看板默认紧凑列表，支持卡片、全文详情、点击统计筛选；可在 CONFIG.ui.defaultView 设置默认形式。
- 我的工作按记住的姓名过滤，个人提交始终下载本人的全部当前记录，忽略其他筛选；“下载当前列表”只下载当前筛选结果。
- 姓名及列表／卡片偏好保存在 `audit-kanban.v1.preferences`，与原台账独立，不改变业务 JSON。它不是认证或权限功能，不能作为访问控制。
- “历史周报”对应 snapshots，“本周留档”生成快照；“备份与恢复”容纳完整 JSON 和恢复流程。底层格式及合并规则不变。
- 新增《使用说明.md》和《易用性与视觉优化记录.md》。技术文档不要求普通同事阅读。

## 2. 文件职责与架构

| 文件 | 职责 |
| --- | --- |
| `index.html` | 页面、弹窗和控件骨架；仅加载同目录本地资源，CSP 禁止网络连接 |
| `config.js` | CONFIG 唯一可调整入口：模块、字段、颜色、看板配置、上限及 Excel 列名 |
| `core.js` | 纯函数：日期、记录和备份校验、业务比较、合并、筛选统计、快照 |
| `excel.js` | SheetJS 适配：模板、Excel 编码和解码、列名映射、错误行报告 |
| `app.js` | UI、事件、localStorage、下载、预览流程和完整恢复；所有写入经过 commit |
| `styles.css` | 本地字体栈、布局、状态样式、响应式、弹窗 |
| `vendor/xlsx.full.min.js` | 固定版本 SheetJS CE 0.20.3，浏览器本地运行 |
| `vendor/LICENSE.sheetjs.txt`、`vendor/README.md` | 第三方许可、来源和校验和 |
| `kanban-prompt.md` | 原始需求，不修改 |
| `kanban-prompt.optimized.md` | 经用户确认并补全的执行需求基线 |
| `tests/core.test.cjs` | Node 内置测试运行器，验证业务与 Excel 数据边界 |
| `tests/browser.test.cjs` | Playwright 离线 Chrome 集成测试，使用独立临时浏览器环境 |
| `验收记录.md` | 实际验收结果和未实测范围 |

不使用 ES modules、fetch 加载本地 JSON、服务工作线程或构建器，避免 file:// 跨源限制。脚本依赖按 `CONFIG → SheetJS → core → excel → app` 顺序加载，并使用 defer 等待文档解析。

卡片以手填百分比显示进度条，并保留文字进展和下一步计划；不根据文字自动估算。原“工作跟踪”已退出主界面，历史文字仍可在备份和导出中保留。

数据流：

```text
手工表单 ─→ 记录校验 ──────────────────────────────┐
Excel／JSON → 解析／校验 → 预览差异 → 用户选择 → 候选台账 ─→ commit
                                                    │
                       校验 → 检查原始存储是否变化 → localStorage.setItem
                                                    │
                          成功：更新内存及页面   失败：保留旧数据＋待保存候选

当前台账 → 筛选 → 同一组记录的统计及卡片
当前完整台账 → 手动快照 → 独立记录副本＋冻结状态 → 只读历史查看
```

## 3. 数据格式与身份

localStorage 键为 `audit-kanban.v1`，保存一个 JSON 对象。格式如下，示例是结构说明，不会自动导入应用：

```json
{
  "schemaVersion": 1,
  "records": [
    {
      "id": "work-example-1",
      "module": "project",
      "name": "示例工作",
      "owner": "负责人",
      "progressPercent": 60,
      "progress": "现阶段进展",
      "dueDate": "2026-09-30",
      "nextPlan": "下一步计划",
      "completed": false,
      "updatedAt": "2026-09-07T01:00:00.000Z"
    }
  ],
  "snapshots": [
    {
      "id": "snapshot-example-1",
      "week": "2026-09-07",
      "savedAt": "2026-09-07T01:00:00.000Z",
      "asOfDate": "2026-09-07",
      "records": []
    }
  ]
}
```

快照 `records` 中每条记录具有与当前记录相同的字段，另加 `frozenStatus`，值为 `normal`、`overdue` 或 `completed`。JSON 下载额外添加 `exportedAt`。恢复时去掉该导出元数据，保留完整台账与快照。

- 记录和快照的 id 为安全随机编号。合法外部编号支持 1–100 位英文、数字、下划线、短横线，禁止用 Excel 行号代替。
- 当前记录编号全局唯一；每个快照内部记录编号唯一，跨快照重复合法。快照自身 id 唯一。
- `updatedAt`／`savedAt` 是 ISO UTC 毫秒时间，如 `2026-09-07T01:00:00.000Z`。用户日期是本地日历日期，避免 UTC 日期偏移。
- 普通 JSON 合并允许当前 records 的 id／updatedAt 留空，导入前生成；恢复文件要求其完整。Excel 同样允许新记录编号及更新时间为空。
- 当前备份只接受 schemaVersion 1。新增可选 progressPercent 字段，不改变已有记录身份；旧备份缺失时保留未知进度，不自动填零。未知顶层字段、未知记录字段、失效模块、非法日期、非法快照状态都会阻止导入，不会截断后静默保存。

## 4. 已确认的业务口径

项目进度 `progressPercent` 是 0–100 的手工整数，支持 null／缺失表示“未填写”；新增表单默认 0。填写 100% 不自动改变 completed，整项确认结束后勾选“是否完成”，表单会将进度设为 100 并锁定；取消完成可再调整。已完成的旧记录没有百分比时显示 100%。导入已完成但显式百分比不等于 100 的记录会报错。

日期计算以本机日历为准。已完成优先蓝色；其余日期早于今天为红色，否则绿色；当天到期是绿色。绿色仅表示“未逾期”，不代表实际工作一定正常。当前页每 30 秒及回到前台时检测是否跨日。

快照所属周必须选择周一；可选择以前的所属周，但状态仍然固定在**实际保存日**，不会伪造回溯日期。`asOfDate` 单独记录状态基准日。保存不受筛选影响，同周多版本按保存时间区分。历史视图禁止编辑工作，删除快照需要确认。

编号相同且业务内容一致时跳过（更新时间变化本身不算冲突）。业务比较包含模块和 CONFIG 字段。冲突采用“整条当前版／整条导入版”二选一，不做字段级拼接，不按电脑时间自动覆盖。

同名不同编号只提示核对，不自动合并。文件缺少某记录不代表删除；本机删除也不会自动传给其他副本。历史 Excel 可用于查看；如将其导入当前台账，会作为普通旧版本记录产生冲突，由汇总人决定，Excel 不会恢复周快照。

## 5. 修改 CONFIG 的方法

### 标签、颜色与展示

- 可以修改模块或字段的 `label`、状态的 `label/color/background`，以及 `appName`。
- 品牌视觉通过 CONFIG.theme 的 brand、brandSoft、brandText 配置；它与红绿蓝业务状态独立。CSS 按导航、统计、列表、卡片、表单分区，便于内网 AI 局部修改。
- JSON 以稳定 id/key 关联；Excel 使用当前标签作为列名、当前模块标签作为显示值。更改列标签后要重新分发模板，旧模板会报缺列；旧模块标签需人工改为新标签或稳定 id。
- `board.textFields` 决定卡片正文的字段及顺序；`showEmptyModules` 控制空模块；`defaultSort` 支持 `dueDate` 升序或 `updatedAt` 倒序。
- 改状态颜色不改变判定口径。要改变状态计算必须同步修改 core 的 `status`、快照校验、测试和说明；已保存快照仍应尊重旧口径，必要时升级数据格式。

### 新增模块

在 `CONFIG.modules` 中添加 `{ id: 'new-module', label: '新模块' }`。共用字段会自动出现在该模块，筛选、统计、Excel 映射同步生效。不要重命名已有模块 id；删除已有模块前必须迁移当前记录及全部历史快照。

### 新增或限定字段

例如仅为“风险议题开发”添加可选文字字段：

```js
{ key: 'riskMemo', label: '风险备注', type: 'textarea', maxLength: 4000, modules: ['risk-topic'] }
```

添加到 `CONFIG.fields` 后，表单、校验、Excel、JSON 比较会统一识别。要在卡片显示，再把 `riskMemo` 加到 `board.textFields`。模块专属字段不得在其他模块放入非空值。模块切换会只保存新模块适用字段；如需要保留旧模块专属历史，请先备份或保存快照。

支持 `text`、`textarea`、`date`、`boolean` 和 `number`；数值字段须配置 min、max，step=1 表示整数。可选文本旧记录缺失时按空展示；新增布尔字段必须为旧记录和快照填充布尔默认值，否则严格校验不会接受旧数据。新增必填字段也必须迁移旧数据。`requiredWhenOpen` 表示未完成时必填。

`name`、`owner`、`dueDate`、`completed`、`nextPlan`、`progressPercent` 是业务核心字段，保留原 key 和原适用范围。不要用 `id`、`module`、`updatedAt`、`frozenStatus` 或 JavaScript 保留属性作为新字段 key。新增字段 key 和 Excel 标签必须唯一。`legacy: true` 用于只保留历史数据、不在表单展示的字段；`importOptional: true` 允许旧 Excel 没有此列。不要移除 tracking 的历史兼容定义。

### 迁移边界

已有业务数据后，修改模块 id、字段 key、删除字段或改变字段类型均属迁移：先导出完整备份，编写显式旧版到新版转换（含所有快照），以副本验证后替换。不能只改 `schemaVersion` 或 `storageKey` 来“解决报错”。普通标签与样式调整无需改数据格式。

## 6. Excel 约定

编号与更新时间列在生成的 Excel 中默认隐藏，减少普通同事的填报负担，但并未删除；导入仍读取隐藏列并据此匹配。新建模板、个人提交、部门列表都遵循此规则。

只读取 CONFIG 指定的“工作台账”表，首行表头必须包含基础列；新增“项目进度（%）”和历史跟踪列可缺失以兼容旧模板；“填写说明”等其他表不导入。编号、模块、原有基础字段、更新时间列需要存在，可选内容可空。状态展示列可省略，存在时也不读取其值。空行忽略，其他行错误报告为原始工作表行号。

“是否完成”接受 `是/否`、`已完成/未完成`、`true/false`、布尔值或 `1/0`，空白按否。导出统一写是／否。Excel 原生日期支持 1900／1904 两种日期系统，正文保留原始空格与换行；编号、模块、日期、更新时间边界空格会规范化。

不执行公式；数据行任何公式均要求粘贴为值后导入。用户正文如 `=HYPERLINK(...)` 也以字符串单元格写出，不生成 `f`。导出不包含宏、链接对象或外部连接。

项目进度列填写整数 60 代表 60%，不要在 Excel 中填写 60%（底层为 0.6，会因非整数被拒绝）。空白保留为未知进度。新模板不包含旧跟踪列；导出的记录存在旧 tracking 文字时附加“工作跟踪（历史保留）”列，兼容旧表头“工作跟踪”。正常编辑保留旧记录的该字段。

模板和导出使用本地 SheetJS，是应用运行能力，不依赖开发机 Excel。Excel 库的来源与校验见 `vendor/README.md`。升级库后至少重跑 Excel 往返、公式文本、日期系统、重复编号及浏览器导入测试。

## 7. 存储异常、备份与恢复

启动使用独立临时键检查存储权限。写入调用以整个状态对象为单位；setItem 成功后更新页面。容量不足等错误保留第一次失败的候选，后续编辑锁定，避免新操作覆盖待保存数据。

- “下载未保存的工作”：导出失败操作的完整候选，用户保存后可另行恢复／合并。
- “下载原数据副本”：导出本页加载时的原文，损坏 JSON 也可保全。
- “重试保存”：适用于权限、容量等问题解除后；若其他页面已修改数据，则继续阻止陈旧覆盖。先导出候选，再刷新并合并。
- 启动遇到损坏存储，锁定编辑，避免空台账覆盖原文。通过完整恢复入口修复。

完整恢复先验证目标文件，再下载现有备份，然后重新选择刚下载的文件做逐字符核对。这样不把“触发下载”误当作“文件已保存”。校验通过后仍需最终确认，才替换全部记录和快照。目标文件错误或保存失败不会主动删除旧数据。

默认限制：导入 15 MB、当前台账及单个快照各 5000 条、100 份快照。浏览器实际存储配额通常会更早成为限制；这些配置是防误操作上限，不是容量保证。大量快照请导出备份后手动整理。非常大的工作簿在主线程解析会短暂阻塞页面，建议拆分导入；本版不包含后台解析线程和数据库存储。

## 8. 开发测试与交付

应用使用无需开发依赖；只有修改代码后复跑自动测试需要 Node。

```sh
node --test tests/core.test.cjs
```

浏览器测试需开发环境提供 Playwright 和 Chrome：

```sh
NODE_PATH=/path/to/node_modules node tests/browser.test.cjs
```

设置 `TEST_BROWSER=msedge` 可在安装了 Edge 的开发环境复跑；不要把 Chrome 的结果当作 Edge 已通过。测试通过 file://、离线网络模式、新建临时浏览器上下文运行，不修改用户浏览器配置或真实台账。输出位于 `tests/artifacts/`，其中截图仅为测试用虚构示例。

修改业务口径重点跑 core 测试；修改页面、存储、导入流程须跑 browser 测试。按《验收记录.md》检查目标内网浏览器及策略。打包只需保留上述静态资源和文档，不要加入真实业务数据、浏览器配置或下载的个人备份。
