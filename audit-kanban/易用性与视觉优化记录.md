# 易用性与视觉优化记录

## 审阅结论

原版功能完整，但把“新增、导入、导出、JSON、备份、快照、编号”等概念同时暴露给使用者；大卡片也不便于经理比较多项工作。对于业务专业、计算机操作经验有限的稽核同事，应按任务组织界面，保留业务口径，把维护细节放到次级入口。

应用原本就是纯前端：HTML、CSS、本地 JavaScript 和浏览器本机存储。文件分成几个模块是为了维护，不代表需要安装或配置服务器。这次保留纯前端和离线部署方式，主要优化工作流程和显示结构。

## 已执行的调整

| 审阅发现 | 已执行优化 |
| --- | --- |
| 同事要反复在全台账里找自己 | 新增“我的工作”，姓名记住一次即可，自动筛选本人事项；新建自动带入负责人 |
| 提交时要理解文件类型和导出范围 | “下载我的提交文件”直接生成个人 Excel，包含本人全部记录，不受搜索或分类影响 |
| 保存成功容易误以为已经提交 | 个人界面和下载结果明确提示：文件还需交给部门汇总同事，页面不会自动发送 |
| 经理难以横向比较大卡片 | 默认按模块的紧凑列表，把名称、负责人、进度、日期、状态及计划对齐；保留卡片切换与全文详情 |
| 找逾期项还要再开筛选 | 逾期统计前置，点击统计卡直接筛选 |
| 配色以灰绿为主，未体现某保险公司公开风格 | 改为橙色主操作、白色内容区、浅灰背景和深色文字；红绿蓝状态独立使用 |
| 百分比每次都要输入 | 增加 0/25/50/75/100 快捷按钮，仍可填任意合法整数 |
| “快照、JSON、编号”不直观 | 常用入口改为“历史周报”“本周留档”“汇总同事进展”“下载全部工作备份”；编号折叠，Excel 元数据列默认隐藏 |
| 删除与更新并列，容易误触 | 删除移到编辑窗口底部，仍需确认 |
| 用户说明和技术说明混杂 | 新增《使用说明.md》，维护架构和数据格式继续放在《构建说明.md》 |

## 品牌视觉依据和边界

2026-09-07 核对[某保险公司公开站点](https://www.pingan-property.com/)及其[页面样式](https://www.pingan-property.com/css/index.css)。公开 CSS 中标题、交互背景等使用 `#FF6300`，正文使用 `#666666`、`#222222`，并使用白色区域。

本应用以公开页面的 `#FF6300` 为品牌强调色，辅以自定义浅橙 `#FFF1E8`、深橙文字 `#A63E00` 和适合长时间阅读的中性色。按钮使用深色文字以提升橙底可读性。进度条统一为橙色，避免与业务状态混淆；未逾期／逾期／完成仍保留原有绿／红／蓝口径。

这属于**公开视觉风格适配**，不是完整内部 VI 合规结论。未取得内部字体、Logo 留白、色彩印刷规格等规范；没有仿制或嵌入官方 Logo。页面“稽”字是部门工具标记，不能作为公司对外商标使用。

## 保留的业务与技术边界

- 姓名是本机填写便利设置，不是登录身份和权限控制；任何使用者仍能打开本机部门看板。
- 不引入后端、注册账号或实时同步。各人保留自己的副本，专人汇总主台账。
- 不自动发送消息或邮件。“下载提交文件”只生成文件。
- 唯一编号、冲突人工选择、JSON 格式版本、完整备份校验、旧 tracking 字段兼容和历史状态冻结保留。
- 未对真实业务数据或用户浏览器存储执行迁移；原台账键及数据版本保持不变。新增姓名和显示偏好单独保存。
