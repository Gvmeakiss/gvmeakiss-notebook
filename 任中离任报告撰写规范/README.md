# 任中离任报告撰写规范

从拍照材料建档、模板与成熟稿交叉建模，到修改意见回对、完整修订稿和 Word 验收的一套工作方法。重点解决三类问题：**材料身份认错后如何完整修复、文字精炼如何守住原意、修改建议如何回对来源并落实到全文。**

本项目依据一次多轮底稿审校与来源纠错实践整理，只保存最终可复用规范、空白记录模板和通用指令。示例均为抽象示例，不对应具体审计项目；原始照片、OCR、底稿、业务数据和个案修改结果不随本项目入库。

## 适用范围

处理底稿的结构、层级、句式、措辞、模板适配及修订稿交付。用户限定“仅关注底稿撰写”时，保留既有事实与判断，不自行扩展为业务资料核验、制度有效性审查或责任认定。

经验主要来自任中稿审校。用于离任稿时，必须重新读取当次有效离任模板及其适用分支，不能照搬任中稿的目录、附件或结论。企业正式模板、用户本次指令和项目实际情况决定具体内容；本项目不另设统一章数、附件数、字数、页数或处罚门槛。

## 执行顺序

| 步骤 | 做什么 | 可以进入下一步的条件 |
| --- | --- | --- |
| 1 | 清点全部文件，锁定最新模板 T、成熟参考池 R、待改稿 D | 完整路径、稳定来源 ID、版本指纹和角色可对应；D 已排出规范池 |
| 2 | 批量提取文字，逐页核对原文与结构 | 原始提取与校核转录分层；页序、表格、脚注及疑点可定位 |
| 3 | 以 T 建格式规则，以 R 补表达方法 | 必须、条件、建议、示例和模板矛盾分别记录，规则有直接出处 |
| 4 | 对 D 逐项审阅 | 意见分为明确文字修正、可选精炼、条件化提示、原句保留 |
| 5 | 将建议回对 T、R 和 D 原件 | 主体、期间、数字、强度、否定、例外和结论边界没有被改写 |
| 6 | 按约定交付完整可编辑修订稿 | 已确定改法落实正文；未决项用批注或必要占位表达，不代填事实 |
| 7 | 验收约定格式；含 Word 时同步内容并渲染 | 全文及附属内容完整；Word 的脚注、批注、目录和逐页显示分别检查 |
| 8 | 更新入口和完成记录 | 检查对应最终输入版本；错误产物清理完成，仍未解决的项目单列 |

任何阶段发生材料角色更正，先执行[来源更正与错误产物清理](./规范/05_来源更正与错误产物清理.md)，再恢复相应步骤。角色更正后的复核不能只换文件名、姓名或条目数量。

## 本轮经验形成的关键判断

- 文件夹叫“参考”不代表其中每份都是参考；用户最新指定的用途控制角色。
- 最新模板控制格式，成熟稿提供表达先例；待改稿不能参与建立审查自己的规范。
- 不新增成效、承诺或赞誉，不等于删除原有政治要求、岗位目标、具体机制、工作结果和外部评价。
- 建议条目数、批注数和保留项数均不等于错误数；不预设必须找到多少问题。
- 对建议的回对必须直达原件，不能只引用自己生成的统一模型。
- 全篇修订完成与事实已经审定是两种状态；含未决批注或占位的文件仍是修订稿。
- 来源内容不变时复用正确 OCR；角色分析、规范、意见和完成证明需要按新依赖重新生成。

## 维护约定

当前目录只保留有效标准。规则修正时同步更新对应示例、记录模板和提示词，避免旧规则仍被执行；被替代版本通过 Git 历史追溯。提交前检查新增内容及链接，不把本地材料包、渲染缓存、临时脚本或个案完成证明混入规范。
