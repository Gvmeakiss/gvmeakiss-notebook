# 修改意见与回对表

复制到本地使用；原句、直接摘录和项目数据不提交到本规范仓库。每条意见应有可定位来源，不靠总览句替代逐条依据。

## 1. 本轮输入

| 字段 | 填写 |
| --- | --- |
| 当前待改稿 ID/内容版本/角色版本 | 待填 |
| 模板及成熟参考 ID/版本 | 待填 |
| 审阅范围和交付要求 | 待填 |
| 当前意见、完整稿及批注版本 | 待填 |
| 本次回对的输入指纹或版本记录 | 待填 |

## 2. 逐项审阅记录

每项复制以下记录块，避免表格过宽而省略依据。

| 字段 | 填写 |
| --- | --- |
| 条目 ID 与主题 | 待填 |
| D 位置：来源 ID、逻辑页、印刷页、区域或段落 | 待填 |
| 原句及必要上下文（本地填） | 待填 |
| 识读是否已确认，是否先排除 OCR 假问题 | 待填 |
| 问题说明 | 待填 |
| 处置性质 | 明确文字修正 / 可选精炼 / 条件化提示 / 原句保留 |
| 建议文字或保留理由 | 待填 |
| 用户要求、直接 T/R 位置及必要摘录；纯文字问题可直接据 D（本地填） | 待填 |
| 规则性质与适用条件 | 待填 |
| 保护字段：主体、动作、期间、数字、状态、程度、否定及例外 | 待填 |
| 回对结论：采用、降级、条件化或撤回 | 待填 |
| 全文落实位置与批注 ID | 待填 |
| 对模型、提示词及其他文件的同步修改 | 待填 |

OCR 识读订正单独登记，不作为原稿文字错误。可选项采纳后仍属可选；原句保留不等于事实已核实。

## 4. 交叉回对

| 对应关系 | 结果及本次实际检查范围 |
| --- | --- |
| D 原件→意见：是否遗漏原内容或误认 OCR | 待填 |
| T/R 原件→意见：是否误把示例或建议当成硬要求 | 待填 |
| 意见→原件：改法是否新增或删减判断 | 待填 |
| 总览→逐条意见：处置性质是否一致 | 待填 |
| 替换段落→全文：文字及适用条件是否一致 | 待填 |
| 批注→正文：是否发生未声明的代选 | 待填 |
| 模型→最终改法：规则纠错是否同步 | 待填 |
| 独立审阅→最终版本：后续变化是否补核 | 待填 |

## 5. 交付说明

分别填写实际审阅条目数、明确文字修正数、可选项数、条件项数和保留项数。写明完整稿覆盖范围、当前文件入口、已做的文档验收及剩余占位/识读/条件事项。不要将“完成回对”写成“业务事实全部确认”。
