# AI 接手约定

先读 [README](./README.md)，再按任务读取相应规范。以下约定适用于本项目及其复用过程。

1. 先确认本次任务范围及材料角色。来源 ID 保持稳定，T/R/D 为可变角色；使用完整路径或精确 ID 映射，禁止相似文件名的子串替换。
2. 用户限定撰写审校时，只处理文字、结构、模板适配和交付。发现实质口径不明，列条件化提示，不自行转为事实核验任务，不新增责任判断。
3. 最新模板决定格式，真实成熟原件提供表达方法。待改稿、历史错误建议、AI 改写稿不得充当规范来源。模板示例、条件分支和建议不得升级为硬要求。
4. 原件、原始 OCR、校核转录、规则、修改意见和修订全文分层保存。已有同版本校核记录时先检索文本，遇到具体疑点才回查图像。
5. 改写保护主体、角色、动作强度、期间、状态、数字、阈值、否定词、重大程度、例外及归属。不能只查名称和数字就宣称原意不变。
6. 原有政治要求、岗位目标、标准句、具体措施、机制、结果和外部评价不按敏感词表机械删除。精炼标明可选；不得主动扩写经营效益、赞誉、保证或承诺。
7. 每条建议直接回对本次 T/R/D 来源。建议有错时同时修订规范、替换段落、全文、批注和入口；不得只修复最后一个文件。
8. 材料角色被更正时，执行[依赖重建与清理](./规范/05_来源更正与错误产物清理.md)。保留原件与正确原始提取，撤销错误对象的派生分析及完成证明。用户要求删除错误结果时，按精确清单清理并验证，不能仅改名后继续作为有效稿。
9. 需要完整修订稿时，覆盖原件可见全文及附属结构，交付可编辑文字。明确改法落实正文；条件项保留原意并批注。必要占位、识读疑点和正式结论严格区分，不编造附件正文。
10. Word 与文本、原生脚注及批注分别验证；最终版渲染后逐页检查。文件存在、可打开或 ZIP 结构正常都不足以证明交付完成。
11. 完成记录绑定当前输入和最终输出版本。独立审阅后发生变化，补核受影响内容；未决项不得写成已核实。不得复用上一对象的条目数、页数或完成证明。
12. 本目录仅提交通用规则、空模板和抽象示例。项目原图、OCR、底稿、个案数据、内部路径及渲染结果留在本地；仓库权限不改变本目录约定。

更新规范后，复核 README 导航、模板、提示词和相互链接。不要为一次性底稿修订自动安装 Skill、改变全局字体设置或新建外部服务。
