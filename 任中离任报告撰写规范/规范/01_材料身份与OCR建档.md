# 材料身份与 OCR 建档

先确定材料是什么、这次拿它做什么，再识别和建模。目录名、文件名、修改时间都不能单独决定材料效力。

## 1. 来源身份和任务角色分开

为每份来源设置稳定 ID，例如 `S001`。文件移动、改名或由参考改为待改稿时保持 ID；内容变化另记版本与 SHA-256。任务角色另行登记：T 为本次有效模板，R 为成熟表达参考，D 为本次待改稿。无关、停用或身份尚未明确的材料单列。

| 必记字段 | 用途 |
| --- | --- |
| 来源 ID、内容版本、完整路径、SHA-256 | 锁定具体文件；识别移动及重复，不依赖简称 |
| 本轮角色、角色修订记录、用户指定依据 | 说明用途；角色版本与内容版本分别管理 |
| 图片序号、逻辑页 ID、画面区域、印刷页码 | 定位一图多页、封面、无印刷页码及跨页续文 |
| 原始提取位置、校核转录位置、处理状态 | 区分机器识别和人工核对 |
| 内容疑点、结构疑点、所影响规则或段落 | 支持定向回查和依赖失效处理 |

先审阅全部目录结构，再对有效材料逐页处理。相似名称必须用完整路径映射，不能让“材料A”替换误命中“材料A（补充）”。若仍不清楚谁是目标，可以继续清点和识读；依赖身份的建模与改稿保持待定。

## 2. 统计口径分别保留

照片数、去重后文件数、画面分区数、印刷页数、逻辑页数和 OCR 记录数是不同指标。一张照片可能同时包含两页；封面没有印刷页码，但仍需逻辑页记录。

按自然页序排序，记录左右页或多栏阅读顺序、跨图续句和脚注归属。相同 SHA-256 的文件移动不增加来源总数；视觉相似不能当成字节一致。重复来源可以共用内容记录，但保留各来源路径和用途关系。

## 3. 原图、机器层、校核层和分析层分离

```text
本地审阅项目/
├── 来源清单与角色记录
├── 原始OCR/             # TXT、识别行、坐标；保留机器实际输出
├── 校核转录/            # 逐页原文、结构、疑点、校核状态
├── 模板与表达模型/      # 规则、直接出处、适用条件
├── 修改意见与回对/
├── 修订全文/            # 当前有效 Word 与文本
└── 工作文件/            # 指纹、处理记录、渲染验收；不作为业务正文
```

原件通常留在用户原位置，以清单引用。校核发现 OCR 漏字时修改校核转录，不回写机器原始输出；角色更正优先更新独立元数据，不重写正确识别行。OCR 错字属于识读问题，不能计为待改稿写作错误。

## 4. 工具用于提取，逐页阅读用于确认

有可靠文字层的 PDF 先提取文本及位置；照片与扫描件优先使用现有本地 OCR。macOS 可使用支持中文的 Vision OCR，其他环境选用可用的中文识别工具。工具不可用时可视觉转录，不必为了完成审校安装整套服务。材料向外部服务上传另受任务授权约束，不能由“使用 OCR”自行推定。

原始提取宜记录引擎、语言、参数、运行版本及来源指纹。识别置信度只表示识别器判断，不能证明文字、表格归属或语义正确。

首次有效版本须覆盖全部页面。重点核对名称、数字、日期、文号、单位、比较符号、否定词、重大程度、例外、表格行列及跨页关系。后续先读索引与校核文本，有疑点再定向看原图；新一轮对话或文件移动不是全量重做 OCR 的理由。

## 5. 模板照片先还原有效净文

模板截图可能同时出现删除线、新增文字、高亮、右侧批注、编辑器按钮及扫描水印。分别记录正文净文、修订痕迹和批注的适用范围，不能把同一段的新旧句同时当成现行要求。

颜色或位置不能单独证明某条文字已生效。无法判断是示例、批注建议还是正式替换时，保留分歧并标记待确认；不根据成熟稿替模板消除矛盾。

## 6. 疑点要具体，确认程度不要混写

- 识读：哪页哪行哪个字符不清；用 `20??` 或明确的“末位待辨”标记，不从邻近日期补字。
- 结构：哪个表格单元格、脚注或跨页句归属不明；保留上下文，不凭排版位置硬拼。
- 语义：同一词可能表达不同主体或动作；转交条件化提示，不由 OCR 解决。
- 来源：角色或版本不确定；暂不进入规范池。

记录“已由原图确认”“推断”“待核实”及对应位置。校核文字读清，不代表业务事实已核实；稿中出现某个数值，也不代表本次已重新验证其计算。
