# 梅林与 Mac / iPhone 使用指南

本指南配套 [梅林项目说明](./README.md) 和 [Shadowrocket 使用指南](../shadowrocket/使用指南.md)。界面以 fancyss 3.5.30 为核对基线，其他版本先确认对应字段。

## 1. 先备份，再修改

1. 在家庭网络中打开自己的路由器管理页，进入科学上网插件。
2. 在“附加功能”导出“新版本 JSON 配置”，存到本地私人目录。它含节点与订阅凭据，不能提交 GitHub、发群或贴到工单。
3. 单独记下主节点、运行模式、DNS、访问控制和黑白名单，方便最小范围恢复。
4. 在 Shadowrocket 中另存当前配置。梅林 JSON 与 Shadowrocket `.conf` 格式不同，不能相互导入。

本仓库的通用名单不含个人例外；完整备份恢复也可能覆盖账号、节点和其他设置。常规更新应只改目标字段。

## 2. 合并通用域名名单

进入“黑白名单”：

- [direct-domains.txt](./direct-domains.txt) 合并到“域名白名单”。
- [proxy-domains.txt](./proxy-domains.txt) 合并到“域名黑名单”。
- 一行一个域名，不加 `https://`、路径、端口、`DOMAIN-SUFFIX,` 或 Shadowrocket 策略名称。
- 先保留现有个人条目，再增加本次通用条目，去掉完全重复的行。不要用公开文件整体替换个人名单。
- 检查同一域名或上下级后缀是否同时进入黑白名单；明确业务策略后只保留需要的方向，不依赖冲突优先级猜测。

这里的域名名单按插件支持的后缀匹配工作。客户端的 `DOMAIN` 精确规则、USER-AGENT 或逐行优先级不能直接复制成完全等价的路由器行为。

私人 API、个人 DDNS、内网服务请仅在本地维护。金融 App 不增加专属规则；关闭 Shadowrocket 不会同时关闭路由器代理，需要无客户端 VPN 时先关闭客户端，如需确认全部直出可使用大陆蜂窝网络另行验证。

## 3. 生成全部美国节点入口绕过

### 准备

需要 Node.js 20 或更新版本，不需要安装 npm 依赖。在仓库根目录执行；以下备份路径是占位符，要替换成刚导出的真实本地路径。备份仅在本地读取，DNS 查询只涉及待解析的节点入口域名。

```sh
node merlin/scripts/generate-us-bypass.mjs --help
node merlin/scripts/generate-us-bypass.mjs --backup "/path/to/Fancyss_conf_backup.json" --dry-run
```

默认按名称包含“美国”筛选，不做 IP 地理定位。若你的订阅用其他命名，先核对节点再使用 `--match`；不要为了凑数量任意扩大匹配范围。

需要指定 DNS 时可重复传入 `--resolver`，例如：

```sh
node merlin/scripts/generate-us-bypass.mjs --backup "/path/to/Fancyss_conf_backup.json" --resolver 223.5.5.5 --resolver 119.29.29.29 --dry-run
```

默认使用系统 DNS，不把家庭网关固定写入脚本。多个解析器的地址不同，不保证它们没有被当前网络劫持或转发；结果仍需结合入口配置判断。

**客户端虚拟 DNS 注意事项：**Shadowrocket 等客户端开启时，系统 DNS 可能把实际节点域名解析成 `198.18.0.0/15` 内的 Fake-IP，甚至返回对应的 IPv4-mapped AAAA。它们不是节点真实入口。工具会拒绝这类地址以及明显的本地/私网入口并停止输出；可先尝试上方显式 DNS 预演，若仍返回虚拟地址，应在方便时关闭客户端虚拟 DNS 所在连接，再重新核验。不要直接把错误地址加入白名单，也不要仅凭改了 DNS 参数就认为没有被接管。

### 生成本地文件

确认预演无未解析节点后，选择一个新的输出目录。正式生成须沿用预演成功的 `--match` 与 `--resolver` 参数；下例对应上方两个显式 DNS 的预演，不要预演成功后又意外切回系统 Fake-IP：

```sh
node merlin/scripts/generate-us-bypass.mjs --backup "/path/to/Fancyss_conf_backup.json" --resolver 223.5.5.5 --resolver 119.29.29.29 --output private-output/us-bypass-current
```

输出内容只在本地使用：

- `merlin-direct-domains.txt`：备份中的域名白名单，加上所有匹配节点的实际入口域名。
- `merlin-direct-ips.txt`：备份中的 IPv4 白名单，加上解析出的唯一 IPv4 `/32`。
- `us-node-endpoints.json`：入口与地址映射、核验结果；虽不含认证凭据，仍包含个人网络信息，不公开。

输出不是可导入 fancyss 的整机 JSON。工具不连接管理后台、不修改设备、不更新订阅，也不会自动定时维护。`--dry-run` 不写文件，终端仅显示统计与警告。输出文件权限为 600，新建目录权限为 700；已有同名输出时拒绝覆盖，每次生成请换一个新的本地子目录。

### 检查与应用

1. 核对命中节点数与订阅中美国节点的数量，检查是否遗漏别名节点；若 Mac / iPhone 使用不同或更新的订阅，应分别核对入口集合。
2. 确认使用的是节点的 `server`，不是 Reality/TLS 伪装域名、SNI 或 `openai.com` 等目标网站。
3. 一个入口被多个节点共享是正常情况；IP 数不必等于节点数。
4. 本工具保守接受 IPv4 单地址或 `/32` 白名单。原名单包含其他 CIDR 时会报错，不会悄悄缩窄或扩大它；请单独核验这些旧网段，不要为让工具通过而盲目删除。
5. 任何匹配节点没有 IPv4、备份格式错误或没有命中节点时，停止本次更新。AAAA 仅作观察，不写入 IPv4 白名单；先检查该节点是否仅使用 IPv6 以及路由器 IPv6 路径。
6. 将生成的两份名单与**路由器此刻的现有名单**合并；备份导出后若你又改过名单，不能用过期生成文件覆盖。
7. 分别填入域名白名单与 IP/CIDR 白名单，保存并应用；等待插件重启和检测完成，不在启动中重复点击保存或刷新。
8. 再导出一个本地完整备份，比对只有预期字段变化。继续使用香港主节点，不需要为入口绕过切换梅林主节点。

精确 IP 白名单覆盖当前解析快照，入口换 IP 后要重新生成。域名白名单不能保证补足由客户端 DoH 解析得到的新 IP；订阅新增/改名节点后也必须复核。不要加入整个云厂商 CIDR 来“永久解决”。

## 4. 其余路由参数

核对 [参数基线](./README.md#参数基线)。对于本次已优化环境，应保持现有订阅、节点认证、香港主节点与 DNS 组合；仅核对目标参数：

- 大陆白名单模式，chinadns-ng 智能判断。
- 访问控制的默认 TCP 端口为 `all`，让所有 TCP 端口接受相同目的地分流；若已有单设备 ACL，要检查它是否覆盖默认项，不应一并删除。
- UDP 代理关闭，海外 QUIC 屏蔽开启。
- IPv6 代理关闭；过滤代理 AAAA、保留直连 AAAA。

IPv6 的旁路与 IPv4 分流不是同一套规则。未经实测不要改成全开或全关 IPv6；客户端 DoH、IPv6-only 节点和不同网络需要分别排查。

## 5. 三种使用场景

| 场景 | Shadowrocket | 路由器与出口 |
| --- | --- | --- |
| 在家日常浏览国内、日本及其他海外网页 | 关闭 | 国内直连，需代理的海外流量经梅林香港节点；不按网页语言强制换地区 |
| 在家使用 GPT 等需要其他出口的服务 | 开启，选适用节点，“全局路由”选“配置” | 所有命中 PROXY 的请求都随客户端节点；美国节点入口由梅林直连绕过，避免再次套香港代理 |
| 外出大陆手机热点或蜂窝网络 | 开启，选可用节点，“全局路由”选“配置” | 客户端独立分流；无需回连家中梅林或固定家庭 DNS |

Mac 与 iPhone 可使用同一份 [conf](../shadowrocket/shadowrocket-optimized.conf)，但各自导入、选中配置和节点。家里的路由器设置不会自动同步到手机客户端。

客户端开启后不是“仅 GPT 使用美国，其余海外仍走香港”。如果需要 Viu 等地区内容，必须选择适合该服务的出口；服务可用性还与账户和节点质量有关。

## 6. 应用后验收

建议先确认路由器单独工作，再开启客户端；避免同时改 DNS、节点、路由和广告规则后无法定位原因。

1. 路由器：国内与国外状态检测通过，仍选中预期香港节点，管理页和 NAS 可达。
2. Mac：新 conf 为正在使用的配置，“全局路由”为“配置”，远程规则集显示全部加载。公开配置有 43 个远程引用。
3. 客户端规则测试：`chatgpt.com → PROXY`、`kimi.com → DIRECT`；再验证微信、抖音、知乎、番茄和常用办公/NAS 功能。
4. 实际访问 ChatGPT、GitHub 与国内站点。robots.txt 或首页 HTTP 200 仅证明基础连接，不代表登录、完整对话或流式/语音功能正常。
5. iPhone 在家与外出热点/蜂窝分别验收；包括锁屏后重连、从 Wi-Fi 切换蜂窝、文件上传及实际长对话。
6. 如需确认没有双重代理，结合路由器实际规则/连接记录观察客户端到节点的入口连接。只看网站显示的出口 IP 或一次 TCP 延迟，不能证明完整路径。

## 7. 常见问题与恢复

| 现象 | 先检查 |
| --- | --- |
| 国内 App 卡顿 | 客户端是否全局“代理”；请求是否命中 REJECT/PROXY；广告误伤、DNS、App 自身网络逐项排查 |
| 路由器单独正常，开启客户端异常 | 节点入口是否全部绕过、入口是否换 IP；客户端节点是否可用，是否有订阅差异 |
| 打开 SR 后其他海外内容地区变化 | PROXY 统一使用客户端当前节点，是预期行为 |
| 新节点不在绕过名单 | 重新导出最新备份，检查筛选命名，重新解析和合并 |
| 无 IPv4、Fake-IP 或 DNS 查询失败 | 停止覆盖；核对入口、客户端虚拟 DNS、指定 DNS 和 IPv6-only 情况，不用旧地址假装核验成功 |
| 手机外出失败但在家正常 | 核对手机独立节点连接、客户端 DNS 与大陆移动网络可达性，不能依赖家庭路由器的中转或 DNS |

恢复优先只还原本次修改的名单/端口并保存应用。确需完整恢复时，在“附加功能 → 恢复 fancyss 配置”选择本地修改前备份，理解它可能覆盖订阅、节点与其他设置；版本应匹配。不要执行“清空配置”。

Shadowrocket 可重新选择或导入自己的旧配置；公开文件不含本地私人例外，更新时要合并它们。保留备份，切勿为排错关闭认证、证书校验或暴露路由器后台。
