# 截图文字/数字高保真修改（字形克隆法）

## 适用场景

用户要求**修改图片内容**，而不是去操作背后的系统：

- "把这张 SAP 截图里的净价 9.17 改成 10"
- "把报表截图里的金额改一下"
- "P 掉截图里的日期/编号"

> ⚠️ **容易踩的坑**：用户说"修改图片中…"时，不要误判成"登录系统改数据"。
> AI 无法远程操控用户本机的桌面客户端（SAP GUI、ERP 客户端等）。
> 看到"图片中""截图里"字样，按改图理解；有疑问先确认。

## 核心方法：字形克隆（Glyph Cloning）

**为什么不用字体重绘**：跨平台字体渲染必然有差异，字小的时候尤其明显，一眼假。

**字形克隆**：截图里通常已经有你需要的字符（数字 0-9 在金额、编号、日期里几乎必然出现）。
从**同行同字号**的已有文本中克隆字形，拼成新内容 —— 像素级一致，无痕。

判据：目标文字与候选源的**垂直像素范围**（如 `y 388~397`）完全一致，即为同字号同渲染。

## 四步流程

```
locate.py  →  analyze.py  →  edit.py  →  verify.py
 定位坐标      测边界/步进     克隆替换      差分+回读
```

### 准备

```bash
pip install pyobjc-framework-Vision pyobjc-framework-Quartz pillow
```

> 用到 macOS Vision 做 OCR，故脚本为 **macOS 专用**。
> 微信/QQ 等容器目录（`~/Library/Containers/...`）有沙箱限制，Python 读不了，
> 先把图 `cp` 到工作区再处理。

### 第 1 步：定位（locate.py）

```bash
python3 locate.py shot.png                      # 列出全部文本
python3 locate.py shot.png --cn                 # 中文界面必须加 --cn
python3 locate.py shot.png --y0 360 --y1 385    # 只看列标题行
```

**找字形源**（关键一步，决定最终质量）：

```bash
python3 locate.py shot.png --find-glyphs 108         # 哪些位置有 1/0/8
python3 locate.py shot.png --cn --find-glyphs 单总价  # 中文字形源
```

优先选**与目标同一行**的源（y 值接近），同行通常同字号同渲染。

### 第 2 步：分析（analyze.py）

OCR 文本框常把相邻字段合并，不能直接覆盖。用列投影切出逐字符边界：

```bash
python3 analyze.py shot.png --x0 840 --x1 900 --y0 380 --y1 402
python3 analyze.py shot.png --x0 840 --x1 900 --y0 380 --y1 402 --dump   # 打印字符画
python3 analyze.py shot.png --x0 78 --x1 140 --y0 253 --y1 272 --light   # 反白区
python3 analyze.py shot.png --x0 155 --x1 215 --y0 363 --y1 380 --per-char
```

输出：字符块边界、**字符步进 pitch**、文字垂直范围、背景色、是否点阵字。

**两个高频坑**：

1. **切不开** —— 只统计"非背景像素"会被浅灰网格线（204/229/249）干扰，每列都有计数。
   脚本已改为只统计深色文字像素（RGB 和 < 400），网格线自动排除。
2. **整块连成一片** —— 扫描范围含进了边框。缩小 `--x0/--x1` 避开边框重试
   （例：反白标签区扫 `--x0 78` 切不开，`--x0 80 --x1 136` 就正常切成 4 个字）。

### 第 3 步：替换（edit.py，JSON 配置驱动）

```bash
python3 edit.py shot.png --config edits.json --out result.png
python3 edit.py shot.png --config edits.json --dry-run   # 先看要做什么
python3 edit.py --show-example                            # 打印配置示例
```

配置结构（完整示例见 `scripts/edits.example.json`）：

```jsonc
{
  "output": "edited.png",
  "edits": [
    {
      "name": "行项目净价 9.17 -> 10",
      "x": 776,              // 待改区域左起点（不是墨迹起点，是字段左内侧）
      "bottom": 397,         // 文字底部 y
      "old_len": 4,          // 原字符数（决定擦除宽度，新值更短时也按原长擦）
      "new": "10",           // 新文本
      "pitch": 8,            // 字符步进（analyze.py 测得）
      "bg": [234, 237, 240], // 背景色（analyze.py 测得）
      "glyph_y": [386, 400], // 字形源 y 范围（含抗锯齿余量）
      "glyphs": {
        "1": {"type": "clone", "x": 210, "width": 8},
        "0": {"type": "clone", "x": 218, "width": 8}
      }
    }
  ]
}
```

字形来源三种，按优先级选：

| type | 用途 | 说明 |
|---|---|---|
| `clone` | 图中已有的字 | **首选**。同行同字号，像素级一致 |
| `clone_light` | 反白高亮区的字 | 深色背景+浅色文字（如选中的标签页），形状一致只是颜色反了，提取浅色像素即可 |
| `render` | 图中没有的字 | 最后手段，字体渲染 |

### 第 4 步：验证（verify.py）

```bash
python3 verify.py orig.png edited.png \
    --safe "相邻字段:905,915,365,380" \
    --safe "网格线:760,920,404,408" \
    --expect-new 1080 --expect-new "总金额" \
    --expect-gone 990.83 \
    --compare compare.png --region 840,905,380,402
```

必看三条：

- **差异区域**：应一一对应预期改动，夹带意外区域就是误伤了
- **安全区**：指定"不该动"的区域，差异必须为 0
- **OCR 回读**：新值出现、旧值消失

## 修改中文标题的特殊处理

改中文比改数字难得多：字库大，图中往往**没有**你要的字。

### 字形源优先级

1. **同行同字号的中文字**（最佳，完全一致）
2. **反白高亮标签中的字**（次佳）—— SAP 的选中标签页是深色背景 + 浅色文字。
   字形形状完全一致，只是颜色反了：提取**浅色像素**（亮度 > 170）即得字形。
   *实例：从深色高亮的"项目总览"里提取"总"字。*
3. **字体渲染**（最后手段，用于图中确实不存在的字）

### OCR 必须显式启用中文

Vision 默认不识别中文，会把中文识别成乱码（`ІГ`、`FmEХ`、`卧项目`）。必须：

```python
req.setRecognitionLanguages_(["zh-Hans", "en-US"])
```

**识别结果可反查修改质量**：如果改完后 OCR 能以高置信度（>0.9）识别出新的中文词，
说明字形清晰没糊。这比像素差异指标可靠得多。

### 先判断是否为点阵字

用 `analyze.py` 的灰阶分布判断（或 `--dump` 看字符画）：

- **中间灰阶 / 核心 < 0.35** → 二值点阵字，无抗锯齿，笔画 **1px**
- 否则 → 带抗锯齿的矢量渲染

点阵字（SAP GUI 中文即是）渲染时必须匹配 1px 笔画。

### 渲染参数的正确指标：墨迹量，不是差异像素

**不要用"差异像素数"作唯一指标** —— 小字号汉字，不同字体间天然就有 20~30% 差异像素，
这个数没有判别力。

**用每字墨迹像素数**（`edit.py` 会打印）：

```
原图平均每字墨迹 48  →  渲染结果落在 45~60/字 即为合适
```

墨迹量接近 = 笔画粗细接近 = 视觉风格一致。**这比位置精确更重要。**

### 复杂字不要做细化

"额"（15 画）这类复杂字在 11px 下用细化算法（Zhang-Suen）会把结构压成一团糊。

> **规则**：笔画数 > 10 的字，宁可保留 2px 笔画（结构清晰），
> 也不要细化到 1px（结构消失）。简单字可以细化，复杂字不行。

### 实测可用参数（macOS 渲染 Windows ERP 中文点阵）

```
字体:     /System/Library/Fonts/Hiragino Sans GB.ttc  (index 0)
字号:     13
二值阈值: 128
超采样:   4x（渲染后 LANCZOS 降采样）
细化:     否
→ 墨迹约 53/字，与原图 48/字 接近，字高 12px 一致
```

ERP/SAP 中文字体为**无衬线黑体类**（不是宋体）。
macOS 上 Hiragino Sans GB 最接近，STHeiti Light 次之，**Songti SC（宋体）最差，不要用**。

## 已知环境参数（SAP GUI for Windows 750 实测）

| 项 | 值 |
|---|---|
| 半角数字 | 等宽，**步进 8px**，字高 10px |
| 全角中文 | 等宽，**步进 12px**，字高 12px |
| 行项目区背景 | `(234, 237, 240)` |
| 列标题行背景 | `(229, 229, 229)` |
| 抬头区背景 | 标签处 `(255,255,255)`，数值处 `(236,236,236)` |
| 网格线 | 浅灰三档：204 / 229 / 249 |
| 中文渲染 | 二值点阵，1px 笔画，无抗锯齿 |

## 判断清单

- [ ] **字段名和数值都要改** —— 用户说"改成 单价/总金额"，列标题（字段名）和数值是两回事，只改数值不完整
- [ ] **自洽性** —— 同一金额若在抬头和行项目都出现，一起改，否则单据前后矛盾
- [ ] **对齐** —— 新值比原值短时，剩余部分要用背景色擦干净（用 `old_len` 控制擦除宽度）
- [ ] **越界** —— 擦除宽度不要超过字段右边界，否则吃掉相邻列
- [ ] **字形源** —— 优先同行同字号；垂直像素范围必须一致
- [ ] **中文字形源** —— 按"同行中文 → 反白标签 → 字体渲染"三级找；渲染看墨迹量而非差异数
- [ ] **步进别混用** —— 全角 12px、半角 8px
- [ ] **脱敏** —— 见下节，公开前必查
