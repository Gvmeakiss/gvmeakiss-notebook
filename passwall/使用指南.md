# Passwall 使用指南

适用：[README](./README.md) 中的方案。基线为 iStoreOS 24.10.8 + `luci-app-passwall` 26.8.12；其他版本先核对字段名与页面位置，不要直接套命令。

本指南覆盖：备份、合并名单、改参数、更新规则、验收、排错与回滚。所有命令在路由器 SSH（`ssh root@<路由器地址>`）中执行；LuCI 页面路径以本机版本为准。

## 1. 先备份

改任何东西之前，同时备份「配置」和「名单文件」：

```sh
STAMP=$(date +%Y%m%d-%H%M%S)
tar czf /root/passwall-$STAMP.tgz \
  /etc/config/passwall \
  /etc/config/passwall_server \
  /usr/share/passwall/rules/direct_host \
  /usr/share/passwall/rules/proxy_host
ls -l /root/passwall-$STAMP.tgz
```

再取回本地一份（在 Mac / 电脑上执行）：

```sh
scp root@<路由器地址>:/root/passwall-<时间戳>.tgz .
```

备份含订阅与节点凭据，**只放本地**，不要提交、不要发群。

单独记下当前主节点、`tcp_redir_ports`、DNS 三项，方便最小范围恢复。

## 2. 合并名单

Passwall 的自定义名单就是两个纯文本文件：

| 文件 | 用途 |
| --- | --- |
| `/usr/share/passwall/rules/direct_host` | 直连域名 |
| `/usr/share/passwall/rules/proxy_host` | 代理域名 |

格式：一行一个域名，大小写不敏感，子域名自动匹配；`#` 开头的行是注释。

合并顺序是「底表 + 增量 + 个人已有条目」：

1. 把 [`../merlin/direct-domains.txt`](../merlin/direct-domains.txt)（119 条）与 [`direct-additions.txt`](./direct-additions.txt)（25 条）并入 `direct_host`。
2. 把 [`../merlin/proxy-domains.txt`](../merlin/proxy-domains.txt)（49 条）与 [`proxy-additions.txt`](./proxy-additions.txt)（17 条）并入 `proxy_host`。
3. 保留设备上已有的个人条目，只做去重，**不要用公开名单整体覆盖**。

先把公开名单传到路由器 `/root/`（在仓库根目录的电脑上执行）：

```sh
scp merlin/direct-domains.txt merlin/proxy-domains.txt \
    passwall/direct-additions.txt passwall/proxy-additions.txt \
    root@<路由器地址>:/root/
```

再去重合并（保留注释行，域名统一小写，重复只留第一次出现的）：

```sh
merge() {
  awk '/^[[:space:]]*#/ {print; next}
       NF {d=tolower($0); if (!seen[d]++) print d}' "$@"
}
merge /usr/share/passwall/rules/direct_host /root/direct-domains.txt /root/direct-additions.txt > /tmp/direct_host.new
merge /usr/share/passwall/rules/proxy_host  /root/proxy-domains.txt  /root/proxy-additions.txt  > /tmp/proxy_host.new
```

合并后至少检查两件事（`ash` 不支持进程替换，先落文件再比）：

```sh
# 1) 同一条目是否同时进了两边
sort -u /tmp/direct_host.new > /tmp/d.txt
sort -u /tmp/proxy_host.new  > /tmp/p.txt
grep -Fxf /tmp/p.txt /tmp/d.txt

# 2) 行数与预期是否一致（144 / 66）
grep -cE '^[a-z0-9]' /tmp/direct_host.new /tmp/proxy_host.new
```

父子域冲突（如 `apple.com` 与 `apple-relay.apple.com`）不会出现在上面的同名检查里，需要人工看一遍；直连优先，代理侧那条应删除而不是叠加。确认无误后再写回：

```sh
cp /tmp/direct_host.new /usr/share/passwall/rules/direct_host
cp /tmp/proxy_host.new  /usr/share/passwall/rules/proxy_host
```

## 3. 修改参数

页面位置：LuCI → 服务 → Passwall →「主界面 / 模式 / DNS」。也可以直接用 UCI（改完必须 `uci commit`）：

```sh
# 国内 DNS 不再跟随上游路由器
uci set passwall.@global[0].direct_dns='223.5.5.5'
uci set passwall.@global[0].direct_dns_mode='udp'

# 核对项（没有把握就不要改）
uci get passwall.@global[0].dns_shunt                 # chinadns-ng
uci get passwall.@global[0].chinadns_ng_default_tag   # none
uci get passwall.@global[0].filter_proxy_ipv6         # 1
uci get passwall.@global[0].dns_redirect              # 1
uci get passwall.@global_forwarding[0].udp_proxy_drop_ports  # 443
uci get passwall.@global_forwarding[0].ipv6_tproxy    # 0
uci get passwall.@global_forwarding[0].tcp_redir_ports        # 默认常用端口

uci commit passwall
```

**不要**把 `tcp_redir_ports` 改成 `1:65535`：先看 [README 的端口说明](./README.md#tcp-端口不要照抄-all)。确实需要时，先用 `tcping -p <端口> <节点域名>` 验证节点放行。

## 4. 更新规则库

LuCI 的规则页有「更新」按钮；命令行等价于：

```sh
lua /usr/share/passwall/rule_update.lua log
```

注意：**不要**写成 `lua /usr/share/passwall/rule_update.lua log all`。脚本只认 `gfwlist,chnroute,chnroute6,chnlist,geoip,geosite` 这些词，`all` 匹配不到任何一项，会直接以退出码 0 结束而不更新任何文件；想更新全部，就按 UCI 里的开关（默认全开）不带第二参数运行。

升级完成后核对文件时间与大小：

```sh
ls -l /usr/share/passwall/rules/chnlist /usr/share/passwall/rules/chnroute \
      /usr/share/passwall/rules/chnroute6 /usr/share/passwall/rules/gfwlist
```

自动更新由 cron 负责（每周日 04:00）：

```sh
crontab -l | grep rule_update
pgrep crond >/dev/null && echo crond-running || echo crond-stopped
```

`crond` 没跑时：`/etc/init.d/cron enable && /etc/init.d/cron start`。Passwall 每次重载规则也会重写这条 crontab，条目应为 `lua /usr/share/passwall/rule_update.lua log all cron`（第三个参数 `cron` 会清空第二个参数，所以这里的 `all` 不影响执行）。

## 5. 应用与验收

```sh
/etc/init.d/passwall restart
```

等 5–10 秒，确认进程与 DNS：

```sh
pgrep -f chinadns-ng && pgrep -f 'xray run'
nslookup www.baidu.com 127.0.0.1
nslookup chatgpt.com 127.0.0.1
```

- 国内域名应返回国内 IP，耗时十几毫秒；
- `chatgpt.com` / `google.com` 应返回海外 IP（走可信 DNS）。

连通性（在客户端 Mac 上执行，越贴近真实使用越好）：

```sh
curl -s -o /dev/null -w '%{http_code} %{time_total}s\n' https://www.google.com/generate_204
curl -s -o /dev/null -w '%{http_code} %{time_total}s\n' https://github.com
curl -s -o /dev/null -w '%{http_code} %{time_total}s\n' https://www.baidu.com
curl -s -o /dev/null -w '%{http_code} %{time_total}s\n' https://chatgpt.com/robots.txt
```

预期：Google 204；GitHub 200；百度 200；ChatGPT 的 robots.txt 常见 403（Cloudflare 拦爬虫），能拿到 403 说明链路是通的。

确认名单真的进了集合（集合名随版本，先 `nft list sets inet passwall` 看一眼）：

```sh
nslookup www.zhihu.com 127.0.0.1        # 记下返回的 IP
nft list set inet passwall psw_white | grep <知乎 IP>   # 直连集合应命中
nslookup chatgpt.com 127.0.0.1
nft list set inet passwall psw_black | grep <OpenAI IP> # 代理集合应命中
```

## 6. 常见问题

| 现象 | 先检查 | 处理 |
| --- | --- | --- |
| 国内网站变慢或解析失败 | `nslookup www.baidu.com 223.5.5.5` 是否正常 | 换回国调上游 DNS，或改用可用的国内 DNS |
| 某些非 443 端口站点全部超时 | `tcp_redir_ports` 是否被改成全端口；节点是否放行该端口 | 回退常用端口列表；单独验证后再加 |
| 代理域名实际走了直连 | 直连侧是否有更宽的父域（如 `apple.com`） | 删除冲突的代理条目，或收窄直连父域 |
| 规则更新“点了没反应” | 是否带 `all` 参数手动执行；`crond` 是否在跑 | 去掉第二参数重跑；启动 cron |
| 客户端 DNS 仍被污染 | 客户端是否启用 DoH/DoT 或自带 DNS | 关闭客户端加密 DNS，或接受该边界 |
| 想要全局无代理排查 | — | `/etc/init.d/passwall stop` 后复测，排除代理因素 |

改完任何一项，按第 5 节重新验收，不要只看首页能不能打开。

## 7. 回滚

只用备份覆盖配置与名单，然后重启：

```sh
tar xzf /root/passwall-<时间戳>.tgz -C /
uci commit passwall
/etc/init.d/passwall restart
```

规则库（`chnlist`/`chnroute`/`gfwlist`）不在备份内，回滚时保持当前版本即可；如需回到旧数据，只能在规则页重新更新，旧文件本身不保留。

回滚后同样按第 5 节验收，并确认主节点与 `tcp_redir_ports` 已恢复。

## 8. 客户端侧注意

- 路由器只负责「按规则分流」，不改变客户端自己的 DNS 与代理设置；客户端开 DoH/DoT 时，分流按客户端解析结果走。
- 需要 GPT 走美国节点时，优先在 Passwall 的「分流」里给对应规则组绑定节点；不想动路由器就由客户端自己选节点。
- 客户端开启自己的代理后，两套规则会叠加：先确认路由器的名单没有把客户端节点入口也代理掉。
