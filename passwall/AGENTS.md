# AGENTS.md · passwall

给 AI 的执行说明。给人看的说明在 [`README.md`](./README.md) 与 [`使用指南.md`](./使用指南.md)。

这个项目的风险是**两头**：一头是泄漏（节点、订阅、路由器备份），另一头是**照抄了不适用的参数**（例如把 fancyss 的「全端口」直接搬到受限节点上）。改之前先读「红线」。

## 执行协议

| 步 | 动作 | 命令 | 通过判据 |
| --- | --- | --- | --- |
| 1 | 改前基线 | `node --test passwall/tests/*.test.mjs` | 退出码 0 |
| 2 | 改文档 / 增量名单 | 只动 `*.md`、`*-additions.txt` | 数字、链接、结论与文件一致 |
| 3 | 复跑测试 | 同上 | 全部用例通过 |
| 4 | 查空白 | `git diff --check` | 干净 |
| 5 | 脱敏扫描 | 搜订阅 / 节点域名 / UUID / 密码 / 真实 IP | 0 命中 |
| 6 | 链接检查 | `pwsh -NoProfile -File scripts/check-links.ps1` | 锚点与相对链接都可解析 |

**硬规则**

1. **公开名单只放通用域名** —— 订阅、节点入口、账号、私用 API、路由器备份一律不进仓库；截图与配置样例先脱敏。
2. **名单只有一份底表** —— 底表是 `merlin/direct-domains.txt` 与 `merlin/proxy-domains.txt`；本目录只放「底表没有的增量」，**不要复制底表内容**。
3. **增量与底表不许重叠** —— 同名或互为父子域都算重叠；要加就先从底表删，保证只留一边。
4. **直连优先于代理** —— Passwall 先匹配直连集合。发现同一个域既直连又代理时，删代理那条，或收窄直连父域，不要靠顺序猜。
5. **数字必须对得上** —— 底表 119 / 49，增量 25 / 17，合并 144 / 66；改任何数字要同步 README、测试与文件。
6. **不把「全端口」写成推荐** —— `tcp_redir_ports=1:65535` 只在节点放行全部端口时成立；本项目的实测节点只放行常用端口，照抄会让高端口站点变成黑洞。
7. **结论要有依据** —— 写「已验证」必须说明设备、版本、客户端与检查项；只做静态检查就写「静态检查通过」，不要写成设备已加载。

## 文件 → 用途

| 文件 | 用途 | 改动注意 |
| --- | --- | --- |
| `README.md` | 方案、参数基线、实测记录与边界 | 参数表用 UCI 字段名；实测要带日期与版本 |
| `使用指南.md` | 备份、合并、应用、验收、排错、回滚 | 命令必须能在 `ash` 下跑，不能依赖 bash 进程替换 |
| `direct-additions.txt` | 直连增量 25 条 | 一行一个、小写、无注释、无空行、不与底表重叠 |
| `proxy-additions.txt` | 代理增量 17 条 | 同上；`apple-relay.apple.com` 不在此列 |
| `tests/passwall.test.mjs` | 离线检查 | 名单格式、数量、重叠、脱敏、文档一致性 |

## 验证判据（用例守什么）

| 用例 | 守的东西 |
| --- | --- |
| 文档齐备 | 三份文档存在，README 含分流、参数、实测、边界四节 |
| 名单格式 | 小写、无注释、无空行、去重、无通配符扩大 |
| 数量一致 | 底表 119/49、增量 25/17、合计 144/66 与 README 一致 |
| 无重叠 | 增量之间、增量与底表之间都不存在同名或父子域 |
| 脱敏 | 文档与名单不含 UUID、协议链接、订阅地址、密码、节点域名、公网 IP（公开 DNS 除外） |
| 命令正确 | 使用指南给的是 `rule_update.lua log`；带 `all` 的写法只能出现在「无效」或 `cron` 语境 |
| 端口结论 | README 不把 `1:65535` 作为推荐；出现处必须带「不要 / 限制 / 超时 / 回退」 |
| 导航 | 根 `README.md` 的「配置与工具」与网络配置说明能链到本目录 |

## 常见失败怎么定位

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 「no overlap」红 | 增量里混进了底表已有的域名 | 从增量删除，底表是唯一来源 |
| 「counts」红 | 改了名单没同步 README / 测试 | 三处一起改，或恢复名单 |
| 「secret scan」红 | 文档里写了真实节点、UUID、订阅或公网 IP | 换成占位符；公开 DNS（223.5.5.5 / 1.1.1.1）可用 |
| 「rule update command」红 | 又把 `log all` 写成了手动更新命令 | 改为不带第二参数；`cron` 那行原样保留 |
| 「port advice」红 | 把全端口写成了推荐 | 改成条件结论，并保留节点端口实测 |
| 链接检查红 | 新增相对链接目标不存在，或锚点与标题不一致 | 先改路径 / 标题，再复跑检查器 |

## 红线

- **不提交**：订阅地址、节点入口与真实 IP、UUID / 密码 / 私钥、完整路由器备份、浏览器书签。
- **不把个人环境当通用结论**：端口限制、节点延迟、DNS 选择都随线路与服务商变化，写清楚适用条件。
- **不为了通过测试改结论**：测试守的是已经验证过的事实；事实变了先改文档与实测，再改测试。
